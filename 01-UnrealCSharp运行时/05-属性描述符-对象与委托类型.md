## 1. 模块职责与架构速览

这一组描述符是 **UE 反射属性 ↔ C# 托管句柄（`IManagedHandle`）之间的搬运层**。核心契约由三个基类定下：

1. `FPropertyDescriptor`（`FPropertyDescriptor.h:20`）：纯虚访问器集合 `Get/Set/CopyValue/Identical/...`，其中 `Get(void*, void**)` 有 4 个带 tag 参数的重载（`FMember`/`FParameter`/`FReturn`/无 tag），tag 用来区分「读字段/传参/取返回值/取临时值」四种不同所有权语义。
2. `TPropertyDescriptor<T, IsPrimitive>`（`TPropertyDescriptor.inl:7`）：持有具体属性指针 `T* Property` 与 C# 侧类型描述 `FClassReflection* Class`，构造函数即 `Class(FTypeBridge::GetClass(InProperty))`（`TPropertyDescriptor.inl:12`）——**`Class` 可以为 `nullptr`**。
3. `TCompoundPropertyDescriptor<T>`（`TCompoundPropertyDescriptor.inl:7`，`IsPrimitive=false`）：把「复合类型」统一成 **8 字节托管句柄**：`GetBufferSize() == sizeof(void*)`（:50-53），`CopyValue()` 走 `Malloc(ElementSize)+InitializeValue+CopySingleValue`（:33-48），并把无 tag 的 `Get(Src,Dest)` 转发到 `Get<FMember>`（:15-18）。
   - 注意 `TCompoundPropertyDescriptor::Get(void*,void**,FMember)` / `(FReturn)` 的基类实现是 **空函数体**（:20-26）。任何不重写它们的子类，读值时会**不写入 `*Dest`**（见 Finding F-PROP2-004）。

数据流（读方向）：`C++ 对象 + 属性偏移` → `Property->GetObjectPropertyValue(Src)`（取原始值）→ `FCSharpEnvironment::Bind/AddMultiReference/AddDelegateReference`（在对象/多重/委托注册表登记并生成托管句柄）→ `*Dest = 句柄`。
数据流（写方向）：`*Src = 托管句柄` → `FCSharpEnvironment::GetObject/GetMulti/GetDelegate`（句柄→C++ 值）→ `Property->InitializeValue(Dest)` → `Property->SetObjectPropertyValue/...`。

工厂 `FPropertyDescriptor::Factory`（`FPropertyDescriptor.cpp:47-134`）按 `CastField<T>` 顺序分派；八个对象描述符全部在此注册（:69-79 特殊处理 `FClassProperty` + `CPF_UObjectWrapper` → `FSubclassOfPropertyDescriptor`）。

**问题**
1. **写操作伪装成读操作**：C# 只是读一下 `Actor.MySparseDelegate`，C++ 侧的 `FSparseDelegate::bIsBound` 就被永久置为 `true`（引擎 `PropertyMulticastDelegate.cpp:547`）。此后 UE 侧 `MySparseDelegate.IsBound()`（引擎 `SparseDelegate.h:131-134`）对**实际没有任何绑定的委托**返回 `true` → 蓝图/C++ 里 `if (MySparseDelegate.IsBound()) { ... }` 分支被错误激活；依赖 `bIsBound` 做网络/复制优化的逻辑也会走错分支。

3. **状态不一致**：假条目的 `FScriptDelegate::IsBound()` 为 `false`（引擎 `ScriptDelegates.h:159-170`，因为 `Object` 为空），因此 `ProcessMulticastDelegate` 会跳过它（`:931`）—— **不会崩溃**。~~假条目始终存在（`InvocationList.Num() == 1`）~~ **【更正】**：广播结束时 `ProcessMulticastDelegate` 会无条件调用 `CompactInvocationList()`（`ScriptDelegates.h:945`），后者用 `RemoveAllSwap(IsCompactable())`（`:1074-1079`）把失效条目移除，所以假条目**在第一次广播后就被清掉**；但 `FSparseDelegate::bIsBound` 这个 1 字节标志**不会被复位**，于是 `FMulticastScriptDelegate::IsBound()`（只看 `Num()>0`）与 `FSparseDelegate::IsBound()`（只看 `bIsBound`）出现长期不一致。插件的 C# `FMulticastDelegate.IsBound`（`FRegisterMulticastDelegate.cpp:30-39` → `FMulticastDelegateHelper::IsBound` → `MulticastDelegateHandler->IsBound` → `MulticastScriptDelegate->IsBound()`，`MulticastDelegateHandler.cpp:65-68`）因此对空委托返回 `true`（C# 侧行为错误）。
4. **替换语义导致的既有绑定丢失**：`:17` 的 `SetMulticastDelegate` 是**整体替换**（`*MulticastDelegate = MoveTemp(Delegate)`）。任何「`bIsBound == false` 但存储里仍有条目」的状态（例如插件自己在 `Set` 里先 `InitializeValue` 把 `bIsBound` 清零，见 F-PROP2-013）都会让这次替换把该委托名下**原有的全部绑定**（C++ `AddDynamic`、蓝图绑定）一次性丢弃。

**建议**
1. 不要在描述符层伪造委托；改为在 `FMulticastDelegatePropertyDescriptor` 里允许 `GetMulticastDelegate` 返回 `nullptr` 时走「空委托」语义：
   - C# 侧 `IsBound → false`、`Contains → false`、`Broadcast → 不做事`、`Add/AddUnique` → 用 `Property->AddDelegate(...)` 直接往属性上添加（引擎 `UnrealType.h:6116` 提供了 `AddDelegate(ScriptDelegate, Parent, PropertyValue)`，sparse/inline 都实现了）；
   - `FMulticastDelegateHelper` 增加「属性为空」的合法状态，而不是逼着它拿到一个非空指针。
2. 若必须保留一个可写的托管包装，也应通过 `Property->GetMulticastScriptDelegate(...)`/`AddDelegate` 路径，而不是 `SetMulticastDelegate` + 假条目。
3. 最小改动（保留现有架构）的补丁：把 dummy 换成**空委托**并避免置位 `bIsBound`——但 `SetMulticastDelegate` 对未绑定委托会走 `else if (SparseDelegate.bIsBound) { Clear... }` 分支，因此空委托无法用于此目的，这进一步说明**这条路走不通**，必须改架构（即建议 1）。

**问题**

**建议**
1. `Set` 应表达赋值语义：`Property->DestroyValue(Dest)`（或 `ClearDelegate(nullptr, Dest)`，引擎 `UnrealType.h:6118`）+ 再写入；避免 `InitializeValue` 直接清零（见 F-PROP2-007）。
2. 写回前先解除旧绑定：单播用 `DestScriptDelegate->Unbind()`（或 `Property->RemoveDelegate`），多播用 `Property->ClearDelegate`/`RemoveDelegate`；对 helper 补充 `FDelegateHelper::UnBind()`（已存在，`:57-63`）的调用，并让 `UDelegateHandler::Deinitialize` 无论 `bNeedFree` 都执行 `Unbind()`。
3. 生命周期：`UDelegateHandler`/`UMulticastDelegateHandler` 目前依赖 `AddToRoot`（`FDelegateHelper.cpp:24`、`FMulticastDelegateHelper.cpp:25`）保命——改为只由 C# 侧 GCHandle 生命周期驱动（`Register/UnRegister` 已成形），去掉 `AddToRoot` 可让「C# 对象已死」时 UE 侧绑定自然失效（`FScriptDelegate::IsBound()` 返回 false 并被 `CompactInvocationList` 清除）。

同一个属性读数，走哪个重载决定了返回的是「强包装（带 owner 生命周期）」还是「弱包装（无 owner）」——差异只在 `FPropertyDescriptor::Get` 的重载选择上，且没有任何注释、命名也不体现（`NewRef`/`NewWeakRef` 的「Ref」在这里指的是注册表项而非 C++ 引用）。调用方一旦改用另一个重载，行为（缓存、生命周期、GC 时机）就悄悄改变。这与 §5 对照表中 Multi 系列用模板 bool 显式表达所有权的做法不一致。

**建议**
统一为显式的所有权参数（与 `AddMultiReference<T, IsNeedFree, IsMember>` 对齐），或在头文件写清 `// NewRef: 强引用 + 按地址缓存；NewWeakRef: 每次新建，生命周期由 C# 侧 UnRegister 决定`。

**验证方式**
grep `NewWeakRef|NewRef`；代码审查调用点。

### 1.2 `Source/Compiler/Private/FCSharpCompiler.cpp`（`+23/−2`）

```cpp
#include "Misc/CoreDelegates.h"           // 新增（文件头）

FCSharpCompiler::FCSharpCompiler() :
	Runnable(nullptr),
	Thread(nullptr)
{
	Runnable = new FCSharpCompilerRunnable();

	Thread = FRunnableThread::Create(Runnable, TEXT("CSharpCompiler"));

	OnPreExitHandle = FCoreDelegates::OnPreExit.AddRaw(this, &FCSharpCompiler::OnPreExit);
}

FCSharpCompiler::~FCSharpCompiler()
{
	OnPreExit();                          // 摘委托 + 停线程都收敛在这里

	if (Thread != nullptr) { /* 原逻辑：delete Thread / Runnable */ }
}

// … Get() / AsyncCompile() / EnqueueTask() / SyncCompile() / Compile() /
//    ImmediatelyCompile() / IsCompiling() / GetCompileProgress() 均未改动 …

// 定义放在文件末尾 = 与头文件里"最后一个 private 方法"的位置一致
void FCSharpCompiler::OnPreExit()
{
	if (OnPreExitHandle.IsValid())
	{
		FCoreDelegates::OnPreExit.Remove(OnPreExitHandle);

		if (Runnable != nullptr)
		{
			Runnable->Stop();
		}

		if (Thread != nullptr)
		{
			Thread->Kill(true);
		}
	}
}
```
- `OnPreExit()` 同时被委托与析构调用 ⇒ **幂等**（`OnPreExitHandle` 已失效即短路），保证 `Kill(true)` 只等一次。
- 析构里原来的"`Thread != nullptr` 才删 `Runnable`"结构未改动，避免扩大行为面。

## 2. 为什么这个改法是对的（沿用 256 的事实，回 HEAD 复核未变）

| 事实 | 现状 |
|---|---|
| 编译线程由**函数内静态** `FCSharpCompiler` 持有 | `FCSharpCompiler::Get()` 仍是 `static FCSharpCompiler Compiler;` |
| 编辑器默认**不卸载模块** ⇒ 静态析构**不执行** ⇒ 原 `Thread->Kill(true)` 在编辑器里**从来不会跑** | 256 §1 修正 2；本轮未改这一事实 |
| `FEngineListener::OnPreExit()` 只 `SetActive(false)`（域），**完全不碰编译线程** | 未变 |
| `FCoreDelegates::OnPreExit` 在本仓已有跨版本用法 | `FEngineListener.cpp:31`（5.0 起可用） |

⇒ 方案 B 把"停线程"从**永不执行的静态析构**挪到**一定会执行的 `OnPreExit`**，且不新增公开面（`OnPreExit` 为 private、句柄为 private 成员）。

### 3.1 探针为什么没拿到（三次尝试，如实登记）

按 256 §4 的要求，在 `OnPreExit` / `~FCSharpCompiler` 各埋一条 `UE_LOG`，试图证明"退出期线程被提前停"，但三条路径都不成立：

| 尝试 | 命令 | 观察 | 结论 |
|---|---|---|---|
| **A. 无头编辑器** | `UnrealEditor-Cmd.exe <proj> -unattended -nopause -nullrhi -ExecCmds="Quit"` | 日志有 `[0]Cmd: Quit`（**命令确实执行了**），但进程 12 分钟不退、无 `LogExit`、无 `B223-*` 输出 | 无头编辑器在 `-unattended` 下不真正退出（引擎侧行为，与本改动无关）⇒ 走不到 `OnPreExit` |
| **B. `-game` 会话** | `... -game -nullrhi -nosound -AutoQuit` | 干净退出（exit 0），**无 `B223-*`** | `FCSharpCompiler` 只在**编辑器模块**里被 `Get()`（`UnrealCSharpEditor.cpp`），`-game` 下不构造 ⇒ 委托未注册 |
| **C. `-game` ＋ 控制台命令** | `... -game ... -ExecCmds="UnrealCSharp.Editor.Compile"` | 仍无 `B223-*`（命令未被识别，编辑器模块未加载） | 同上 |

- 剩下的唯一路径是**交互式编辑器**（构造编译器后关闭），本环境无法自动化驱动 GUI 关闭。
- ⇒ 本轮**只能给到"编译 + 回归 + 静态一致性"证据**，"线程是否真的被提前停"**无运行期读数**。探针代码已**全部删除**（`B223-` 命中 0）。

## 4. 风险与边界（施工后仍存在的）

1. **`Kill(true)` 会阻塞退出**：若退出时线程正卡在 `dotnet build`（`SyncProcess`），`OnPreExit` 会等它跑完。这是 256 已接受的取舍（"退出期不产生半写产物"优先于"退出更快"），但**没有实测**退出耗时变化。
2. **只在编译器已构造时注册**：若整个会话从未 `Get()` 过（例如纯 `-game`），委托不注册、也无线程可停 —— 行为与改前一致（改前也是没有线程）。
3. **析构路径不变**：静态析构真发生时只调一次 `OnPreExit()`（内部先 `Remove` 再 Stop/Kill），不会二次 `Kill`。
4. **未覆盖**：`FCSharpCompilerRunnable` 内部若在 `Stop()` 后仍有已入队的任务，行为沿用既有 `bIsStopped` 语义（本轮未改）。

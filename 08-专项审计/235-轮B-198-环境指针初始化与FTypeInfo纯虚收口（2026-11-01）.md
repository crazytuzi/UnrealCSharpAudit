## 2. 代码事实

### 2.1 `F-CONC-015`（裸指针未初始化）

**改前**：

```cpp
// FCSharpEnvironment.h:322-325
private:
	static FCSharpEnvironment Environment;

	FDomain* Domain;                    // ← 无初值
```

```cpp
// FCSharpEnvironment.h:349-376（同形 13 个 + 1 个条件编译）
FDynamicRegistry* DynamicRegistry;  class FCSharpBind* CSharpBind;  FClassRegistry* ClassRegistry;
FReferenceRegistry* ReferenceRegistry;  FObjectRegistry* ObjectRegistry;  FStructRegistry* StructRegistry;
class FContainerRegistry* ContainerRegistry;  class FDelegateRegistry* DelegateRegistry;
FMultiRegistry* MultiRegistry;  FStringRegistry* StringRegistry;  FFieldPathRegistry* FieldPathRegistry;
class FBindingRegistry* BindingRegistry;
#if UE_F_OPTIONAL_PROPERTY
class FOptionalRegistry* OptionalRegistry;
#endif
```

**为什么是缺陷**：

```cpp
// FCSharpEnvironment.cpp:44-51 —— 构造函数只挂委托，不碰这些指针
FCSharpEnvironment::FCSharpEnvironment()
{
	OnUnrealCSharpModuleActiveDelegateHandle = ...AddRaw(this, &FCSharpEnvironment::OnUnrealCSharpModuleActive);
	OnUnrealCSharpModuleInActiveDelegateHandle = ...AddRaw(this, &FCSharpEnvironment::OnUnrealCSharpModuleInActive);
}
```

```cpp
// FCSharpEnvironment.cpp:53-55 —— 析构无条件走 Deinitialize
FCSharpEnvironment::~FCSharpEnvironment()
{
	Deinitialize();
```

```cpp
// FCSharpEnvironment.cpp:166-310 —— Deinitialize 对 14 个指针逐个判空后 delete
if (OptionalRegistry != nullptr) { delete OptionalRegistry; OptionalRegistry = nullptr; }
...
if (Domain != nullptr) { delete Domain; Domain = nullptr; }
```

⇒ `Environment` 是**静态对象**（`:42`），`Initialize()` 只经 `OnUnrealCSharpModuleActive`（`:366-369`）触发，而该委托由 `UnrealCSharp` 模块在收到 **Core 模块 active** 时广播（`UnrealCSharp.cpp:36-48`）。若进程里 `Environment` 已构造但 `Initialize()` 从未执行（Core 未激活／模块启动期早退），析构会拿 **14 个未初始化指针**逐个判空，垃圾值非空即 `delete` 垃圾。

**改后**：14 个成员全部 `Type* Name{};` ⇒ 未初始化路径上判空为假，`delete` 不执行。

**可达性说明**：该路径**未实测**（本轮套件走的是正常 init→shutdown 路径，改动前后计数无差异）；本条的判定依据是"**补初值 = 零行为变化的 C++ 卫生修复**"，与 `F-DEF-001`（需要改接口/语义、故"不施工"）不同。残余的"重复 `Initialize()` 泄漏"仍在 `F-ENV-009`（不可达），不在本条内。

### 2.2 `F-DEF-005`（只有声明，没有定义）

**改前**：

```cpp
// FTypeInfo.h:3-18
struct FTypeInfo
{
	virtual ~FTypeInfo() = default;

	virtual FString GetName() const = 0;
	virtual const TArray<FString>& GetNameSpace() const = 0;

	virtual int32 GetBufferSize() const;      // ← 只声明；全树无定义（Binding/TypeInfo/ 下无 .cpp）

	virtual bool IsRef() const = 0;
	virtual bool IsStatic() const = 0;
	virtual bool IsPrimitive() const = 0;
};
```

派生面：

- 主模板 `TTypeInfo<T, bIsStatic>`（`TTypeInfo.inl:9-62`）**有** `GetBufferSize` override（`:29-39`）；
- `TTypeInfo<void>` 特化（`TTypeInfo.inl:64-98`）**没有** override，但 `Get()` 直接 `return nullptr`（`:94-97`），全库**零构造点** ⇒ 当前只在"将来有人实例化"时才会变成未定义符号（链接期才暴露）。

**改后**：`virtual int32 GetBufferSize() const = 0;` ⇒

1. 未定义符号从根上消失（不再依赖"没人用"这一巧合）；
2. `TTypeInfo<void>` 变成抽象类 —— 将来若有人给它加 `static TTypeInfo Instance`（照主模板的写法），**编译期**就会报"cannot instantiate abstract class"，而不是链接期才发现。

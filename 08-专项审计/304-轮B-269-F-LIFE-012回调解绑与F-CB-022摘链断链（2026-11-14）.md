## 1. 改动清单

### 1.1 `F-LIFE-012`：`ClassCollector.cpp:150-154`（P2）

```cpp
void FClassCollector::PopulateClassHierarchy()
{
	FCoreDelegates::OnEndFrame.Remove(OnEndFrameDelegateHandle);

	OnEndFrameDelegateHandle.Reset();
```

**改前**只有 `Reset()`。这不是"清标志"，而是**丢掉唯一解绑凭据**：

1. `Remove(FDelegateHandle Handle)` **按值**收句柄、内部 `RemoveDelegateInstance(Handle)`，**不回写调用方**（5.6 `Delegates/DelegateSignatureImpl.inl:1007-1016`）；只有 `FDelegateHandle::Reset()` 才把 `ID` 清 0。
2. 所以旧顺序 `Reset()` 之后：句柄失效 ⇒ ① `~FClassCollector` 的 `IsValid()` 守卫（`:92`）**跳过 Remove** ⇒ `OnEndFrame` 上的绑定**永不解绑**；② 下一次 `RequestPopulateClassHierarchy` 的守卫（`:144-147`）看到"无效"⇒ 再 `AddStatic` **一条新的**（`AddStatic` 不去重）⇒ 每请求叠一条，随后**每帧 N 次全类遍历**。
3. 新顺序：先 `Remove`（真正解绑）再 `Reset`（清 ID）⇒ 每次回调只解绑自己那一条，下一次请求最多再注册一条 ⇒ **恒 ≤ 1 条**。
4. **广播期解绑是安全的**：`RemoveDelegateInstance` 只 `Unbind()` ＋ `CompactInvocationList()`，而压缩在 `InvocationListLockCount > 0`（正在广播）时**直接跳过、延迟到广播结束**（5.6 `MulticastDelegateBase.h:299-317` / `:138`）⇒ 不需要"下一个 tick 再解绑"的两段式。
5. **直接调用路径不受影响**：`PopulateClassHierarchy()` 另有直接调用点（`ClassCollector.cpp:33`），此时句柄通常无效 ⇒ `Remove` 内部先判 `IsValid()`（`DelegateSignatureImpl.inl:1009-1012`）⇒ **no-op**，不会误删别人的绑定。

### 1.2 `F-CB-022`：`FCSharpBind.cpp:181`（P3）

```cpp
					if (PrevField != nullptr)
					{
						PrevField->Next = Field->Next;
					}
					else
					{
						Class->Children = Field->Next;
					}

					Field->Next = nullptr;

					break;
```

- 摘链已把"前驱 → 后继"接好，但**被摘节点自己仍指向原后继**。被摘函数若因 `IsRooted()` 分支存活（`FRegisterClass.cpp:22-31` 只解根、不标垃圾）或在该帧内仍被别处持有，任何"从该节点出发按 `Next` 遍历"的代码都会把**已不属于该类的后继链**当成它的链（重复遍历/越界语义）。
- 补一行断链后：被摘节点成为**叶子**（`Next == nullptr`），遍历面收敛。
- 不改"是否摘除"的判定（仍是遍历命中才摘），也不引入新分支；`UField::Next` 在 5.0 是 `UField*`、5.6/5.8 是 `TObjectPtr<UField>`，两者都可赋 `nullptr`。

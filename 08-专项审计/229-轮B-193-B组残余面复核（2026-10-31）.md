## 2. 逐条证据

### 2.1 `F-CONC-021`（S=2.71）

- 原判 4 个忙等点里，B-181/183/184 已把 `OnCompile`／控制台／工具栏／`OnPostEngineInit`／`Generator` 的编译入口外移到编译器线程；`WaitForCompile` 保留心跳（`FEditorListener.cpp:750-770`，`HeartBeat()` ＋ 120 Hz 轮询）。
- **剩余唯一实质点**：`FUnrealCSharpFunctionLibrary::SyncProcess` 的等待循环（`:1761-1793`）没有 `FThreadHeartBeat::Get().HeartBeat()`；当它仍在游戏线程被调用（`SyncCompile`／命令行走同步分支）且 build 超过 hang 阈值时，仍可能触发引擎 "hang detected"。
- 施工形态：循环体内补一行心跳（引擎既有 API，无新出口、无新日志）。

### 2.2 `F-PERF-018`（S=2.44）

- 原判"~2000 Hz 自旋"已不成立：`PollsPerSecond = 120`（`FCSharpCompiler.h:33`），`WaitForCompile` 的 `SleepNoStats(PollIntervalSeconds)` = 8.3 ms（`FEditorListener.cpp:769`）。
- 每轮仍 tick `FTSTicker`／`FThreadManager`／`ProcessThreadUntilIdle`，但 120 次/秒属"保活 + 泵图"的合理代价；异步化属交互语义变更（B-125 已判"部分修"），无量化缺口 ⇒ **结案**。

### 2.3 `F-CMP-001`（S=1.82）

- `Stop()`（`FCSharpCompilerRunnable.cpp:110-117`）置 `bIsStopped` ＋ `Trigger`；
- `Compile` 两处 `SyncProcess(..., return bIsStopped || GExitPurge)`（`:367`、`:597`）⇒ 循环内 `InIsStopped` 命中后 `bCancelled`；
- `SyncProcess` 在 `bCancelled` 时 **`TerminateProc(ProcessHandle, true)`**（`:1809`）⇒ 子进程被终止；`Kill(true)` 的等待因此有界（≤ 一个轮询周期 ＋ 终止耗时）。
- 原缺陷"`Stop()` 不终止 `dotnet` 子进程"**不再成立** ⇒ 结案。

### 2.4 `F-CMP-011`（S=2.38）

- `Event` 空判已覆盖全部入队路径（上表行号）——原"`Exit()` 后仍入队 ⇒ 空指针"半边已闭合；
- 静态析构序半边：`FCSharpCompiler::Get()` 仍为函数局部静态（`FCSharpCompiler.cpp:29-34`），`~FCSharpCompiler` 仍 `Kill(true)` ＋ `delete Runnable`，而 `~FCSharpCompilerRunnable` 会 `Remove` 另一模块的委托句柄；**是否真的落在"Core 模块静态已销毁之后"仍未验证**（审计原文即"无法验证"）。
- 处置：结案（残余不施工）。触发条件 = 出现卸载期崩溃/`ensure` 实证，或引入模块级生命周期重构时一并处理。

### 2.5 `F-PERF-013`（S=1.82 → P3）

- 键仍为 `TMap<TTuple<FString,int32>, FMethodReflection*>`（`FClassReflection.h:178`），`GetMethod` 每次构造临时键；
- B-13 实测：`GetMethod` **2 000 次 / 712.6 µs = 0.36 µs/次**，随机型 `GetParentMethod` 链长恒 1；会话级 < 1 ms ⇒ 不施工。改键类型是公开 API 变更，代价不支持收益（B-13 已论证）⇒ **P2 → P3**。

### 2.6 `F-FN-008`（S=2.46）

- `UFunction : UStruct` ⇒ `NotifyUObjectDeleted` 会走 `RemoveClassDescriptor(UFunction)`；但 `AddClassDescriptor` 唯一调用点是 `FCSharpBind.cpp:122`（入参只来自 `UClass`/`UScriptStruct`），`UFunction` 永不进 `ClassDescriptorMap` ⇒ `RemoveClassDescriptor` 对它在 `FClassRegistry.cpp:123` 即返回，四个 `*Map` 条目不被自身死亡清理。
- 触发需"`UFunction` 先死 ＋ 地址复用/同哈希再取用"两条件；修法要改注册键语义（弱引用/删除钩子），属协议级改动 ⇒ **不施工（潜伏）**。触发条件 = 拿到上述两条件的实证，或类描述符级联清理被改动。

### 2.7 `F-INT2-004 (11)`（S=1.26）

- 当前 `FRegisterPolyglotTextData.cpp`：`SetNativeCulture` 已绑到 `&FPolyglotTextData::SetNativeCulture`（`:20-21`），C# 产物 `PolyglotTextData.cs:61 public void SetNativeCulture(FString InNativeCulture)` **正确**；
- 残余：`:40-42` 的 `IsMinimalPatch` setter 重载 `ParamNames` 仍是 `{"InCulture","OutLocalizedString"}`（从 `GetLocalizedString` 复制残留），产物 `PolyglotTextData.cs:247 public void IsMinimalPatch(bool InCulture)` **形参名错**。
- 引擎侧 `PolyglotTextData.h:126` 的 setter 本身就叫 `IsMinimalPatch(const bool)` ⇒ **绑定名/目标无错**，只改形参名即可：
  `TArray<FString>{"InIsMinimalPatch"}`。
- 影响：C# 形参名（非签名类型/数量）；产物仅该文件一行变化，套件不受影响。

## 2. 面 ② 栈实参地址入表：本语料未复现（防御性登记）

### 2.1 代码路径（仍然存在）

```
TArgument<T,false>::Set()                          TArgument.inl:69-73
  └─ TPropertyValue<Type,Type>::Get<std::is_reference_v<Type>>(&Value)
       ├─ is_reference_v == true  → AddBindingReference<…, false>(&Value)   ← 视图（栈地址）  TPropertyValue.inl:219 / :274
       └─ is_reference_v == false → AddBindingReference<…, true>(new copy)  ← 堆拷贝（安全）
```

`Set()` 由 `TOut` 在**引用参数**回写时调用（`TOut.inl:25-34`，`IsRef()` 为真才调），`Value` 是 `TFunctionHelper::Call` 栈上 tuple 的成员 ⇒ 若走视图分支，注册表键就是**栈地址**。

### 2.2 实测

| 指标 | 值 | 判读 |
|---|---|---|
| `FBindingRegistry::AddReference` 调用 | **46 次** | 绑定表的全部流量（含 EnhancedInput 的 A1/A2 用例） |
| 其中地址落在**当前线程栈 ±1 MB** | **0 次** | 没有栈地址入表 |
| `TArgument::Set()` 调用 | **16 次** | ref/out 复合参数的回写路径**确实被执行** |
| 16 次 `Set()` 的实例化 | 全部为**值类型**（`std::is_reference_v<Type>` 为假）⇒ **copy 分支** | 视图分支**从未被实例化** |

⇒ **"栈实参地址进全局绑定表"在本库现有语料（1 968 条断言、含 `OutArrayValueFunction`/`OutStringValueFunction`/`OutMapValueFunction` 等 ref/out 用例）中未复现**。视图分支是**防御性代码**：只有绑定宏/生成器产生"引用类型实例化"（`is_reference_v<Type>` 为真）时才会启用。

### 2.3 若将来复现：候选修法（1 行，未施工）

| 方案 | 改动 | 代价 / 风险 |
|---|---|---|
| A. 强制 copy | `TArgument.inl:71` 的 `Get<TTypeInfo<Type>::IsReference()>` → `Get<false>` | 每个 ref/out 复合参数一次深拷贝；语义从"视图"变"快照"（对 out/ref 回写方向等价，但 C# 侧写入不再回传——回写本就发生在调用结束之后） |
| B. 作用域释放 | 给 `TArgument` 记录 view handle，在 `TFunctionHelper::Call` 的 `TOut` 之后 `RemoveBindingReference` | 释放点太早：C# 代理在 native 返回**之后**才读取 OUT_BUFFER 里的对象指针 ⇒ 需协议层配合 |
| C. 维持 | — | 以本页读数为证据，等复现再动 |

**本轮不做 A**：没有复现 ⇒ 改的是"防御性路径"，无判据；且 A 是全路径语义变更（copy vs view），不宜在不能证伪的情况下落地。

**⇒ 处置：⚫ 维持登记（防御性）**。触发条件：① 生成器/绑定宏出现引用类型实例化；② 探针下出现 `bindings_stack > 0`；③ 某次 ref/out 复合参数调用在 C# 侧观察到"out 值事后被改写/串对象"。

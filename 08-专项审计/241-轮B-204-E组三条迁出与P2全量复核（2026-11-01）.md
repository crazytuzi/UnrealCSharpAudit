## 4. 新发现一：`E1(b)` 已解锁 `F-ABI-003` ≡ `F-DOM-019`（一处 3 行修复＝两条收口）

**事实链**：

1. **两条编号指向同一处**：`F-ABI-003`（[`08-…/04`](../08-专项审计/04-跨语言ABI与平台兼容审计.md)）与 `F-DOM-019`（[`02-…/04`](../02-UnrealCSharpCore核心/04-脚本域抽象与三大后端.md)）都是「`AssemblyLoader` 的 `[UnmanagedCallersOnly]` 入口没有 try/catch，托管异常跨越原生边界」。`F-DOM-019` 的 `01` 行内还记着 B-125 的处置：**暂缓（Q2 排除新 try/catch）**。
2. **该函数本身就是边界入口**：

   ```csharp
   // Plugins/UnrealCSharp/Script/Interop/AssemblyLoader/AssemblyLoader.cs:13-28
   [UnmanagedCallersOnly]
   public static unsafe nint LoadFromStream(byte* InData, int InLength, char* InInPublishDirectory)
   {
       if (InData != null && InLength > 0) { … return HandleData.Alloc(Context.LoadFromStream(Stream)); }

       return 0;
   }
   ```

   失败值**既有且唯一**（`:27` 的 `return 0`）⇒ 满足 E1 的"返回值必须落在该函数既有失败取值"。
3. **封锁已解除**：B-125 的暂缓理由是 **Q2「不新增 try/catch」**；但 **2026-10-25 的 G7 裁定白名单已开放 `E1 边界屏障`**（`_CONVENTIONS` §8.5，来源 [`08-…/118`](../08-专项审计/118-轮B-80-G7口径裁定页（E1边界屏障·E2只读访问器·E3哨兵）（2026-10-25）.md)）：**`[UnmanagedCallersOnly]` 函数体内的单层 `try { 原函数体 } catch (Exception) { 既有失败值 }` 无需再裁定**。后来的 `F-LEAK-014`（B-199/B-202）就是按 E1 落地并获批的（B-202 还额外批了 E4）。

**结论**：这不是"可转出"，而是**从「暂缓/需设计」变成「可直接施工」**——修法 = 在 `:16-27` 的函数体外包一层 `try`，`catch (Exception) { return 0; }`；机械判据 = `catch` 只出现在边界函数内、块内无日志/断言/throw/新 API（E1 三条硬约束全满足）。**一处修复同时收口 `F-ABI-003` 与 `F-DOM-019`** ⇒ 若施工，P2 63 → **61**。

> ⚠️ 边界：本轮**未施工**（需排期）；也未验证 `UnrealAssemblyLoadContext.LoadFromStream`（`:32-42`）内部是否还有其他异常出口 —— 那是 E1 的 `try` 覆盖范围问题，施工轮必须先确认"原函数体"包含它。

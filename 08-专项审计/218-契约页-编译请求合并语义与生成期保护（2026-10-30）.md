# 契约页：编译请求合并语义与生成期保护（2026-10-30）

> **来源**：T4-4 `F-ARCH-009` 设计页 [`08-…/208`](208-轮B-175-T4-4-F-ARCH-009设计裁定-编译请求合并与线程退出（2026-10-29）.md) §5.3 —— "G3 合并（后到者覆盖）是既有设计，不新增 API/日志；**在维护文档中写明**"。本页即该落点。
> **性质**：**规范页（0 代码）**。不登记新缺陷、不新增编号。
> **一句话**：`AsyncCompile` 是**布尔合并**（多次请求压成一次，后到者只补文件变更）；生成期（`bIsGenerating=true`）**不消费队列**，请求会保留到 `OnEndGenerator` 后补跑。

---

## 1. 请求类型与语义（HEAD `376d8cfd`）

| 入口 | 行为 | 线程 |
|---|---|---|
| `FCSharpCompiler::AsyncCompile()` | `bIsPending = true`（**布尔，合并**）＋ `Event->Trigger()` | 任意 |
| `FCSharpCompiler::AsyncCompile(FileChanges)` | 同上 ＋ `FileChanges.Append(...)`（**累计，不丢**） | 任意 |
| `FCSharpCompiler::Compile(Function)` | `AcquireCompile()` → `CompileInternal(...)`：**在调用线程同步跑完整编译** | 调用线程 |
| `FCSharpCompiler::ImmediatelyCompile(force)` | `ImmediatelyDoWork`：调用线程同步编译（含 interop 与生成后重载） | 调用线程 |
| `FCSharpCompiler::EnqueueTask(TFunction)` | 入 `TQueue`（B-181 起）＋ `Trigger()`；**不参与合并** | 任意（执行在编译器线程） |
| `FCSharpCompilerRunnable::Compile(...)` | 同上，`AcquireCompile` 闸门内的同步编译 | 调用线程 |

**合并的含义**：`bIsPending` 没有计数、没有队列。N 次 `AsyncCompile()` 只对应**一次** `DoWork()`；最后一次请求"赢"，但 `FileChanges` 会累计 ⇒ 文件变更不会丢。

## 2. 文件变更的消费点

```cpp
// FCSharpCompilerRunnable.cpp:634-642（B-178 起）
TArray<FFileChangeData> FileChangesSnapshot;

{
	FScopeLock ScopeLock(&CriticalSection);

	FileChangesSnapshot = MoveTemp(FileChanges);
}

if (Compile()) { /* Reload(...) */ }
```

- **编译开始前**在锁内快照并清空 ⇒ **成功/失败都消费**（旧行为是"仅成功才消费"，失败时残留会被 `OnBeginGenerator` 清掉）。
- `Reload` 通过 `FFunctionGraphTask::CreateAndDispatchWhenReady(..., ENamedThreads::GameThread)` 派发到 GT（`:681-685`）；**非 GT 调用方会等待它完成**（`:687-693` 自旋）⇒ 编译线程调用 `ImmediatelyCompile` 时，`FDynamicGenerator` 仍在 GT 重建动态类。
- `Reload` 内按 `bReloadImmediately || HasDynamicFileChanged(snapshot)` 决定"先 Deactivate → 生成 → Activate"还是"生成 → MarkOutdated"。

## 3. 生成期保护（`bIsGenerating`）

| 阶段 | `Run()` 行为 |
|---|---|
| `bIsGenerating == true`（`OnBeginGenerator` 之后、`OnEndGenerator` 之前） | **只 `Event->Wait()`**：不跑编译、**不排空队列** |
| 退出生成期 | `OnEndGenerator` 置 `false` 并 `Trigger()` ⇒ 线程醒来，按"编译优先、队列其次"补跑 |
| 生成期到达的请求 | `bIsPending` 与 `FileChanges` **保留**（B-178 起 `OnBegin/OnEnd` 不再清），生成结束补跑 |

🔴 **禁止**：在 `OnBeginGenerator` 之后投递**依赖队列执行**的任务（分析等）。这类任务在生成期不会被取出；若调用方还在等它（如同步等待），即死锁。
—— `FUnrealCSharpEditorModule::Generator` 的拆分（B-183）就是为此把 `OnBeginGenerator` **后置到第二段**：分析在第一段投递，第二段才广播。

---

## 4. 优先级与唤醒

1. `bIsPending`（编译请求）**优先于** `TaskQueue`（后台任务）；
2. `TaskQueue` 内部 FIFO；
3. 两者皆空 → `Event->Wait()`（`Event` 为自动重置事件，入队/置 pending 都会 `Trigger()`）。

## 5. 调用方速查（HEAD）

| 调用方 | 入口 | 备注 |
|---|---|---|
| 文件监听 / 蓝图编译 | `AsyncCompile(FileChanges)` | 编辑器内常态路径 |
| `UnrealSharp.Editor.Compile` 控制台命令 | `Compile([](){})` | **同步跑在 GT**（未被本轮外移） |
| `FEditorListener::OnPostEngineInit` / `ImmediatelyDoWork` | `ImmediatelyCompile()` | 启动期发布检查 |
| `FUnrealCSharpEditorModule::Generator()`（编辑器） | `AsyncTask` 续跑里 `ImmediatelyCompile`（B-184 起改为投递编译器线程） | 见 §6 |
| `FUnrealCSharpEditorModule::Generator()`（commandlet） | 同步 `ImmediatelyCompile` | 进程即退，必须同步 |
| 分析 / 生成后处理 | `EnqueueTask(...)` | B-181 起的通用后台任务 |

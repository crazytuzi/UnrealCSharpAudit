# 轮 B-244 `F-LOG-001` 取号与修复：域卸载时反注册 LogBridge（2026-11-04）

> **对象**：新登记 **`F-LOG-001`**（P2 · 活跃）——「`LogBridge.Initialize()` 在域初始化时被调用，但**没有任何反注册**：域卸载后 `Console.Out`/`Console.Error` 仍指向 `LogBridge`，`LogBridge.LogFn` 仍指向 `FScriptLog::Log` ⇒ 之后任何 `Console.Write` 会沿着**已结束的域**回调到插件路径（模块卸载后即悬挂函数指针）」
> **来源**：B-241 追根时登记为候选（[`08-…/277`](277-轮B-241-F-LIFE-015追根一-静态普查与20s上限实验（2026-11-04）.md) §1.1）；本轮取号并修复。
> **规模**：插件 **7 文件 `+22/−0`**（0 新增公开 API / 日志 / 断言；C# 无需改动）
> **状态**：🟢 **已提交** `72360284`

## 1. 问题链（取号依据）

| 事实 | 证据 |
|---|---|
| 初始化时会接管 Console 并设置日志回调 | `FScriptDomainImpl.inl:596-607` 的 `RegisterLog()`：`LogBridgeSetLogFn(&FScriptLog::Log)` ＋ `LogBridgeInitializeFn()`；C# 侧 `LogBridge.Initialize()` 备份原 writer、`Console.SetOut/SetError(new LogBridge(...))` |
| 卸载时**没有**对应反注册 | 全树 `LogBridgeDeinitialize` 命中 **0**；`UnloadAssembly()` 只清桥表与函数指针 |
| 后果 | 域结束后 `Console` 仍被占用、`LogFn` 仍指向插件内的 `FScriptLog::Log`；**模块卸载后该指针悬挂**，任何后续 `Console.Write`（托管侧迟到代码/宿主）会跳转到已卸载代码 |
| 可达性 | 域 reload（编译后重建）、`SetActive` 循环、模块卸载窗口；不是"每帧都跑"，但属于**必然留下的悬挂回调** |

## 2. 施工（7 文件 `+22`）

| 文件 | 改动 |
|---|---|
| `CoreMacro/FunctionMacro.h` | 新增 `FUNCTION_LOG_BRIDGE_DEINITIALIZE = "Deinitialize"` |
| `Domain/Script/IScriptTypes.h` | 新增 typedef `log_bridge_deinitialize_fn`；`NATIVE_BRIDGE_METHODS` 增加 `Op(LogBridgeDeinitialize, log_bridge_deinitialize_fn, CLASS_LOG_BRIDGE, FUNCTION_LOG_BRIDGE_DEINITIALIZE, 0)`（**跨行折行以守 110 列**） |
| `Domain/Script/FScriptDomainImpl.inl` | 在 `RegisterLog()` 同一 `#ifndef SCRIPT_DOMAIN_CUSTOM_REGISTER_LOG` 门控内新增共享 `UnregisterLog()`（`LogBridgeDeinitializeFn != nullptr` 才调用） |
| `Domain/CoreCLR/FCoreCLRDomain.{h,cpp}` | 声明 `UnregisterLog()`；`UnloadAssembly()` 在 `AssemblyLoaderUnloadFn()` 之后、**清空函数指针之前**调用 |
| `Domain/Mono/FMonoDomain.{h,cpp}` | 同上 |

**顺序理由**：放在 `AssemblyLoaderUnloadFn()` 之后 ⇒ 卸载期间的日志仍能正常落盘；放在 `*_METHOD_CLEAR` 之前 ⇒ `LogBridgeDeinitializeFn` 仍然有效。
**LeanCLR 未改**：其 `SCRIPT_DOMAIN_CUSTOM_REGISTER_LOG` 定义了自定义日志路径（`LogLeanCLR` P/Invoke），不经过本门控的 `RegisterLog`；如需要按同一形态补，应单独立项（本轮不扩面）。

### 3.1 装置性崩溃（如实登记，不计为本改动的缺陷）

强制域卸载探针下，**改动侧 3 次运行出现 1 次** `EXCEPTION_ACCESS_VIOLATION` reading `0x10c`，崩溃点为 **`UBlueprintGeneratedClass::AddReferencedObjectsInUbergraphFrame`（引擎 GC 扫动态类，Foreground Worker）**；**基线（撤掉本改动、同一探针）1 次未复现**。
判断：崩溃发生在**引擎 GC 扫描动态类**时，不在新增的 `UnregisterLog()` 调用栈内；"在活会话里强制执行域卸载 + 随后 GC"本身就是既有探针装置的已知破坏面（与 B-241 的 dump 探针、B-231 生成会话的 `0x10c` 同族）。⇒ 记为**装置面/flaky**，正式判据以套件 ×2 同 SHA ＋ 生成 delta 为准。

### 3.2 未取得

- **"卸载后 `Console.Write` 不再回调 native"** 的**直接**运行期判据：需要 managed 侧探针（在 Default ALC 里加一个可调用的只读探针方法），本轮未做；本轮取得的是"方法解析成功 ＋ 调用无异常 ＋ 全套回归"。
- **LeanCLR 的对应面**：其日志走 `LogLeanCLR` P/Invoke，反注册形态未核（见 §2 末）。

## 7. 补充（B-245）：自定义反注册门控 ＋ LeanCLR 对称实现

> 复核意见：`RegisterLog` 有 `SCRIPT_DOMAIN_CUSTOM_REGISTER_LOG` 门控，`UnregisterLog` 也必须有**自己的对称门控**，否则自定义日志后端（LeanCLR）没有反注册出口。

| 项 | 内容 |
|---|---|
| 共享层 | `UnregisterLog()` 从 `#ifndef SCRIPT_DOMAIN_CUSTOM_REGISTER_LOG` 中移出，改由**独立的** `#ifndef SCRIPT_DOMAIN_CUSTOM_UNREGISTER_LOG` 门控（`FScriptDomainImpl.inl`） |
| LeanCLR | 定义 `SCRIPT_DOMAIN_CUSTOM_UNREGISTER_LOG`；新增 `FLeanCLRDomain::UnregisterLog()`：与 init 段 `LogBridge.InitializeLeanCLR` 的反射装配对称 —— `Class_Get_Method_From_Name(InteropModule, COMBINE_FULL_NAME(NAMESPACE_INTEROP, CLASS_LOG_BRIDGE), FUNCTION_LOG_BRIDGE_DEINITIALIZE)` ＋ `Bridge_Invoke`；`UnloadAssembly()` 在 `InteropModule = nullptr` **之前**调用 |
| C# 对称 | `LogBridge.InitializeLeanCLR()` 现在也备份 `ConsoleOut`/`ConsoleError`（原先只置 `bIsLeanCLR` 并重定向）⇒ `Deinitialize()` 的恢复分支在 LeanCLR 上同样有效 |
| 判据 | 插件提交 **`72360284`**（4 文件 `+26`）：UBT 5.6 **Succeeded**（25.78 s）／UBT 5.0 **Succeeded**（32.30 s）／C# build **0 Warning / 0 Error**（部署 `Interop.dll` = `94D985AEFA0F535…`）／套件 ×2 **1 992 / 0 / 同 SHA `085D3178D15B…`**／全量生成 **16 231 文件 delta 0**（286.2 s，干净退出）／§7 **CLEAN**／§8 **PASS**（4 文件：C# 4 空格缩进、`FLeanCLRDomain.cpp` AddedMax 98、`diff --check` 0） |

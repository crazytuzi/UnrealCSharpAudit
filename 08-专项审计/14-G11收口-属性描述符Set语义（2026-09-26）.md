## 1. 这一组到底是什么（一句话）

G11 是 **P0-3/P0-4「用 `nullptr`/越界表示失败」之外的第二个系统性模式**：**描述符层用"假定内存无效"的 API（`InitializeValue`）去写"已经构造完成"的属性内存**，以及**把"只 `Free` 外壳"当成"释放了一个对象"**。

判据不是"哪个函数写了 `InitializeValue`"，而是**`Dest` 是否已持有活值**（引擎两段注释互为反面：`InitializeValue` = *"The existing data is assumed invalid"*，`DestroyValue` = *"The existing data is assumed valid"*，`UnrealType.h:1044-1050` / `:962-967`）。同一个 `Set` 被两类调用点共用 ⇒ **修调用点，不修描述符**（§1.1 方案 1，本轮采纳）。

## 7. 复用价值（给下一轮）

- **判据优先于模式**：`InitializeValue` 出现 21 次，但**修复面只有 4 个点**。凡是"某 API 出现了 N 次"类的族，**先按 `Dest` 状态分类**，再定修复面（本轮用"引擎两段注释互为反面"作为分类依据，比逐点推演快且可复核）。
- **修调用点 vs 修被调用者**：当同一函数被"活值"与"未初始化"两类调用点共用时，**修调用点是唯一安全解**；改被调用者必然要引入两套语义（`Set`/`SetUninitialized`），而本仓口径不许新增公开 API。
- 🟢 **覆盖测量成本极低**：三个 `UE_LOG` 计数 + 一轮两阶段装置就拿到 5350 / 2770 次命中 ⇒ 对"只改了判空/只加了一次释放"这类**难观测**的修复，这是把"编译过"升级为"执行过"的最短路径（沿用 G2 轮的新手段）。
- 🎯 **可达性判据要读"快速返回"**：`IsSupported(FProperty*)` 的第一行 `if (bIsGenerateAllModules && Property->IsNative()) return true;` 会让后面所有排除分支**对 native 属性失效**。凡引用"某类型被生成器排除"的结论，必须同时确认**是否在快速返回之后**——本轮 `F-PROP-007` 的"不可达"就是栽在这一行上。
- 🎯 **产物即地面真值**：判断"某个 C# 属性会不会被生成"，最快的证据是 `grep` 产物（`Script/UE/Proxy/**`），而不是读生成器（生成器有配置开关、快速返回、旧产物残留三层干扰）。
- **改前/改后对照的替代**：本轮没有 baseline 二进制，退而记录"路径命中数 + 无回归 + 用例名逐名一致"。下一轮若要做真正的收益量化，建议先建"改前二进制留档"（编译产物 + patch 反向应用脚本），否则每次都会卡在同一处。

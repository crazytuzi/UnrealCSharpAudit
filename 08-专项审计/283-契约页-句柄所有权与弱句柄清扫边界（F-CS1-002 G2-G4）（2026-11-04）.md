## 2. 契约条款

| 条款 | 内容 |
|---|---|
| **C-HANDLE-1** | 强/弱矩阵沿用 [`08-…/212`](212-契约页-句柄所有权矩阵与OptionalHelper取用契约（2026-10-30）.md)：包装类（字符串/容器/委托/软引用/属性 helper）**Weak**；C++ 持有的对象 **Normal**（引用计数，`Free` 归零释放）。矩阵不改。 |
| **C-HANDLE-2** | **弱句柄表项只由两条路径回收**：① 显式 `Free`（`Count` 归零；`Target == null` 时直接移除）；② 域卸载的 `HandleData.Clear()`。**不提供**运行期清扫器 —— B-177 方案 C 否决理由（锁内 O(N) 扫描、表项本应由 `Free` 清理、收益有限）维持。弱句柄**不阻止**对象回收，但**表项**不会因对象被回收而自动消失。 |
| **C-HANDLE-3** | 句柄号**进程内单调、不复用**（`++Handle`）；`Clear()` **不重置**计数器 ⇒ 跨域不保证从 0 开始，**调用方不得假设句柄号可复现**（日志/存档/对比脚本不应用句柄号做身份）。 |
| **C-HANDLE-4** | 同一**托管对象实例**的 `GCHandle` 类型由**首次** `Alloc` 决定，后续 `Alloc` 只增计数、**静默忽略**本次意图 ⇒ 调用方对同一实例必须使用一致的意图（`Alloc(x)` / `Alloc(x, true)` 不混用）。`FClassReflection::NewObject(bIsWeak = false)`（`FClassReflection.h:68`／`.cpp:720-728`）每次新建实例，常规路径不构成冲突；**混用只在"同一实例被两条不同意图的路径重复登记"时发生**，当前**未取实证**。 |

## 3. 复评触发条件

| 条款 | 触发条件（出现任一即重新立项，不再按本页契约处理） |
|---|---|
| C-HANDLE-2 | 长会话/多次域 reload 后 `Handles` 表项数**单调增长**（探针见 §4）；或出现"弱句柄表项泄漏"实证 |
| C-HANDLE-3 | 出现依赖句柄号连续/可复现的外部消费者（存档、AB 对比、协议） |
| C-HANDLE-4 | 出现"同一实例先弱后强"的调用点证据，或 `IsAlive` 在 C++ 仍持有期间返回 0 的实证 |
| G4 | 出现"域销毁但 `AssemblyLoaderUnloadFn == nullptr` 且表非空"的路径（如某后端在方法绑定前就分配过句柄） |

## 4. 判据配方（本轮**未跑**，留给触发时使用）

1. **表项计数探针**（C# 侧）：临时反射读 `HandleData` 的私有静态 `Handles` 与 `ObjectToHandleReference`，每条日志输出 `Handles.Count` / 死弱项数（`Target == null`）。
2. **域 reload 循环**：`UnrealCSharp.Editor.Generator` 或既有域重建命令连续触发 N 次（N = 5/20），比较每次 `Deinitialize()` 后的计数；期望 **0**（`Clear()` 生效）。
3. **C++ 侧对照**：`IsAlive` 抽样若干弱句柄，确认 `Clear()` 后 `IsAlive == 0`（表清空）。
4. 若 1–3 全部符合 ⇒ 契约成立；若表项增长 ⇒ 按 §3 立项清扫器。

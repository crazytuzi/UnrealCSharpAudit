## 1. 施工面

### 1.1 `F-HLP-005` —— 非 POD 元素补构造（`FArrayHelper.cpp`，+37/−11）

三个 API 用**同一判据**（与同文件 `RemoveAt:251` 的既有写法一致）：

```cpp
const auto PropertyFlags = InnerPropertyDescriptor->GetPropertyFlags();

const auto bNeedConstruct = !(PropertyFlags & (CPF_IsPlainOldData | CPF_NoDestructor));
```

| 函数 | POD 路径（不变） | 非 POD 路径（新增） |
|---|---|---|
| `AddUninitialized` | `AddUninitializedValues(InCount)` | `AddValues(InCount)` |
| `InsertZeroed` | `ScriptArray->InsertZeroed(...)` | `InsertValues(InIndex, InCount)` |
| `AddZeroed` | `ScriptArray->AddZeroed(...)` | `AddValues(InCount)` |

- 两个整型返回函数保持**单出口**（`if (InCount >= 0) { … return 三元; } return INDEX_NONE;`）；`InsertZeroed` 是 `if/else` 语句、无提前 `return`。

### 1.4 `F-INT1-003` —— 注册失败释放（`FRegisterScriptInterface.cpp`，+7/−2）

```cpp
const auto bAdded = FCSharpEnvironment::GetEnvironment().AddMultiReference<
	TScriptInterface<IInterface>, true, false>(Class, InManagedObject, ScriptInterface);

if (!bAdded)
{
	delete ScriptInterface;
}
```
`AddMultiReference` 在 `MultiRegistry == nullptr` 时返回 `false`（`FCSharpEnvironment.inl:238-244`）；成功时所有权转移给注册表（`FMultiRegistry.inl:54-79` 的 `FMemory::Free`），失败时由本处 `delete` —— 与 `new` 成对，`TScriptInterface` 为平凡类型。

### 1.5 `F-ABI-007` —— `ulong` 分支（`FieldBridge.cs`，+1）

```csharp
_ when InValue is ulong UnsignedValue => unchecked((long)UnsignedValue),
```
放在 `_ when InValue.GetType().IsValueType => Convert.ToInt64(InValue)` **之前**（否则 `ulong > long.MaxValue` 走 `Convert.ToInt64` 抛 `OverflowException`）。位语义与 C++ 侧 `int64` 一致。

### 1.6 `F-ENV-018` —— 单出口条件式（`FCSharpBind.cpp`，+1/−3）

```cpp
return Bind<false>(InClass) ? Bind(static_cast<UObject*>(InClass)) : InvalidManagedHandle;
```
**安全性核对**：`Bind<IsNeedOverride>(UStruct*)`（`FCSharpBind.inl:8-27`）在"class descriptor 已存在"时**提前 `return true`** ⇒ 返回 `false` 只发生在 `BindImplementation` 真失败时；因此不会把"已绑定"误判成失败。原建议的 `ensureMsgf` **撞 G7** 作废。

## 3. 🔴 前提更正：`F-HLP-005` 的"崩溃"未复现

原报告（`01-…/07` §F-HLP-005）断言：`TArray<FText>` 走 `AddZeroed` 后"任何 `Get()` 读取该元素也会崩"。**本轮实测不成立**（改前 4 条断言全 true，无崩溃、无日志异常）。三条机制里**至少一条**解释了这一点：

1. `FText` 持 `TRefCountPtr<ITextData>`（`Text.h:899`）—— 零值即空指针；`TRefCountPtr` 的**拷贝/析构对空指针安全**（`TRefCountPtr` 语义），所以"零值 → `Empty()`/`RemoveAt` 析构"这一半**本来就不崩**。
2. `FText::Rebuild()` 先 `if (TextData)`（`Text.cpp:1286-1292`），而 `FText::ToString()` = `Rebuild(); return GetTextData().GetDisplayString();`（`:1250-1254`）—— 若走的是**包装对象**而非槽位按位视图，空值就被 `Rebuild` 的判空兜住。
3. 插件侧 `FTextPropertyDescriptor::Get`（`FTextPropertyDescriptor.cpp:4-20`）走 `Class->NewObject(true)` **新建包装对象**再加字符串引用，C# 拿到的未必是槽位原始位模式。

> **逐条归因未拆开**（需要单点探针），因此本条的**结论按"未复现"记**：`F-HLP-005` 由"P2 崩溃面"改判为"**P2 未定义行为面收窄 / 构造对等化**"。修法本身仍成立且更正确（不再把未开始生命周期的槽位交给 C#），4 条守卫保留为**回归护栏**（能在将来把"零值恰好可用"的巧合变成显式约束）。

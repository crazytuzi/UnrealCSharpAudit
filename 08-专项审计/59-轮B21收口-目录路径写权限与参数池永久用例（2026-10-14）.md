```cpp
bool FDirectoryPathCustomization::IsWritablePath(const FString& AbsolutePath) const
{
	auto bIsWritablePath = false;

	auto& PlatformFile = FPlatformFileManager::Get().GetPlatformFile();

	if (const auto TempFilename = FPaths::CreateTempFilename(*AbsolutePath, TEXT("UnrealCSharp"), TEXT(".tmp"));
		!TempFilename.IsEmpty())
	{
		if (const auto FileHandle = PlatformFile.OpenWrite(*TempFilename))
		{

			PlatformFile.DeleteFile(*TempFilename);

		}
	}

	return bIsWritablePath;
}
```

#### 1.1.1 有没有现成 API？（维护者提问 → 检索 ＋ 实测结论，**留档**）

**结论：UE 没有可移植的"这个目录能不能写"API。**

| 候选 API | 引擎实现 | 为什么不能用作判据 |
|---|---|---|
| `IPlatformFile::IsReadOnly(const TCHAR*)` | Windows：`GetFileAttributesW(...) & FILE_ATTRIBUTE_READONLY`（`WindowsPlatformFile.cpp:1178-1183`） | 只看**只读属性位**，**不看 ACL/权限** |
| `FFileStatData::bIsReadOnly`（`GetStatData`） | 同源（`WindowsPlatformFile.cpp:1658/1703`） | 同上 |
| `access(path, W_OK)` | **引擎自己在非 Windows 的 `OpenWrite` 内部用**（`UnixPlatformFile.cpp:997`、`ApplePlatformFile.cpp:666`、`AndroidPlatformFile.cpp:1626`、`IOSPlatformFile.cpp:589`） | 真访问检查，但**未导出为公共 API** |
| `AccessCheck` / `GetEffectiveRightsFromAcl` | 引擎内**无**调用点 | 需自写 `PLATFORM_WINDOWS` 分支 |

🔴 **盲区实测（本机）**：DACL 拒绝写之后 —— 目录属性仍 = `Directory`（**只读位未置位**，属性 API 会回答"可写"），但真实写入 **失败**（`UnauthorizedAccessException`）⇒ 属性类 API 恰好漏掉要挡的场景；**引擎自己的答案就是"试着按写方式打开"**（Windows `CreateFileW(GENERIC_WRITE, CREATE_ALWAYS)`、POSIX `access(W_OK)`）。

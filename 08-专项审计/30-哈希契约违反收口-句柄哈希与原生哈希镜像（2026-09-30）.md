## 1. 前提回核（第 0 步，逐条落代码）

### 1.1 机制：`GetHashCode` 是"实例身份"，而 `Equals` 是"原生值/身份"

- `HandleData.Alloc`（`Script/Interop/Handle/HandleData.cs:41-58`）以 **`ConditionalWeakTable<object, HandleReference>`** 为键：**一个托管实例恰好一个句柄**（`Value = ++Handle` 只在首次分配时写入）⇒ `(int)HandleData.GetHandle(this)` 是**实例身份**哈希。
- 14 个手写包装类的相等一律走原生：`==` = `ReferenceEquals(A,B) || X_IdenticalImplementation(handleA, handleB)`，而 `Identical` 在原生侧解析句柄后按**值**（`*A == *B` / `CompareScriptStruct`）或**对象指针**比较 ⇒ **两个不同实例只要原生相等，哈希就不同** —— 违反 .NET 的 `Equals ⇒ GetHashCode` 契约。
- 受影响面 = **用户侧 .NET 哈希容器与 LINQ**（`Dictionary` / `HashSet` / `Distinct` / `GroupBy` / `ToDictionary`）；**`TMap`/`TSet` 包装不受影响**（原生容器，不走 .NET 哈希）。

## 2. 跨版本核实（5.0.3 → 5.8.3，九个 release tag）

> 方法：对 `D:\file\UnrealEngine\Release` 的 `5.0.3 / 5.1.1 / 5.2.1 / 5.3.2 / 5.4.4 / 5.5.4 / 5.6.1 / 5.7.4 / 5.8.3` 九个 tag 逐 API `git show` / `git grep`。**结论：12 个导出所依赖的引擎 API 在 5.0–5.8 全部存在**，无需新增版本门控；真正需要门控/偏离的是**语义**而非**存在性**。

### 2.1 字符串族：表达式九版同形，无需门控

- 九个 tag 的 `FStrProperty::GetValueTypeHashInternal` 都是 `return GetTypeHash(*(const <StringType>*)Src);`，唯一实现都是 `FCrc::Strihash_DEPRECATED(S.Len(), *S)` ⇒ **大小写不敏感**（对大小写敏感的相等是"更粗"，安全）。
- `GetTypeHash(const FString&)` 并未消失：5.0.3–5.3.2 在 `Core/Public/Containers/UnrealString.h`（`:1847 / :1865 / :2058 / :2063`），**5.4 起随 `FString` 类搬进 `UnrealString.h.inl`**（5.4.4 `:2239` / 5.5.4 `:2284` / 5.6.1 `:2350` / 5.7.4 `:2176` / 5.8.3 `:2129`，由 `UE_STRING_CLASS` 宏为三种字符串各生成一次）⇒ **调用方视角无差异**。
- `FAnsiString`/`FUtf8String` 的**容器类型** 5.4 起存在、**属性类** 5.5 起存在；插件现有宏 `UE_F_ANSI_STR_PROPERTY` / `UE_F_UTF8_STR_PROPERTY` = `UE_VERSION_START(5,6,0)`（[`UEVersion.h:152,154`]）比引擎事实**保守一个 minor** ⇒ 本轮**不收窄也不放宽**该门控（属独立裁定）。
- ⚠️ **不可跨类型复用哈希**：同文本的 `FString` 与 `FAnsiString` 哈希值不同（`ANSICHAR` 特化每字符 1 次查表、`WIDECHAR` 每字符 2 次）⇒ 三个包装各调自己的 `GetTypeHash`（本轮即如此）。

### 2.2 指针族：仅 `TWeakObjectPtr` 需要偏离（9/9 版本）

- **`TWeakObjectPtr`**：相等 = `(ObjectIndex == && ObjectSerialNumber ==) || (!IsValid() && !Other.IsValid())`（5.0.3 `WeakObjectPtr.h:91` … 5.8.3 `:166`；5.6+ 第一支被 `UE_WITH_REMOTE_OBJECT_HANDLE` 门控为 `ObjectRemoteId` 比较），而哈希 = `uint32(ObjectIndex ^ ObjectSerialNumber)`（5.0.3 `:167-170` … 5.8.3 `:583-586`）⇒ **两个"分别指向已销毁对象"的失效弱指针相等而哈希不同**（`5^3=6` vs `0xFFFFFFFF^0`）⇒ 必须偏离。
- **`TLazyObjectPtr` / `TSoftObjectPtr` / `TSoftClassPtr` / `TSubclassOf`：九版全部自洽**（比较与哈希同源：`ObjectID`/`FSoftObjectPath`/`UClass*`）。⚠️ 特别注意"两个都无法解析的 soft/lazy 指针**不相等**"（按 `ObjectID` 比较）—— 这正是引擎自洽的原因。
- **`TScriptInterface`**：比较九版一致 = **对象 + 接口指针**（`ScriptInterface.h` `:199`…`:285`）；引擎唯一哈希只哈希接口指针。**5.8 的真实变化在构造函数**（5.8.3 `:176-183` 新增 `SetObject(nullptr)` 规范化；`TObjectPtr` 构造改为委托），**不是比较函数** ⇒ 哈希公式**不需要按版本分叉**；本轮选择比两种相等都更粗的**对象级**哈希 ⇒ 与版本无关地安全。
- ⚠️ **本轮的自我更正**：第一版施工曾给 `TLazyObjectPtr` 也加"IsValid ⇒ 哈希 : 0"守卫；跨版本核实证明该族九版自洽 ⇒ **该偏离被撤销**（避免无依据的语义分叉）。

### 2.3 结构体族：三个"不可盲调"的前提 + 一个"引擎自身不自洽"的反例

1. **`UScriptStruct::GetStructTypeHash` 有前置**：直通 `GetCppStructOps()->GetStructTypeHash(Src)`，**无空指针检查**；`ICppStructOps::GetStructTypeHash` 在 **5.0.3–5.6.1** 带 `ensure(HasGetTypeHash())`（5.6.1 `Class.h:1682`），5.7.4/5.8.3 改为 `if (HasGetTypeHash()) … else return 0`；`GetCppStructOps()` 自身带 `checkf(bPrepareCppStructOpsCompleted, …)`（5.6.1 `Class.h:1839`）。
2. **`UUserDefinedStruct` 九版都有 `GetStructTypeHash` 覆写**（5.0.3 `UserDefinedStruct.cpp:319` … 5.8.3 `StructUtils/UserDefinedStruct.cpp:390`，逐属性哈希），且其 `PrepareCppStructOps` 把 `CppStructOps` 置 **nullptr** ⇒ 对 BP 结构体 `GetCppStructOps()->HasGetTypeHash()` 会**空指针解引用**。
3. **反射一致性的版本分界**：`FFloatProperty::Identical` 在 ≤5.4 是 `==`（继承自 `TProperty_WithEqualityAndSerializer`）而哈希是**位模式**（`GetTypeHash(float) = *(uint32*)&Value`）⇒ `±0` 相等却哈希不同；**5.5 引入 `CorePreciseFP`** 后 `PreciseFPEqual/PreciseFPHash`（`PreciseFP.cpp:12-17/32-38`）把 NaNs 视为互相相等、把 `±0`/NaN 一律哈希为 0 ⇒ 自洽。
4. 🔴 **反例（本轮最关键的前提产出）**：`CompareScriptStruct` 只在 `StructFlags & STRUCT_IdenticalNative` 时用 ops `Identical`，否则**逐属性**比较（5.6 `Class.cpp:3611-3627`）；而 `FVector` **有** `STRUCT_IdenticalNative`（实测：ops 分支被走到）且 `GetTypeHash(TVector) = FCrc::MemCrc_DEPRECATED(&Vector, sizeof(Vector))`（`Vector.h:2583`，**原始内存 CRC**）⇒ `FVector(-0.0,0,0)` 与 `FVector(0.0,0,0)` **相等而哈希不同** —— **引擎自身的结构体相等/哈希对就不自洽**（即 UE 原生 `TSet<FVector>` 同一个洞）。
   ⇒ 由此定下修法：**不盲用 ops 哈希**，而是**镜像 `CompareScriptStruct` 的分支**并优先走逐属性哈希（见 §3.3）。

### 3.3 结构体族：镜像 `CompareScriptStruct` 的分支（`FRegisterStruct.cpp`）

```
GetTypeHash(Struct, Value):
    逐属性哈希（StructHash）成功 ⇒ 用它
    ── 否则若 (StructFlags & STRUCT_IdenticalNative) 且有 ops 哈希 ⇒ GetStructTypeHash(Value)
    ── 否则 ⇒ 0
```

`StructHash` 的规则（逐条对应 `CompareScriptStruct` 的逐属性路径）：

| 规则 | 依据 |
|---|---|
| 遍历 `InStruct->PropertyLink` 链（含继承）并对每个属性取 `ContainerPtrToValuePtr<void>` | 与 `CompareScriptStruct` 的 `TFieldIterator<FProperty>` 同序同集 |
| `FStructProperty` ⇒ **递归**（不调它的 ops 哈希） | 避免嵌套原生结构体把 memcrc/位哈希的 `±0` 问题带回来 |
| `FFloatProperty`/`FDoubleProperty`：值 `== 0` 时贡献 **0**，否则 `GetTypeValueHash` | 复刻 `UE::PreciseFPHash` 的"zeroes treated equal"（5.5+），并把 **≤5.4 的位哈希 `±0` 不一致**一并消除 |
| `FWeakObjectProperty`：`IsValid()` 为假贡献 **0** | 复刻 `FWeakObjectPtr::operator==` 的"双失效相等"条款 |
| 其它属性：`HashCombineFast(OutHash, Property->GetValueTypeHash(Value))` | 逐属性哈希与逐属性 `Identical` 是引擎的配对契约 |
| **任一属性缺 `CPF_HasGetValueTypeHash` ⇒ 整个结构体回 0** | 避免 `FProperty::GetValueTypeHash` 内部 `check(CPF_HasGetValueTypeHash)` 触发；同时保证"不可哈希 ⇒ 不猜" |

**为什么"逐属性优先"而不是"ops 哈希优先"**：§2.3-4 的 `FVector ±0` 反例是**实测**（改前/改后判据都命中它）；而逐属性路径与 `CompareScriptStruct` 的逐属性语义**同构**，对"ops 相等忽略某字段"的罕见结构体，ops 哈希与逐属性哈希**具有同样的暴露**（两者都哈希全部字段）⇒ 逐属性优先**不更差、且严格更好**（`±0`/NaN 归一）。

### 3.4 两处引擎语义偏离（必读）

1. **`TWeakObjectPtr` 失效 ⇒ 0**（9/9 版本必需）：反例见 §2.2；修正公式与 `UE_WITH_REMOTE_OBJECT_HANDLE`、`UE_WEAKOBJECTPTR_ZEROINIT_FIX` 无关（有效分支一律调引擎 `GetTypeHash`，不自算 `index^serial`）。同一归一化也在 `StructHash` 的 `FWeakObjectProperty` 分支里复刻（否则"含弱指针成员的结构体"会继承同一个洞）。

## 6. 复用价值（给下一轮）

1. 🔴 **"`Equals` 走原生、`GetHashCode` 走句柄"是一整族形态**：修它必须**成对**改（手写包装 + 生成器），否则下一次重生成立刻回归；本轮的 `git grep 'GetHashCode() => (int)HandleData'` = **唯一可机械核查的判据**（改前 5975 + 14、改后 0）。
2. 🔴 **引擎哈希不能按"名字存在"就用**：`UScriptStruct::GetStructTypeHash` 有三重前置（`HasGetTypeHash` 的 `ensure`、`GetCppStructOps()` 的 `checkf`、UDS 的 null ops）；**先问"引擎自己这一对自洽吗"**——`FVector` 的 `±0`（`MemCrc` vs `==`）就是活反例。
3. 🟢 **镜像"引擎的分支结构"比镜像"引擎的函数"更安全**：`CompareScriptStruct` 的 `STRUCT_IdenticalNative` 分支决定了"该用 ops 哈希还是逐属性哈希"；照抄这一判据比照抄任一实现都更接近正确。
4. 🟢 **"更粗的哈希"是安全方向，"更细"才危险**：`IsValid ? hash : 0`（weak）、对象级哈希（script interface）、字符串大小写不敏感哈希（引擎自带）都是"更粗"；判定一致性只需检查"相等 ⇒ 同哈希"，不需要哈希相等 ⇒ 值相等。
5. 🪤 **跨版本核实的性价比极高**：本轮 3 个并行只读子代理在 9 个 tag 上核出 4 处会改代码的事实（weak 必须偏离、lazy 不需偏离、UDS null ops、`±0` 版本分界），其中 2 处直接改掉了第一版施工。
6. 🪤 **改前对照的最省做法**：`git stash push -- Script/UE`（只藏 C# 层，原生改动是惰性的）⇒ 一次 C# 重编即可得到改前态，无需回退原生与产物。

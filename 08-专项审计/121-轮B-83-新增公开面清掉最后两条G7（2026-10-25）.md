## 1. `F-PROP2-006 (04b)`：新增 `FText.ToBufferString()`

### 1.1 为什么是"新增"而不是"改语义"

B-74 实测：把 `FRegisterText.cpp` 的 `ToString` 改走 `WriteToBuffer` 可编可跑，但会把既有用例 `TextToString` 的期望（显示串 `"12"`）打红。⇒ 本次**不动 `ToString`**，另加一个**语义明确**的公有方法，命名跟随既有 `FText(string InBuffer, …)` 构造参数（`InBuffer`）的用词。

### 1.2 改动面（4 文件）

| 文件 | 改动 |
|---|---|
| `Script/UE/CoreUObject/FText.cs:63-65` | `public string ToBufferString()` → 调 `FTextImplementation.FText_ToBufferStringImplementation` |
| `Script/UE/Library/FTextImplementation.cs:60-76` | 声明 `__FText_ToBufferStringImplementation` 部分方法 ＋ 包装（`HandleData.GetObject` → `Free`），形态与 `FText_ToStringImplementation` 逐字同形 |
| `Source/UnrealCSharp/Private/Domain/Interop/FRegisterText.cpp:84-100` | 新增 `ToBufferStringImplementation`（`GetString<FText>` → `FTextStringHelper::WriteToBuffer` → `NewString`），null 时返回 `InvalidManagedHandle` |
| 同上 `:110` | `.Function("ToBufferString", ToBufferStringImplementation)` |

> **库桥是自动的**：`__FText_ToBufferStringImplementation` 由 `UnrealTypeSourceGenerator.cs:1173` 的 `LibraryBridgeGenerator` 从**部分方法声明**生成（`LibraryBridgeReceiver` 扫 `Script.Binding`/`Script.Library` 命名空间的 `partial` 声明）⇒ 只要声明 + native 注册成对，P/Invoke 体就自动生成。

### 1.3 判据（永久用例，工程侧）

`UnitTest/String/FText/UnitTestSubsystem.cs` 新增 `TestTextToBufferString()`：

| 断言 | 读数 |
|---|---|
| `TextToBufferStringNonEmpty`（`new FText("12").ToBufferString().Length > 0`） | **true** |
| `TextToBufferStringRoundTrip`（`new FText(Buffer).ToString() == "12"`） | **true** |

> **往返成立**：`WriteToBuffer` 产出的是 `ReadFromBuffer`（即 `FText(string,…)` 构造）能解析的串 ⇒ 新增 API 与既有构造**互为逆运算**。这两条是**行为判据**（不是静态判据），且不依赖被改语义的旧用例。

## 2. `F-ABI-007`：新增 `TryGetStaticValue` op

### 2.1 为什么选"新 op"而不是"改装 `GetStaticValue`"

`GetStaticValue` 用 `0` 同时表示"字段不存在"与"值就是 0"。**改签名**要动既有 ABI 与唯一消费点；**新 op** 只做加法，旧 op 原样保留（老调用方零影响）。

## 6. 边界

1. **`TryGetStaticValue` 的"缺失"分支未运行期取证**（见 §2.3）；目前靠"唯一消费点字段名同源"论证不可达，与 B-82 的终局理由一致。
2. **Mono / LeanCLR 未实跑**：`TryGetFieldStaticValue` 在两者是同一份 `FScriptDomainImpl.inl` 实现 ＋ override 声明；仅经 5.0 门禁编译覆盖（CoreCLR 构建），LeanCLR 的 `Bridge_Invoke` 对 `int64*` 出参的语义**未实测**（同类指针出参的既有先例：`TypeBridgeBoxInt64(int64*)`）。
3. **`FText.ToBufferString()` 的语义边界**：返回的是 `FTextStringHelper::WriteToBuffer` 的产物（可能带引号/NSLOCTEXT 形式），**不保证人类可读**；与 `ToString()`（显示串）语义不同，二者并列存在。
4. **新 API 的位置**：`ToBufferString` 落在 C# 用户面（`Script/UE`），未在 C++ 侧新增任何公开方法；`TryGetFieldStaticValue` 是**新增纯虚**（接口变更），三个后端必须实现 —— 已全部补齐，但外部若有人自实现 `IScriptDomain` 会编译失败（插件内无第三方实现）。
5. 本轮未跑 PIE / 打包版；`Interop.dll` 仍走手工发布（同 B-79/B-81 的边界说明）。

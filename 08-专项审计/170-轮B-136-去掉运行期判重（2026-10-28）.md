## 1. 最终实现

```cpp
for (TObjectIterator<UFunction> Iterator; Iterator; ++Iterator)
{
	const auto Function = *Iterator;

	if (Function == nullptr || Function->GetName() != SignatureFunctionName)
	{
		continue;
	}

	return Function;
}

return nullptr;
```

- 命名契约不变：`"F" + SignatureFunction->GetName() − HEADER_GENERATED_DELEGATE_SIGNATURE_SUFFIX`（逆 `GetFullClass`）。
- 与项目既有约定一致：**桥接层只按类型名匹配**（与 `GetClass`/`GetFullClass` 同口径），不引入 namespace 推导。
- 前缀判定用仓内宏 **`STRUCT_PREFIX`**（= `"F"`，`TBaseStructure<FVector>::Get()->GetPrefixCPP()`），不再用字面量 `TEXT("F")`；**不是** `OBJECT_PREFIX`（= `"U"`）——委托 wrapper 是 F 类型（`GetFullClass` 返回 `"F"+名`），与 `FDynamicDependencyGraph.cpp` 里 `static auto F = STRUCT_PREFIX;` 同口径。
- 0 个命中 ⇒ `nullptr`（属性按不支持丢弃）；≥1 个命中 ⇒ **首命中**。

## 1.1 这个 `UFunction` 是谁、什么时候创建

| 问题 | 实证（`Intermediate/Build/Win64/UnrealEditor/Inc/UnrealCSharpTest/UHT/TestSingleCastDelegateOwner.gen.cpp`） |
|---|---|
| 谁生成 | UHT：`Z_Construct_UDelegateFunction_<Module>_<Name>__DelegateSignature()` |
| 何时创建 | **懒创建、只建一次**：`static UFunction* ReturnFunction = nullptr; if (!ReturnFunction) { ConstructUDelegateFunction(&ReturnFunction, ...); }` |
| 谁先触发 | 拥有该委托属性的 **UCLASS 注册属性**时（`FDelegatePropertyParams.SignatureFunction` 引用它）⇒ 模块加载 / 首次 `StaticClass()` |
| 放在哪 | `{ (UObject*(*)())Z_Construct_UPackage__Script_<Module>, ..., "<Name>__DelegateSignature" }` ⇒ outer = 包 `/Script/<Module>`，名字 = `<Name>__DelegateSignature` |
| 之后可见性 | 创建后缓存进包的对象表 ⇒ 运行期 `TObjectIterator<UFunction>` 能扫到（本函数反查的基础） |

> 类内声明（outer 为 UClass）时 outer 就是那个类 —— 这正是 `GetClassNameSpace` 两个分支的来源，也是"同名委托在不同类下"现象的根因。

## 1.2 C# 侧不产生 `UFunction`：wrapper 与签名函数的分工

| 步骤 | 谁做 | 产物 |
|---|---|---|
| 1. C++ 编译 | UHT | `Z_Construct_UDelegateFunction_<Module>_<Name>__DelegateSignature`（懒创建 ctor） |
| 2. 模块加载 / 首次 `StaticClass()` | 引擎类注册 | 真正 `new` 出 `UFunction`（outer = `/Script/<Module>`），登记进包 |
| 3. 脚本代码生成（编辑器 `FUnrealCSharpEditorModule::Generator` 或 `-run=GeneratorScriptCode`） | `FClassGenerator` / `FStructGenerator` / `FGeneratorCore` → `FDelegateGenerator` 遍历反射 | `F<Name>.cs`（`Execute/Bind/Unbind/IsBound` 或 `Broadcast/Add/Remove`），按 (namespace, class) 去重 |
| 4. `dotnet build` | Roslyn（`Script/SourceGenerator`） | 只补 `[UClass]`/`[UStruct]` 分部类，**不生成委托 wrapper** |
| 5. C# 编译完成后 | `FCSharpCompilerRunnable` → `FDynamicGenerator::Generator` → `FDynamicGeneratorCore` → `FTypeBridge::Factory` | 动态类的 `UClass`/属性；委托属性在此按名字反查第 2 步的 `UFunction` 并赋给 `SignatureFunction` |

> 结论：**C# 永远不创建 `UFunction`**，只能复用 C++ 声明的委托签名；纯 C# 无法声明新委托类型（B-135 因此需要 `UTestSingleCastDelegateOwner` 这个 C++ 宿主）。

## 5. 边界（已登记）

1. **同名首命中**：引擎确有 5 组同名委托（namespace 不同）。若将来某个 C# 动态属性使用这类名字，首命中可能绑到**另一个签名**（参数不同 ⇒ 执行期错误）。当前语料未使用这些名字；若需支持，只能在"命名唯一"上做文章（本项目未采用任何判重方案）。
2. **native-only 名**：反查按未编码名；非 native 委托签名会 fail-closed 丢弃（沿用 169 §3）。
3. **扫描成本**：每个未命中类型一次 `TObjectIterator<UFunction>` 全扫；未缓存（缓存需处理域卸载/热重载失效面）。

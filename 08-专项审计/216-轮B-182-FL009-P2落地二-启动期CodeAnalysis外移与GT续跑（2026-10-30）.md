## 1. 施工

```cpp
void FEditorListener::OnPostEngineInit()
{
	FCSharpCompiler::Get().EnqueueTask([]()
	{
		FCodeAnalysis::CodeAnalysis();

		AsyncTask(ENamedThreads::GameThread, []()
		{
			FDynamicGenerator::CodeAnalysisGenerator();
		});
	});
}
```

## 3. 为什么 `Generator()` 动作不照搬（结构性原因）

`FUnrealCSharpEditorModule::Generator()`（`UnrealCSharpEditor.cpp:348` 起）是 **13 步模态慢任务**，序列为
`OnBeginGenerator.Broadcast()` → SolutionGenerator → **CodeAnalysis** → **CodeAnalysisGenerator** → … → `EndGenerator`。

- `OnBeginGenerator` 会置 `FCSharpCompilerRunnable::bIsGenerating = true`（B-178 起"只切 `bIsGenerating`"）；
- 而 `Run()` 的**空闲分支**才排空 `TaskQueue`，`bIsGenerating` 为真时直接 `Event->Wait()`；
- ⇒ 若在这个动作里 `EnqueueTask` 一个分析任务，该任务**永远不会被执行**（线程在等事件、醒来仍见 `bIsGenerating`），而 GT 又在等它 ⇒ **死锁**。

要外移必须**重排动作**（分析先行、`OnBeginGenerator`/慢任务后置），并处理 `FScriptDomainTypeScope`、culture 保存/恢复、`FScopedSlowTask` 的栈生命周期——属独立设计，非"顺手改"。**本轮保持同步**（该动作本身就是带进度对话框的显式长任务）。

## 7. 边界

1. **后台线程读 settings CDO**：`FCodeAnalysis` 的路径/dotnet 解析会经 `FUnrealCSharpFunctionLibrary::GetScriptDirectory()`/`GetDotNet()` 读 `UUnrealCSharpEditorSetting`/`UUnrealCSharpSetting` 的 CDO。B-181 起这些读已发生在编译器线程上，本轮把启动期也纳入同一形态；与 `F-CONC-008`（编译工作线程访问 CDO）的"决定不做"口径一致，**登记为已知边界**，未做"GT 预算路径再传值"的重构。
2. **退出期竞态**：若编辑器在分析完成前关闭，GT 续跑可能不执行 ⇒ 本次启动不生成动态类型；下次启动会重跑（与同步路径"没跑到"的后果相同）。
3. **`CodeAnalysis()` 失败仍会跑生成器**：与改前一致（原同步代码也是先 Compile+Analysis 再无条件生成），未改变失败语义。
4. **未跑 Mono/LeanCLR**：编辑器线程模型改动与脚本后端无关；5.0 只做编译门禁。

## 1. 缺陷确认与改前读数

### 1.1 机制

`FBindingClassGenerator::GeneratorPartial` 只在 `!Function.GetParamNames().IsEmpty()` 时采用声明里的名字，随后**按形参下标**索引 `FunctionParamName[Index]`：

| 位置 | 用法 |
|---|---|
| `:386` | 默认参数体里的 `%s ??= …` |
| `:399` | 声明签名的 `%s %s` |
| `:495` / `:498` | 实现体 InBuffer 的赋值 |
| `:609` | 实现体 OutBuffer 的写回（`FunctionParamName[FunctionOutBufferIndex[Index]]`） |

`:349` 只判**非空**、不判数量 ⇒ 当 `GetParamNames().Num() < Params.Num()` 时，`Index` 越界。

- 语料：`FRegisterRotator.cpp` 的 `Equals` 名字由 `{"R", "Tolerance"}` 改为 `{"R"}`（**2 形参 / 1 名字**），UBT 重编 `UnrealCSharp` 模块。

> ⇒ 本条不是"生成一个错名字"，而是 **Development 编辑器在生成期直接崩溃**（`TArray::RangeCheck` 的 `checkf`）。B-55 §2.7 的"危险方向现网 0 站点"仍成立，但它成立的原因是**没有站点**，而不是无害。

### 1.3 与原文锚点的关系

原文引用的 5 个索引点（`:95/98/134/137/166`）都在 **subscript** 上，且已被 B-157（`F-GEN-011`）的 `IsSubscriptValid`（`IsSet` ＋ 1 param ＋ 1 paramName ＋ 非空 return）前置挡住 ⇒ **本轮关闭的是"函数形参"这半边**，不是重复修。

## 2. 修法

```diff
-		if (!Function.GetParamNames().IsEmpty())
+		if (Function.GetParamNames().Num() >= Params.Num())
 		{
 			FunctionParamName = Function.GetParamNames();
```

- **为什么改条件而不是逐点守卫**：两个分支从此都满足 `names.Num() >= params.Num()`（if 分支由条件保证，else 分支按 `Params.Num()` 逐个合成）⇒ `:386/:399/:495/:498/:609` **全部**安全，不必在 6 处各加一次 `IsValidIndex`。
- **出口合规**：名字少于形参时整体回落到**既有的"无名字"分支**（合成 `OutValue%d` / `InValue%d`）—— 既有取值、无新增日志/断言/`throw`/公开 API（G7 无触面），符合 Q2「失败收敛到既有取值」。
- **语义边界（如实登记）**：else 分支不生成默认参数 ⇒ 退化函数会**丢掉 `= 默认值`**（与现网"无名字函数"的行为一致）。没有做"部分名字 ＋ 默认值"的混合策略 —— 那会引入新的命名/默认值组合语义，超出本条范围。

## 1. 这一组到底是什么（一句话）

G12 是 **P0-8「注册↔反注册不成对」那套模式在其它入口的扩散面**：P0-8 修的是"委托句柄被丢弃 ⇒ 悬空 `this`"（`FEditorListener` 的 AssetRegistry 族、蓝图工具栏扩展器），G12 是同一模式在**编辑器目录监视、类收集器、跨语言输入绑定、单播委托包装**四处各自重演一遍。

与 P0-8 的差别在于：**只有 `F-ED2-003` 能照抄 P0-8 的"句柄存容器"样板**，其余三处都不是"句柄被丢弃"，而是三类不同病根（注册守卫缺失 / 根集与函数表不成对 / 包装结构无清理点）。

### 3.3 `F-CS2B-018`（动态 `UFunction` 的 `AddToRoot` 不成对）— ✅ 已修（最小口径）

**核查结论：成立；但原文的一处因果需要更正。**
- `BindFunction`（`:286`）在 `AddToRoot()`（`:317`）之后是**唯一**让该函数进根集的点；而 **`RemoveFromRoot()` 只出现在 `FRegisterClass::RemoveFunctionImplementation`**（由 C# 的 `Class.RemoveFunction` 触发）⇒ 正常"绑定后不解绑"的用法下，每个输入回调的 `UFunction` **永久 rooted**，并把所属 `UClass` 一起拖住（`FunctionMap` + `Class->Children` 链表）⇒ 跨 PIE 累积。
- ⚠️ **更正（本轮实测引擎源码）**：原文 §问题 1 说"下一次输入事件到来时 UE 按名字查找该 UFunction → 找不到 → Debug 下断言崩溃"。**该因果不成立** —— `BindToInputComponent` 在**绑定时**就把函数解析成了函数指针（`InputActionDelegateBinding.cpp:24` 的 `AB.ActionDelegateDelegate.BindDelegate(ObjectToBindTo, FunctionNameToBind)`），事件触发路径**不再按名字查找**；而 `RemoveFunctionFromFunctionMap` 只摘函数表，**不动 `Class->Children` 链表**（`UClass::FindFunctionByName` 会沿 `Children` 找），故"按名查找失败"在正常绑定流程里不可达。**真正可达的后果是泄漏 + 根集累积**（原文 §问题 2/5 那部分成立）。

**改法（`FRegisterInputComponent.cpp:294-299`；`+3/−1`）**
```cpp

			{
```

## 7. 复用价值（给下一轮）

- **同一条编号在不同报告里行号可信度不同**：`06-…/02b`（C# 侧）零漂移、`01`/`04`（C++ 侧）漂移 2~14 行 ⇒ 引用行号前**先按函数名定位**。
- **"句柄存容器 vs `RemoveAll`"的判据是 API 给不给句柄**，不是风格：`IDirectoryWatcher` 给 ⇒ 容器；`FAssetEditorExtender`（lambda）不给 ⇒ `IsBoundToObject` 过滤。
- **"守卫 vs 容器"的判据是病根类型**：`FClassCollector` 的病根是"同一成员被反复覆盖"⇒ 守卫；`FEditorListener` 的病根是"N 个注册共用一个成员"⇒ 逐项容器。
- 🪤 **本轮踩到的构建坑（会再遇到）**：UBT 按**时间戳**判定 `.obj` 是否最新 —— 若"删符号"与"重新编译"落在同一分钟，源码 mtime 可能不晚于 `.obj` ⇒ **链接复用旧 `.obj`、报 `LNK2001` 幽灵符号**。处置：直接删 `Plugins/UnrealCSharp/Intermediate/Build/Win64/x64/UnrealEditor/Development/<Module>/Module.<Module>.cpp.{obj,dep.json,sarif}` 再编（`-Rebuild` 过重）。
- 🪤 **同一天踩到的第二个"产物新鲜度"坑（更隐蔽）**：**`UnrealCSharpEditor.dll` 与 `UnrealCSharp.dll` 是两次独立的编译+链接动作** ⇒ 只重编编辑器模块时，`Source/UnrealCSharp/**` 的改动**不会**进被测二进制。**收尾自检**：跑测前比对**所有受影响模块**的 `.dll` 时间戳必须晚于最后一次源码改动（本轮首轮终态就是这么被抓出来的）。
- 📐 **形态口径（维护者 2026-09-25 四条，本仓通用）**：① **`if` 判定一律"正向条件包裹 + 末尾默认返回"**，不用早退 `if (X) { return; }` 做单调守卫（§3.1 已按此改写；`if (const auto Module = …)`、`FRegisterInputClass` 的 `if (Found == nullptr) { return; }` 这类**原文既有**写法保持不动）；② **容器判空用 `IsEmpty()`**，不用 `Num() > 0`（§3.2 已按此改写）；③ **`TMap` 遍历用结构化绑定**（`for (const auto& [Key, Value] : Map)`），不用的分量写 `PLACEHOLDER`（本仓既有 46 处先例，§3.2 已按此改写）；④ **委托句柄局部量带 `On` 前缀**（与注册 API 的形参名、本仓 `On*DelegateHandle` 成员同名同形；注册侧与反注册侧用**同一个名字** ⇒ 左右对称可读）。
- **探针写法**：`UE_LOG(LogTemp, Display, …)` 即可（`-LogCmds="LogUnrealCSharp Verbose"` 不影响其它 category），收尾用 `grep` 三连确认零残留。

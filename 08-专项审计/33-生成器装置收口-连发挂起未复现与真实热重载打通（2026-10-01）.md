# 生成器装置收口：`UnrealCSharp.Editor.Generator` 连发多趟「卡死」未复现 + 真实热重载打通（2026-10-01）

> **轮次**：2026-10-01「生成器装置收口」轮。
> **快照与基线**：插件 **`16f87940`**（父 `152b5681`，`F-CS2B-035` 收口提交）的**工作区**；工程侧 HEAD `98e6fb2`。**本轮不改任何插件/工程源码**，只新增装置脚本与日志。

### 1.2 原记录为什么看起来像"挂起"（两条已定位的装置缺陷）

| # | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| 1 | **探针计数读错文件** | `pie_driver_g4multi.py:49-55` 的 `probe_count()` 读 `LOG_EDITOR = KIT_LOG = Saved/Logs/G4Multipass.log` —— 那是**驱动自己写的 kit log**，里面永远不会有 `[G4PROBE]` ⇒ 恒返回 0 | `wait` 阶段只能靠 90 s 超时推进；记录里 `probe lines=0` 出现了 4 次即此 |

⇒ 这三条**不构成"挂起"的根因**（它们只解释"看起来像挂起"与"证据缺失"），但都是装置必须修掉的缺陷。

### 1.3 真正卡住"真实热重载"的东西：`F-BLD-023`

`G4HR2`（touch **普通**测试文件）暴露了引擎侧的真话：

```
[2026.10.01-13.02.07:155][ 80]LogUnrealCSharp: Error:   Determining projects to restore...
  All projects are up-to-date for restore.
  SourceGenerator -> ...\Script\SourceGenerator\bin\Debug\netstandard2.0\SourceGenerator.dll
  Weavers -> ...\Script\Weavers\bin\Debug\netstandard2.0\Weavers.dll
CSC : error CS2012: Cannot open '...\Script\UE\obj\Debug\net10.0\UE.dll' for writing
      -- The process cannot access the file '...\UE.dll' because it is being used by another
         process.; file may be locked by '.NET Host' (27412) [..\Script\UE\UE.csproj]

Build FAILED.
    0 Warning(s)
    1 Error(s)
Time Elapsed 00:00:14.95
```

- **两趟都是这条失败**（生成趟 `13:02:07`、重载编译趟 `13:03:46`），而**驱动的计时完全正常**（生成趟 18.4 s、编译趟 12.1 s）⇒ 我最初把"计时正常 + `Game.dll` mtime 前进"读成了"热重载发生了"，**那是错的**：`Game.dll` 的 20:57:32 是**上一趟会话**留下的。

- 🔴 **失败不可见**：错误只落在 `LogUnrealCSharp: Error:`（无对话框、无中断），编辑器继续跑 ⇒ 从外部看是"生成成功、程序集没变"。

## 2. 标准装置（本轮交付）

| 文件 | 作用 |
|---|---|
| `Saved/Retest/pie_driver_g4hotreload.py` | 会话内状态机：**T0 快照 → 全量生成 → T1 快照 → touch 动态类 → `build-server shutdown` → `UnrealCSharp.Editor.Compile` → T2 快照 → 退出**；每步落 kit log + `LogPython`；状态**先推进后发命令**（重入守卫）；两处释放 MSBuild 节点 |
| `Saved/Retest/run-g4-hotreload.ps1` | 启动器 + 轮询 + 收尾：进程守卫按**完整 `.uproject`** 判；**不传 `-log=`**（保留默认引擎日志）；跑完归档 `editor.log` / `editor-stdout.txt` / 计数标记 |
| `Saved/Retest/pie_driver_g4diag.py` + `run-generator-hang-diag.ps1` | 挂起诊断版（纯计时 + 心跳 + 硬停），用于"是否挂起"这类判定 |

**关键设计（都可复核）**

1. **touch 的必须是动态类文件**：`UnrealCSharp.Editor.Compile` 走 `FCSharpCompiler::Compile` ⇒ `Compile(..., bReloadImmediately=false)`，而 `CompileInternal` 的重载条件 `bReloadImmediately || bHasDynamicFileChanged`（`FCSharpCompilerRunnable.cpp:494`）+ `HasDynamicFileChanged → IsDynamicFile(Data.Filename)`（`FDynamicGenerator.cpp:198-257`，判据是 `CodeAnalysisDynamicFilesMap` 的路径匹配）⇒ **touch 普通文件不会重载域**（`G4HR1` 实测：touched 一个测试文件，编译成功但**没有**重载）。
2. **两处 `dotnet build-server shutdown`**：`startup`（清掉上一次遗留的节点）与 `before-reload`（清掉生成趟留下的节点）。命令由驱动通过 `subprocess.run(["dotnet","build-server","shutdown"])` 发出，两处 `rc=0`。
3. **判据只用产物侧可观测**：`Content/Script/Game.dll` 的 (size, mtime) 快照。**不要用 `Script/Script.sln` 的 mtime** —— `CopyTemplate` 对 `.sln` 是"内容相同即不写"⇒ 三趟快照里它**一直没变**（本轮实测：`3534@1788411488.990` 恒定）。

## 4. 新发现：`F-BLD-023`（MSBuild 复用节点锁 ⇒ C# 编译失败不可见）

### [F-BLD-023] MSBuild 复用节点锁住 `obj/**.dll` ⇒ 插件侧 C# 编译失败，且失败**不可见**

- **类别**: Bug / 构建
- **严重度**: **P1**（功能错误：修复轮次的"程序集已更新"判据会假阳性；且它使**每一轮**的编译验证都可能静默失效）
- **文件**: `Source/Compiler/Private/FCSharpCompilerRunnable.cpp:407-421`（`CompileGame` 拼 `dotnet build "<proj>" --nologo -c <cfg>`）
- **置信度**: **高**（本轮两次实测 + 引擎日志逐字）

**现状（代码事实）**

```cpp
// FCSharpCompilerRunnable.cpp:416-421
const auto CompileParam = FString::Printf(TEXT("build \"%s\" --nologo -c %s"),
    *FUnrealCSharpFunctionLibrary::GetGameProjectPath(), *GetBuildConfiguration());
```

⇒ 参数里**没有** `-nodeReuse:false` / `-p:UseSharedCompilation=false`，也没有在编译前后关闭 build server。

**实测（本轮，`G4HR2`）**：同一会话两次 `dotnet build` 都以

```
CSC : error CS2012: Cannot open '...\Script\UE\obj\Debug\net10.0\UE.dll' for writing
-- file may be locked by '.NET Host' (27412)   →   Build FAILED.  (0 Warning / 1 Error)
```

结束；而**驱动的计时、`console returned`、会话退出全部正常** ⇒ 外部**看不到**失败。对照组（`G4HR3`，两处 `dotnet build-server shutdown` 后）同一装置同一时刻 **`CS2012 = 0 / Build FAILED = 0`**，`Game.dll` 两次前进。

**为什么这是问题（触发路径）**

1. 任一入口成功编译过一次（启动期 `SyncCompile`、`ImmediatelyCompile`、异步 `DoWork`）⇒ 留下 MSBuild 复用节点；
2. 之后任何一次 `CompileGame` 都连到同一节点 ⇒ 上一次的输出 `obj/**/UE.dll` 仍被它持有；
3. 编译失败 ⇒ 程序集**没重建**，但**没有可见反馈**（无对话框、`-game` 下也无 CSV 异常）；
4. ⇒ 依赖"改完代码跑一遍套件"的验证，会拿到**旧程序集**的结果（**假绿/假红**）。

**建议（未施工，属裁定项）**：① `CompileParam` 追加 `-nodeReuse:false`（最小、直击；代价是每次编译多起一个节点）；② 编译前后各调一次 `dotnet build-server shutdown`（本轮装置用的就是这个，实测有效）；③ 把失败**可见化**（弹通知/非零返回向上传）—— 与库内"不加日志/不抛异常"口径冲突，需你先拍板。

**验证方式**：跑 `run-g4-hotreload.ps1`，判据 = `Game.dll` 两次时间戳前进 + 引擎日志 `CS2012`/`Build FAILED` 均为 0。

## 6. 复用价值（给下一轮）

1. 🟢 **"命令返回" ≠ "编译成功"** —— 本轮最大的教训。插件把 `dotnet build` 的输出经 `LogUnrealCSharp: Error:` 打印，**失败不改变控制流**；任何"改完代码跑套件"的验证都必须**同时**看引擎日志的 `Build FAILED`/`CS2012` **与**产物 mtime。
2. 🟢 **C# 编译是"生成趟"的可靠产物判据**：`Generator()` 的第 12 帧就是 `ImmediatelyCompile` ⇒ 每趟必重建 `Content/Script/Game.dll`（走 `Game.props` 的 `CopyDllsAfterPublish`）。**判据取 (size, mtime) 快照**，不要取 `.sln`（内容相同即不写，本轮三趟恒定）。
3. 🟢 **`build-server shutdown` 是 MSBuild 锁的通用解**（本轮两处 `rc=0`，锁消失）；而 **UBT 侧**同样问题已有先例（第 29 轮：`CS2012` 两次、靠 `dotnet build-server shutdown` / `-nodeReuse:false` 解）。
4. 🟢 **"真实热重载"的入口判据 = `IsDynamicFile()`**：`UnrealCSharp.Editor.Compile` 的 `bReloadImmediately=false` ⇒ 只有**动态类文件**变化才会走 `Deactivate → 生成 → Activate`；touch 普通文件只编译、不重载（本轮 `G4HR1` 实测）。
5. 🪤 **`-log="<abs path>"` 会吞掉引擎日志**：本轮实测该文件 0 B 且默认日志不再产生备份 ⇒ 装置**不要**改日志路径；要单独留档就在跑完后 `Copy-Item`。
6. 🪤 **探针计数必须指向引擎日志**：`G4Multipass` 的 `probe_count()` 读的是驱动自己的 kit log ⇒ 恒 0，把"没有观测面"伪装成"没有进展"。
7. 🟢 **心跳是"挂起 vs 慢"的第一判据**：本轮在 `wait` 阶段每 20 s 打一条心跳，据此把"命令挂起"（心跳全停）与"命令很慢"（心跳照走）分开 —— 后者才是本轮的真实形态。

## 1. 改了什么

两处 GT 同步编译改成"投递到 `CSharpCompiler` 线程"，**沿用 B-181/B-184 已对另外 3 个调用点用过的同一形态**（`FCSharpCompiler::Get().EnqueueTask([](){ …原同步调用… });`）：

```cpp
// UnrealCSharpEditor.cpp:123-135（控制台命令 UnrealCSharp.Editor.Compile）
-				FCSharpCompiler::Get().Compile([]()
+				FCSharpCompiler::Get().EnqueueTask([]()
 				{
+					FCSharpCompiler::Get().Compile([]()
+					{
+					});
 				});
```

```cpp
// DynamicDataSource.cpp:38-60（撤销/重做"删除动态类文件"事务的 Apply / Revert）
-		FCSharpCompiler::Get().ImmediatelyCompile();
+		FCSharpCompiler::Get().EnqueueTask([]()
+		{
+			FCSharpCompiler::Get().ImmediatelyCompile();
+		});
```

**为什么是这两处**：`F-CMP-005` 的原文是「控制台命令 / 右键菜单」。逐条核对当前 HEAD 后，**用户可触发的 GT 同步编译入口只剩这两个** —— 控制台命令，以及撤销/重做（`FDeleteFileChange::Apply/Revert`，即"右键删除动态类文件后 Ctrl+Z"）。菜单/工具栏的其余编译入口（Blueprint 工具栏的 CodeAnalysis）**早已是 `EnqueueTask`**。

**没改的**（如实登记）：`StartupModule` 的 `SyncCompile()`（`:59`）与 `OnPostEngineInit` 的 `ImmediatelyCompile()`（`:283`）仍同步 —— 那是**启动期一次性**阻塞（此时编辑器还没进入可交互状态），且 `SyncCompile` 是另一个 API；本轮不动，避免把"启动必须等编译完"的语义改掉。

# 轮 B-46 探针：选项 B（`GC.TryStartNoGCRegion` 包住 compound 批量＋物化）—— **正确但不稳定，不交付**

> **来源**：维护者指定"**B 吧**"（B-44/87 的选项 B）。**做法**：native 批量返回 weak 句柄；C# 在一个 no-GC 区里完成"批量调用 ＋ 把句柄物化成 `T[]`/`KeyValuePair[]`"，区外再 `yield`。**结论**：🟨 **技术可行（5 次运行套件全绿、数值全对）**，但 **性能不稳定且多次退化**（`TArray<FString>` 59–269 ms vs 逐元素 107 ms；`TMap<FString,FString>` 161–560 ms vs 258 ms）⇒ **不交付，已回滚**（插件仍 `87dac201`，0 提交）。

## 1. 实现要点（若将来重启 B）

```csharp
private static T[] FillObjects(nint InHandle, int InIndex, int InCount, byte[] InBuffer, int InElementSize)
{
    if (GCSettings.LatencyMode == GCLatencyMode.NoGCRegion || !GC.TryStartNoGCRegion(4 << 20))
    {
        return null;                       // 区不可用 ⇒ 调用方回退逐元素
    }

    try
    {
        var Count = GetElements(InHandle, InIndex, InCount, InBuffer);   // native 批量
        var Objects = new T[Count];                                   // 区内物化
        for (var Entry = 0; Entry < Count; Entry++)
        {
            var ManagedHandle = Unsafe.ReadUnaligned<nint>(ref InBuffer[Entry * InElementSize]);
            Objects[Entry] = ManagedHandle != 0 ? (T)HandleData.GetObject(ManagedHandle) : default;
        }
        return Objects;
    }
    finally
    {
        if (GCSettings.LatencyMode == GCLatencyMode.NoGCRegion) { GC.EndNoGCRegion(); }
    }
}
```

- 关键约束：**`yield` 不能在区内**（否则用户代码任意分配会耗尽预算），所以每块先物化成数组，区外再 `yield`；
- 物化数组本身是强引用 ⇒ 区结束后 wrapper 由数组保活，直到迭代器越过该块；
- `GCLatencyMode` 守卫同时用于"防嵌套启动"和"防 `EndNoGCRegion` 抛异常（预算耗尽时区已自动结束）"。

## 3. 结论

1. **B 的正确性成立**（5/5 套件同 SHA、sum 全对），但 **性能不可交付**：最好一次 −40%，最差一次 **+151%**（269 vs 107）。
2. 换 chunk/预算没有稳定甜点：小 chunk 区调用多、大 chunk 预算大；256 KB 直接被耗尽（B-44 的 weak 问题以另一种形式回来）。
3. ⇒ **compound 维持逐元素（C）**；`F-PERF-025` 的 compound 部分按"**按设计不批量**"收口。

## 5. 复用价值

1. **"正确"不等于"可交付"**：B 的 5 次运行全绿，但性能中位数退化 —— 优化项的交付判据必须包含**多次运行的分布**，而不能只看最好一次。
2. **`TryStartNoGCRegion` 有真实代价**：它会触发/等待 GC 并预留预算；按 chunk 调用时，区启动成本会吃掉 P/Invoke 收益。
3. **预算与 chunk 强耦合**：chunk 越大，区内容易超预算（weak wrapper 被回收 ⇒ 崩溃或空值）；chunk 越小，区启动越频繁。256 KB/1024 的崩溃就是这条边界的实测。

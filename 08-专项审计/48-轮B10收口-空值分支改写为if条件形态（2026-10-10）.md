```cpp
// 改写后（正条件 + 单一出口）
	static auto Get(std::decay_t<T>* InMember, const IManagedHandle InManagedHandle)
	{
		auto SrcManagedHandle = InvalidManagedHandle;

		if (InMember != nullptr && !IsNull(*InMember))
		{
			SrcManagedHandle = FCSharpEnvironment::GetEnvironment().GetMultiObject<std::decay_t<T>>(InMember);

			if (!IManagedHandleIsValid(SrcManagedHandle))
			{
				if (const auto FoundClass = TPropertyClass<T, T>::Get())
				{
					SrcManagedHandle = FoundClass->NewObject(true);

					FCSharpEnvironment::GetEnvironment().AddMultiReference<std::decay_t<T>, false, true>(
						FoundClass, SrcManagedHandle, InMember);
				}
			}
		}

		return IManagedHandleToObject(SrcManagedHandle);
	}
```

## 2. 为什么这是等价的（逐分支核对）

| 场景 | 改写前 | 改写后 |
|---|---|---|
| 空值（或 `InMember == nullptr`） | 提前 `return IManagedHandleToObject(InvalidManagedHandle)` ⇒ `nullptr`；描述符侧写 `InvalidManagedHandle` | `SrcManagedHandle`/`Object` 初值即 `InvalidManagedHandle`，`if` 分支不进入 ⇒ 末尾 `return`/写回同一值 ✓ |
| 非空 | 解析 → （无效则按 `Class != nullptr` 新建包装并登记） → 返回/写回 | 同一顺序、同一条件嵌套 ✓ |
| 新增分支 | —— | **无**（本轮的 `git diff` 中新增的 `return;` 语句 = **0**，新增的条件全部是原条件的**取反**） |

## 5. 复用价值

1. **"库内既有写法"就是规范**：这两处我按通用 C++ 习惯写了守卫（提前 `return`），而本仓库的既有形态是"**先给默认值 → 正条件包住原逻辑 → 末尾单一出口/写回**"（`F*PropertyDescriptor::Get` 一族 8 个文件都是这个形状）⇒ **改前应先读同族 2–3 个文件的写法再动笔**。
2. **形态类返工也要走完整验证**：即使是"等价改写"，仍跑了 **3 次构建 + 4 次套件**（CoreCLR ×2、Mono ×1、恢复态 ×1），并保留"与上一交付逐行 0 差异"作为等价性判据 —— 这比"看起来一样"更能兜住手误。
3. **等价性可判据化**：`git diff` 中`^\+\s*return;` 计数 = 0 ＋ 套件逐行 0 差异，两条合起来足以支撑"语义等价"的结论。

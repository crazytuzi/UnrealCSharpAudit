## 1. 逐条复验

### 1.1 `F-CS4-004`（2.88）—— 已由 B-33 v3 判"空块即正确"，建议归档

- B-33 v3 的结论（[`08-…/74`](74-轮B-33收口-死代码批次C补实现（2026-10-16）.md) §3.2/§10）：`[Localized]` 在 UHT 侧自 5.4 起只 `LogError("deprecated")`、**不写任何 flag/metadata**；`[FieldNotify]` 只置 UHT 导出标志、由 UHT 代码生成产出描述符、运行时无 flag 可置 ⇒ **三处空块保留/恢复为空块是正确的**；`[SealedEvent]`（唯一"引擎有实体语义"的一处）已实装。
- 10-08 复审的"未修"**已过期**：它不是"没做"，而是"没有可做的存储位"。
- **建议**：按 `F-GEN-016`/`F-PERF-019` 先例归档"**不适用（已有裁定）**"，保留编号与全部事实，**不写"已修"**。

### 1.2 `F-REG2-007`（2.84）—— 事实成立、可达性降级为潜伏

- `FCSharpEnvironment::Initialize()`（`FCSharpEnvironment.cpp:63-93`）无条件 `new` 14 个对象/注册表，并注册 2 个编辑器 delegate（`:95-110`）——**没有幂等守卫**。
- 但调用链只有 `FUnrealCSharpCoreModule::Activate()`（`UnrealCSharpCore.cpp:19-27`），且 `if (State == EState::Inactive)` 才广播 Active；`Deactivate()` 才广播 InActive（`:29-37`）⇒ 同一状态机内**不会**重复初始化。
- **判定**：机制成立、**可达性 = 潜伏**（仅在直接调用 `FCSharpEnvironment::Initialize()` 的误用路径上）。**暂缓**：修法 = 私有 `bIsInitialized` 守卫（不新增公开 API），但无可达判据；除非构造"直接双重初始化"的探针，否则收益只是防御性。

### 1.3 `F-LEAK-010`（2.84）—— 🟢 立项 ①：hostfxr 句柄与 close 的收口

- `FCoreCLRDomain::Initialize()`：`HostFxrDllHandle = FPlatformProcess::GetDllHandle(...)`（`:44`），此后有 **4 处早退**（`:46-49` / `:72-75` / `:99-104` / `:108-113`）—— 后三处已持有 `HostFxrDllHandle`（可能还有 `HostFxrHandle`）。
- **全插件 0 处 `FPlatformProcess::FreeDllHandle`**（grep 实证）⇒ 句柄**永不释放**；`hostfxr_close` 只在 `Deinitialize()`（`:158-167`），而 `Deinitialize()` 首行 `if (!bIsInitialized) return;`（`:136-140`）⇒ **失败态/早退态永远不会 close**。
- **修法**：把"关停"从 `bIsInitialized` 闸里拿出来 —— `HostFxrHandle != nullptr` 就 close、`HostFxrDllHandle != nullptr` 就 `FreeDllHandle` 并置空（`Deinitialize` 首行早退改成按句柄判空）；`Initialize` 的早退路径可交给 `Deinitialize` 统一收，不新增日志/异常。
- **判据**：临时探针打印 `HostFxrHandle`/`HostFxrDllHandle`（1）正常 initialize→deinitialize 后两者为 **nullptr**（改前：dll 句柄非空）；（2）构造一次 `Init` 早退（例：把发布目录移走 ⇒ `UE.dll`/`Game.dll` 缺失 ⇒ `IsAssembliesFileExists` 为假）→ `Deinitialize` 后两者仍为 **nullptr**（改前：非空）；套件 **1 963 / 0** 同 SHA。

### 1.4 `F-LEAK-015`（2.80）—— 🟢 立项 ①：`CrcCompiledSignatures` 只增不减

- `FEditorListener.h:98`：`TMap<FSoftObjectPath, uint32> CrcCompiledSignatures;`
- 写入 3 处（`FEditorListener.cpp:319` / `:516` / `:529`），全文件**没有** `Remove`/`Empty`（`:125` 的 `Empty()` 是 `OnDirectoryChangedDelegateHandles`，不是它）。
- 键是 Blueprint 的 `FSoftObjectPath`；**删除/改名后旧键永留**（会话内只增）；与 `F-REFL-003`/`F-REGR-*` 的 "只增不减" 同类，但**这里是编辑器监听器自己的缓存**、有现成钩子。
- **修法**：在已有 `OnAssetRemoved`（`:378`）里 `CrcCompiledSignatures.Remove(InAssetData.GetSoftObjectPath())`，`OnAssetRenamed`（`:390`）里 remove 旧路径（`FSoftObjectPath(InOldObjectPath)`）；`OnCompile` 写入处不变。
- **判据**：探针读 `Num()`（1）连续"添加 N 个 Blueprint→编译→删除"后 map 条目数不增（改前 +N，改后 0）；（2）改名后旧键消失、新键在；（3）套件 **1 963 / 0** 同 SHA（编辑器侧判据用 B-24 的资产事件装置）。

### 1.5 `F-GEN2-012`（2.80）—— 🟢 立项 ②：静态生成器不输出 `[Flags]`

- `FEnumGenerator::Generator` 的输出模板（`FEnumGenerator.cpp:98-117`）只有：头注释、`using` 列表、`namespace`、`[PathName]`、`public enum X : 底层类型` —— **无 `[Flags]` 槽位**；`UsingNameSpaces` 只塞 `Script.CoreUObject`（`:60`），也不含 `System`。
- 产物扫描：**本轮复跑** `Script/UE/Proxy`（**16 155** 个 `.cs`）与 `Script/Game/Proxy` 的 `\[Flags\]` = **0 命中**；`EObjectFlags` 这类位标志枚举生成的是 `public enum EObjectFlags : int`（`Script/UE/Proxy/Binding/EObjectFlags.cs:8`）——`|`/`&` 仍可做，但 `ToString()` 输出数字而非组合名、`HasFlag` 无语义表达。
- **修法（静态路径）**：`FEnumGenerator` 读 `InEnum->HasMetaData(TEXT("Bitflags"))`（或 `GetBoolMetaDataHierarchical`），命中则（a）`UsingNameSpaces.Add(TEXT("System"))`；（b）模板里 `[PathName]` 前插一行 `[Flags]`。**`FBindingEnumGenerator`（`EObjectFlags` 走这条）不在本轮**：它需要给 `FBindingEnum` 加字段/宏，属协议面，登记为后续。
- **判据**：新增一个项目侧 `UENUM(meta=(Bitflags))` 测试枚举 → 生成产物含 `[Flags]` 且 `using System;`；C# 侧 `(A|B).ToString()` 输出 `"A, B"`（改前输出数字）；既有 16 230 产物除该枚举外 **0 差异**；套件 **1 963 / 0** 同 SHA。
- ✅ **前置已核（2026-10-21 补）**：`Bitflags` 是引擎注册的**枚举元数据键** —— `Engine/Source/Runtime/CoreUObject/Public/UObject/ObjectMacros.h` 的 `EEnumMetadata` 表在 **5.0.0 / 5.6.0 / 5.8.3** 三个 tag 上逐条相同（`/// Metadata that identifies an enum as a set of explicitly-named bitflags` ⇒ `Bitflags`，行号 1577 / 1744 / 1818）⇒ `UENUM(meta=(Bitflags))` 合法；但**引擎现有 UENUM 0 个使用它**（`Engine/Source` 全树 `meta=(Bitflags)` = 0 命中）⇒ 判据必须**自建测试枚举**，不能指望既有语料。

### 1.6 `F-CMP-019`（2.80）—— 🟡 候补 ③：`SourceCodeGenerator` 的字典索引器与绝对路径

- `SourceCodeGenerator.cs:775`：`Path.Combine(HeaderPath[classObj.Package.Module.ShortName], classObj.HeaderFile.FilePath)`。
- 两个独立缺陷：① `HeaderPath` 是 `Dictionary<string,string>`（`:59`），模块短名不在表内（例如来自 `Source/` 之外的 header、或插件/引擎模块扫描未覆盖）⇒ `KeyNotFoundException` 让整趟生成中断；② `HeaderFile.FilePath` 若是绝对路径，`Path.Combine` **返回第二参**（吞掉第一参）⇒ 生成绝对 `#include`。
- **修法**：`TryGetValue` 命中才 Combine、否则跳过该文件（既有 `IsSkip` 风格）；`Path.IsPathRooted` 为真时直接用原路径（不拼前缀）。不新增日志。
- **判据**：语料装置（一份 header 属于未扫描模块、一份用绝对路径）→ 改前：进程抛 `KeyNotFoundException` / 产物出现绝对 include；改后：跳过/按原路径、其余产物 0 差异。⚠️ 需要一个可独立跑 `SourceCodeGenerator` 的会话装置（本轮未建）。

### 1.7 `F-CS1-022`（2.80）—— 暂缓：消歧需要类型签名

- `TypeBridge.GetMethod`（`Script/Interop/Bridge/TypeBridge.cs:63-69`）：`foreach Type.GetMethods(...)` 取**第一个** `Name == Name && 参数量 == InParamCount` 的方法；C++ 侧 typedef（`IScriptTypes.h:19`）只传 `(handle, name, count)`，**没有类型信息**。
- 后果：同参数量重载 / 静态与实例同名 / 继承链同名都可能选错，参数按错误类型读取（`MethodBridge` 的 `ReadPrimitiveValue`）⇒ 垃圾值或 `ArgumentException`（被吞）；另无缓存（每次 `GetMethods` + `GetParameters` 分配）。
- **暂缓理由**：真正的消歧要在协议上补"参数类型签名"（跨 C++/C# 的 typedef + 所有调用点），不是一轮；**缓存**可单独做但会固化错误选择。

### 1.8 `F-INT1-013`（2.88）—— 暂缓：无可达窗口

- `FRegisterObject.cpp:56` 的 `IScriptDomain::Get()` 未判空（同目录另有 5 处同型）；`IScriptDomain::Get()` 只在域销毁后为空。
- 与 `F-REG2-006`（关停顺序）同一条时序；**无已证实的"域销毁后仍有 C#→C++ 调用"路径** ⇒ 1 行守卫可做，但判据只能构造。

### 1.9 `F-REG2-006`（2.80）—— 部分成立：移除依赖 InActive 广播，存在关停顺序风险

- `FUObjectListener` 在 `OnUnrealCSharpModuleActive` 里 `AddUObjectCreateListener/DeleteListener`、在 `OnUnrealCSharpModuleInActive` 里移除（`FUObjectListener.cpp:27-39`）；监听器是 `FUnrealCSharpModule` 的**成员**（`UnrealCSharp.h:27`）。
- `FUnrealCSharpModule::ShutdownModule()`（`UnrealCSharp.cpp:19-34`）只摘掉自己挂在 `FUnrealCSharpCoreModuleDelegates` 上的两个 handler；若 core 的 InActive 广播发生在 `ShutdownModule` **之后**，模块已摘 handler ⇒ 收不到 InActive ⇒ GUObjectArray 上留下指向已析构 listener 的指针。
- **判定**：不是"完全不解除"（10-08 原文过强），而是"**移除依赖广播时序**"。**暂缓**：需要"core 先/后 shutdown"的顺序装置才能定论；修法应改为在 `FUObjectListener` 析构里**兜底** `RemoveUObjectCreateListener/DeleteListener`（幂等、不新增 API）—— 可作为将来的小修。

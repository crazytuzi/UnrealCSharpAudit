```cpp
bool FCSharpCompilerRunnable::PublishInterop(const FString& InSourcePath, const FString& InTargetPath,
                                             const FString& InBackupPath)
{
	if (!IFileManager::Get().FileExists(*InSourcePath))
	{
		return false;
	}

	if (IFileManager::Get().FileExists(*InTargetPath))
	{
		if (IFileManager::Get().FileExists(*InBackupPath) ||
			!IFileManager::Get().Move(*InBackupPath, *InTargetPath, false))
		{
			return false;
		}
	}

	return IFileManager::Get().Move(*InTargetPath, *InSourcePath, false);
}
```

### 2.2 三处设计取舍（都基于实测，不基于推测）

| 取舍 | 理由 |
|---|---|
| **不用 `REPLACE_EXISTING` 一步覆盖** | 实测 `MoveFileEx(…, 1)` 对锁定目标返回 **`false` / err 5**（§3.2 探针 4）⇒ 照抄原文建议会**继续失败**；两阶段改名两次都实测成功（探针 5a/5b） |
| **备份文件放 `Intermediate/UnrealCSharp/` 且带时间戳** | ① 已改名但仍被映射的文件**在本会话内删不掉**（探针 6）⇒ 固定名备份会在"同一会话第二次强制发布"时**撞名阻塞**；② 放 `Intermediate/` 而不放 `Content/Script` ⇒ 不污染发布目录、随 Intermediate 清理 |
| **始终重定向构建输出（而非"失败后再补救"）** | 失败后重试要付两次构建代价，且恢复逻辑分支多；恒定路径只有一次重命名开销，且**不依赖锁是否存在**（无锁时 `InTargetPath` 不存在 ⇒ 直接移入） |

## 5. 复用价值（给下一轮）

1. 🟢 **"谁持有这把锁"要用进程内证据说话**：`The file is locked by: "UnrealEditor (50836)"` 一句就把"外部占用"排除为"**编辑器自锁**"——这决定了修法是"避开锁"而不是"等锁释放"。
2. 🟢 **Windows 上"被 CLR 加载的程序集文件"的四条语义**（写 ✗ / 改名 ✓ / `REPLACE_EXISTING` ✗ / 删除 ✗）是**可复用的实测结论**：凡"发布目标同时是加载目录"的构建系统，正确形态都是"**构建到别处 + 两阶段改名**"，不要指望 `MoveFileEx` 一步覆盖。
3. 🟢 **可达性先于修法**：动手前先问"**谁会把这个条件置为真**"（本轮答案：只有 commandlet 的 `-Rebuild`）——它同时决定"要不要修"和"用哪个装置验证"（[`08-…/21`](21-G4剩余条目收口-动态类型静态容器与依赖图（2026-09-29）.md) 的"表 = 复用判据"式提问法的姊妹版）。
4. 🪤 **`execute_console_command` 会重入 tick 回调**：状态机必须**先推进、后发命令**。本轮第一版驱动违反该警戒（命令连发 334 次、域未进入稳态、整套判据失效），库内 [`08-…/08`](08-G5与G6首刀（编译链路并发与关停，2026-09-23）.md) §9 与 [`08-…/21`](21-G4剩余条目收口-动态类型静态容器与依赖图（2026-09-29）.md) 都有记录 —— **写装置前先读库内的装置警戒**。
5. 🟢 **"锁定文件"类缺陷的判据要包含"文件真的被改写吗"**：`MSB3027 = 0` 只说明命令没报错；**mtime + SHA 变化**与**备份文件里是旧内容**才是"发布真的生效"的证据。

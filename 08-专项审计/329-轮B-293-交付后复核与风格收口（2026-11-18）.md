## 7. 命名与"声明/定义顺序"复核（维护者追加要求，2026-11-18）

> 追加要求：**新增函数/变量命名是否一致** ＋ **定义顺序与声明顺序是否一致**。复核对象 = `44fa66d8` / `f11a1072` 引入的 **10 个私有函数 ＋ 2 个成员变量**（`FSetHelper` 5 ＋ 1，`FMapHelper` 5 ＋ 1）。⇒ 抓到 **3 处不一致**，全部由 **`daec330d`**（4 文件 `+105 −105`，纯改名/移动，**0 语义改动**）收口。

### 7.1 N1：`Set` 侧新名内部混用 `Value*` 与 `Element*`（已统一为 `Element*`）

| 项 | 内容 |
|---|---|
| 现象 | 同一次提交新增的 6 个符号里：`ValueBuffer`／`PrepareValueBuffer`／`DestroyValueBuffer` 用 **Value**，而 `GetElementHash`／`IsSameElement`／`GetElementIndex` 用 **Element** |
| 基准 | 该类**既有**命名是 `ElementPropertyDescriptor`／`GetElementPropertyDescriptor()`；"Element" 是 Set 元素的既有名词（C# 侧的 `InValue` 只是入参名） |
| 修法 | `ValueBuffer`→**`ElementBuffer`**、`PrepareValueBuffer`→**`PrepareElementBuffer`**、`DestroyValueBuffer`→**`DestroyElementBuffer`**（`GetElementHash`／`IsSameElement` 不动）⇒ Set 侧 5 个 helper 全部 `Element*` |
| 为何 Map 侧不改 | Map 侧本来就是 `KeyBuffer`／`PrepareKeyBuffer`／`DestroyKeyBuffer`／`GetKeyHash`／`IsSameKey` 五个 `Key*` ＋ `PairIndex` 一个 `Pair*`；"pair" 是 map 的**存储单元**（引擎 `TPair`），语义正确、内部自洽 ⇒ **零改动** |

### 7.2 N2：查找函数用了 `Get*Index`，与兄弟类/引擎的 `Find*` 惯例不一致（已改 `Find*`）

| 项 | 内容 |
|---|---|
| 现象 | 新加的 `GetElementIndex` / `GetPairIndex` 是"**搜索并可能返回 `INDEX_NONE`**"的查找函数 |
| 基准 | 兄弟类 `FArrayHelper` 的同族函数叫 **`Find` / `FindLast`**（`int32 Find(const void* InValue)`、`int32 FindLast(...)`）；`FMapHelper` 自身已有 `Find`／`FindKey`；引擎侧同功能叫 **`FindIndex`（Set）／`FindPairIndex`（Map）** |
| 修法 | `GetElementIndex`→**`FindElementIndex`**、`GetPairIndex`→**`FindPairIndex`**（后者与它内部调用的 `ScriptMap->FindPairIndex` 同名同义，属"包装同名"惯例） |

### 7.3 N3：声明顺序 ≠ 定义顺序（已把私有块移到文件末尾）

| 项 | 内容 |

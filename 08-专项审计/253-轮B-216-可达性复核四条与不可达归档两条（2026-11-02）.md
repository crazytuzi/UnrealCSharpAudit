## 2. 逐条证据

### 2.1 `F-ENV-009`（`Initialize()` 二次调用泄漏 13 对象）—— 确认不可达

```
EState State = EState::Inactive;                                  // UnrealCSharpCore.h:45（初值）
void FUnrealCSharpCoreModule::Activate()
{
    if (State == EState::Inactive) { State = EState::Active; …Broadcast(); }   // 只有 Inactive→Active 才广播
}
```

- `FCSharpEnvironment::Initialize()`（`FCSharpEnvironment.cpp:70`）**没有**重入守卫，二次调用确实会 `new` 出第二份 `FDomain`/注册表；
- 但它的调用者只有 `OnUnrealCSharpCoreModuleActive()`（`:368`），后者只由上面那次**状态迁移广播**触发；
- `Activate()` 的 4 个调用点（`FCSharpCompilerRunnable.cpp:669`、`FEngineListener.cpp:70/111`、`UnrealCSharpEditor.cpp:153`）全部经过同一状态机；
- **成对性**：`FCSharpCompilerRunnable.cpp` 的 Reload 走 `Deactivate()` → `Activate()`（成对）；控制台 `SetActive 1` 连发两次，第二次因 `State == Active` 不广播。
- ⇒ 没有"两次 Initialize 之间不 Deinitialize"的路径 ⇒ **不可达确认**。

### 2.2 `F-CMP-016`（`DOTNET8`/`!DOTNET9` 死分支）—— 确认不可达，且原判低估了范围

- 插件里 `DOTNET8`/`DOTNET9` 的**全部**使用只有 3 处，且都在 `FMonoDomain.cpp`：`:67`、`:76`、`:83`；
- 该文件 `:2` 是 `#if WITH_MONO`，本机 `Definitions.UnrealCSharpCore.h` 实测 `WITH_MONO 0` ⇒ 三处**全不参与编译**；
- 宏本身：`DotnetVersion.h` 的 `DOTNET8 = VERSION_START(8,0,0)` 在 `DOTNET_MAJOR_VERSION=10` 下为**真**，所以"死分支"的成因不是宏恒假，而是**整段代码被 `WITH_MONO` 编译掉**。
- ⇒ **不可达确认**（在 CoreCLR/LeanCLR 配置下）；若将来编 Mono 后端，则按 `DOTNET_*` 的实际值重新评估。

### 2.3 `F-CMP-018`（空 `ExportModule` ⇒ 全部跳过）—— 不可达标注被推翻

```csharp
var ExportModule = new List<string>();                       // :111，默认空
…
if (SettingConfigHierarchySection.TryGetValues("ExportModule", out var Values)) { … }   // :123，ini 没有该键则保持空
…
foreach (var module in Session.Modules)
{
    if (module.Module.ModuleType != EngineRuntime && != GameRuntime) continue;
    if (ExportModule.All(x => string.Compare(x, module.Module.Name, OrdinalIgnoreCase) != 0))
        continue;                                            // :155 空列表 ⇒ All 恒真 ⇒ 全跳过
    QueueClassExports(module.ScriptPackage, tasks);
}
```

- **默认配置即命中**：`Config/DefaultUnrealCSharpEditorSetting.ini` 在**工程与插件两侧都不存在**（工程只有 `DefaultUnrealCSharpSetting.ini`）⇒ `ExportModule` 为空 ⇒ 所有模块被 `continue`；
- 另发现一处**同类不一致**：该 C# 路径**完全不读 `bEnableExport`**（`:113-143` 只读 `ExportModule`/`ClassBlacklist`），而编辑器侧 `ExportModule` 的 `UPROPERTY` 带 `EditCondition = "bEnableExport"` ⇒ 编辑器里那个开关对 UBT 插件这条路径无效。
- **未验证的部分（如实登记）**：`SourceCodeGenerator` 是 `Type: Program` 的 UBT 插件模块（`UnrealCSharp.uplugin` 里仍在列），**本轮没有验证 UBT 是否会执行它**；本工程 16 155/76 份产物来自**编辑器**生成器，不是这条路径。⇒ 结论定为「**可达性未经证实的"潜伏"**，触发条件 = 走 UBT `SourceCodeGenerator` 路径且未配置 `ExportModule`」，**不归档**。

### 2.4 `F-CMP-014`（`DotnetVersion` 可选 V8/V9 生成 net8/net9）—— 不可达标注被推翻

```cpp
// UnrealCSharpSetting.h:186-191
UENUM(BlueprintType) enum EDotnetVersion { V8 = 8, V9 = 9, V10 = 10, Latest };

UPROPERTY(Config, EditAnywhere, Category = Solution)
TEnumAsByte<EDotnetVersion> DotnetVersion;
```

```cpp
// FSolutionGenerator.cpp:285-295
OutResult = OutResult.Replace(TEXT("<TargetFramework></TargetFramework>"),
    *FString::Printf(TEXT("<TargetFramework>net%d.%d</TargetFramework>"),
                     FUnrealCSharpFunctionLibrary::GetDotnetVersion(), DOTNET_MINOR_VERSION));
```

- `DotnetVersion` 是 `EditAnywhere` ⇒ **用户可以在项目设置里选**；`GetDotnetVersion()`（`FUnrealCSharpFunctionLibrary.cpp:1530`）把它传给 `ReplaceTargetFramework` ⇒ 选 `V8` 就生成 `<TargetFramework>net8.0</TargetFramework>`；
- 本机默认 `Latest`（→ 10）⇒ 生成 `net10.0`，与现有产物一致；
- ⇒ 这是**配置可达**的路径，不是"不可达"。**不归档**，改判「潜伏 · 触发条件 = 用户实际选择 V8/V9」，仍留在 C 组（暂缓）。

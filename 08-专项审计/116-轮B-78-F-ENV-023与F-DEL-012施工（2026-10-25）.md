## 1. `F-ENV-023`：root 归属的单向性（新登记）

### 1.2 HEAD 事实（`987be131`）

两条路径同形（`BindFunction`，创建 `FUNC_BlueprintEvent` 的动态 `UFunction`）：

| 文件:行 | 内容 |
|---|---|
| `FRegisterInputComponent.cpp:594-599` | 早退分支 `FoundFunction->RemoveFromRoot(); return;` |
| `FRegisterEnhancedInputComponent.cpp:76-81` | 同上 |
| `FRegisterInputComponent.cpp:601-621` | 新建路径：`NewObject<UFunction>` → `Bind()` → `StaticLink(true)` → `AddFunctionToFunctionMap` → 接入 `Children` → 注册 descriptor，**无 `AddToRoot`** |
| `FRegisterEnhancedInputComponent.cpp:83-103` | 同上 |
| `FCSharpBind.cpp:782-785` | 全插件唯一的条件 root：`if (InClass->HasAnyInternalFlags(RootSet) \|\| GUObjectArray.IsDisregardForGC(InClass)) NewFunction->AddToRoot();` |

### 1.3 「早退分支不该 unroot」的证据链（引擎源码）

1. `UClass::FuncMap` 是 `TMap<FName, TObjectPtr<UFunction>>`（`Class.h:3164`）、`UStruct::Children` 是 `TObjectPtr<UField>`（`:412`）、`UField::Next` 是裸 `UField*`（`:159`）—— **三者都没有 `UPROPERTY`**。
2. `UStruct::AddReferencedObjects`（`Class.cpp:2514-2529`）只在 `if (GIsEditor)` 里 `Collector.AddReferencedObject(This->Children, This)` ⇒ **非编辑器构建下这条链不参与引用收集**。
3. `UFunction::Bind()`（`Class.cpp:7679` 起）只做 `Func = &UObject::ProcessInternal` / 查 native 表，**不 root**。
4. ⇒ 对这些动态 `UFunction` 而言，**root 是唯一与构建形态无关的保活手段**；`RemoveFromRoot()` 不是"清理死函数"，而是**撤掉保活**。

**结论**：早退分支命中时（同名函数已存在，典型 = 同 `UClass` 二次绑定 / 域重载后重注册），若该函数是由 `DuplicateFunction` 建立并已条件 root 的那一个，`RemoveFromRoot()` 把它降级为"只靠 `FuncMap`/`Children` 引用"—— 而 B-73 的残余结论（"register 未失效、dispatch 仍按名查找"）意味着它**仍在被用**。这就是"单向解根"。

### 1.4 修法（A）

| 文件:行 | 改动 |
|---|---|
| `FRegisterInputComponent.cpp:594-597` | `if (const auto FoundFunction = …)` ＋ `FoundFunction->RemoveFromRoot();` → `if (InClass->FindFunctionByName(*InFunctionName) != nullptr) { return; }`（+1/−3） |
| `FRegisterEnhancedInputComponent.cpp:76-79` | 同上（+1/−3） |

> **为什么是"删"而不是"补 `AddToRoot`"**：本路径**从不 root**（§1.2 第 3 行），补 root 会引入一个**新的**配对责任（回收在 `FCSharpFunctionRegister.cpp:69-128`，只对 `IsRooted()` 的才 unroot）；而删掉无配对的一侧，在"函数从未 root"时是**严格 no-op**，在"函数已被别人 root"时是**严格更安全**。⇒ 零行为变化 + 消掉唯一的不对称。

> **未采用（B 方案，登记为触发条件）**：早退分支补"摘 `FuncMap` ＋ 失效 register"的**完整替换语义**。它改的是"重绑定到底复用还是重建"这一语义问题，需要先回答"域重载后旧 `UFunction` 的 `Func` 指针是否还能用"，不是本轮能收口的。

**G7**：新增注释 0 / 日志 0 / `throw` 0 / `try-catch` 0 / `ensure`·`check` 0 / 公开 API 0（`BindFunction` 是 `namespace {}` 内的静态成员）。
**Q2**：不触碰任何返回值域（早退仍是 `return;`）。

### 2.2 修法

| 文件:行 | 改动 |

> **保留原函数体的理由**：`RemoveReference(UObject*)` 与 `RemoveReference(IManagedHandle)` 是两个重载（`FCSharpEnvironment.h:310/314`，实现 `:677-690`），前者经对象查表、后者直接用句柄。把函数体搬进 GT 分支可**逐字保持原语义**，避免"顺手换重载"引入第二处变量。

> **返回语义（口径项）**：非 GT 路径返回 **`1`（已投递/受理）**，GT 路径返回真实结果。既有值域仍为 `{0,1}`；不给"排队中"新增值（那是值域扩张，会破坏 C# 侧 `bool` 契约）。⇒ 见 §6 台账的口径登记与 [`115`](115-轮B-77-T3第八次选片与立项建议（2026-10-25）.md) Q2 的延续问题。

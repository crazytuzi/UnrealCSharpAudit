### 1.1 被测量函数（HEAD `ea105780`，`Source/UnrealCSharpEditor/Private/Listener/FEditorListener.cpp:497-548`）

```cpp
void FEditorListener::CompileChangedBlueprints()
{
	FGeneratorCore::BeginGenerator(false);                       // :499

	FUnrealCSharpFunctionLibrary::ResetScriptChanged();          // :501

	for (TObjectIterator<UBlueprint> Iterator; Iterator; ++Iterator)   // :503
	{
		if (const auto Blueprint = *Iterator)
		{
			if (Blueprint->GeneratedClass != nullptr)
			{
				if (const auto AssetData = FAssetData(Blueprint);          // :509
					FGeneratorCore::IsSupported(AssetData))                // :510
				{
					const auto SoftObjectPath = FSoftObjectPath(Blueprint); // :512
					const auto CrcLastCompiledSignature = Blueprint->CrcLastCompiledSignature;
					const auto CrcCompiledSignature = CrcCompiledSignatures.Find(SoftObjectPath); // :516
					if (CrcCompiledSignature == nullptr)
					{
						CrcCompiledSignatures.Add(SoftObjectPath, CrcLastCompiledSignature);
						if (!IFileManager::Get().FileExists(                     // :522
							*FGeneratorCore::GetFileName(static_cast<UClass*>(Blueprint->GeneratedClass))))
						{
							FAssetGenerator::Generator(AssetData);               // :525
						}
						continue;
					}
					if (*CrcCompiledSignature != CrcLastCompiledSignature)
					{
						CrcCompiledSignatures.Add(SoftObjectPath, CrcLastCompiledSignature);
						FAssetGenerator::Generator(AssetData);                   // :535
					}
				}
			}
		}
	}

	FGeneratorCore::EndGenerator(false);                         // :542
	if (FUnrealCSharpFunctionLibrary::IsScriptChanged()) { Compile(); }
}
```

## 4. 机制更正（本轮真正的产出）

### 4.1 原判据"每蓝图一次 `FileExists` 系统调用" —— 只在冷路径

`:516` 先查 `CrcCompiledSignatures`，**:522 的 `FileExists` 只在 miss 时执行**。稳态（缓存已满且签名未变）**0 次 syscall**；冷趟 N 次（本机 4.63 µs/次 ⇒ N=16 时 74 µs，N=3 000 时 18.3 ms）。原报告与队列备注把它写成"每个都……`FileExists` 系统调用"，量级与频次都不对。

### 4.2 原判据"`FSoftObjectPath` 构造" —— 38 ns，可忽略

与 `05 §F-PERF-016` 的自行更正一致（快路径 2 个 `FName` 写，不拼字符串）；本轮给出实测量级 **38 ns**，占 9.16 µs 的 **0.4%**。

### 4.3 新主项：`FAssetData(Blueprint)` 的 asset-registry tag 收集（90.5%）

- 构造入口：`AssetData.cpp:403-445`；在**默认 flag** 下 `:438-442` 会调 `InAsset->GetAssetRegistryTags(Context, *this)`；:422-436 另有 `GetLongPackagePath`、`GetClass()->GetPathName()`、`GetPathName()` 三次字符串化。
- `UBlueprint::GetAssetRegistryTags`（`Blueprint.cpp:1048-1090`）会：取 `GeneratedClass` 的 CDO 再收集一遍其 tags（`:1050-1059`）、`Super::GetAssetRegistryTags`、再为 `GeneratedClass` / `ParentClass` / `NativeParentClass` 构造 `FObjectPropertyBase::GetExportPath` 字符串。
- 实测 A/B：完整 **9 648 ns** vs `SkipAssetRegistryTagsGathering` **918 ns** ⇒ **8 730 ns/项（90.5%）是 tag 收集**。

🔴 **两处既有口径都被推翻**：① 原"收益项"（省 `FSoftObjectPath` 构造）只值 38 ns；② `05 §F-PERF-016` 的更正"真正的稳态大项其实是 `IsSupported` 的包路径字符串判断"也只值 **71.9–632 ns（0.8–6.9%）** —— 真正主项是**构造 `FAssetData` 时收集 tags**，原报告与更正都没有把它列入。

## 5. 会话模型与外推

**公式**（N = `CompileChangedBlueprints` 调用时**已加载**且命中的 UBlueprint 数；K = 会话内交互式编译次数）：

```
warm(N)    = 0.1544 ms + N × 9.16 µs
cold(N)    = 0.1544 ms + N × (9.16 + 1.55 + 4.63) µs ≈ 0.1544 + N × 15.34 µs
session(N, K) = cold(N) + K × warm(N)
```

| N（已加载命中） | 单次 warm | 首次 cold | 会话 K=10 | 会话 K=50 | 越过 0.2 s 所需 K |
|---|---|---|---|---|---|
| 100 | 1.07 ms | 1.69 ms | **12 ms** | 55 ms | 185 |
| 300 | 2.90 ms | 4.76 ms | **34 ms** | 150 ms | 67 |
| 1 000 | 9.31 ms | 15.49 ms | **109 ms** | 481 ms | **20** |
| 3 000 | 27.63 ms | 46.17 ms | **323 ms** | 1 428 ms | **6** |

- 本机工程 N=16：单次 **0.44–0.48 ms**、会话（K=10）约 **5 ms** ⇒ 本工程内可忽略（如实登记）。
- 本条原始前提 N=3 000：单次 **27.6 ms**，已是"一次 BP 编译"里 5–50% 的附加延迟（BP 编译本身约 50–500 ms，未单独测量）；会话 K=10 即 **323 ms** ⇒ **超 0.2 s**。
- 与原始假设对比：原假设"3 000 次 `FileExists`"= 3 000 × 6.11 µs = **18.3 ms**；实测 27.6 ms **更高**。⇒ 严重度不因机制更正而下降。

## 6. 修法评估（已量化，本轮**未施工**）

### 6.1 原修法"键改 `UBlueprint*`"—— 证伪

只省 `FSoftObjectPath` 构造 38 ns ＋ `TMap` 哈希 1 次（16–19 ns）≈ **54 ns/项 = 0.59%**，对 27.6 ms/次的量级无意义；且引入"键对象生命周期"问题。

### 6.2 修法 A（不新增公开面，~5 行）—— 8.9×

只把"判定"降级为 skip-tags 构造，`FAssetData` 的完整对象**延迟到真正生成时**构造：

```cpp
if (const auto AssetData = FAssetData(Blueprint,
        FAssetData::ECreationFlags::SkipAssetRegistryTagsGathering);   // 918 ns
    FGeneratorCore::IsSupported(AssetData))
{
    ...
    if (CrcCompiledSignature == nullptr)
    {
        CrcCompiledSignatures.Add(SoftObjectPath, CrcLastCompiledSignature);
        if (!IFileManager::Get().FileExists(*FGeneratorCore::GetFileName(...)))
        {
            FAssetGenerator::Generator(FAssetData(Blueprint));   // 只有这里付 8.7 µs
        }
        continue;
    }
    if (*CrcCompiledSignature != CrcLastCompiledSignature)
    {
        CrcCompiledSignatures.Add(SoftObjectPath, CrcLastCompiledSignature);
        FAssetGenerator::Generator(FAssetData(Blueprint));
    }
}
```

- 实测 replica：**146.6 → 16.5 µs/趟（8.9×）** ⇒ N=3 000 时 **27.6 → 3.25 ms/次**，会话 323 → **48 ms**。
- 语义：判定只用包名（`GetPackage()` 不变）；生成路径拿到的是**同参数构造**的完整 `FAssetData`，与今日逐字节一致。

### 6.3 修法 B（公开面 ＋1 个导出标记）—— 133×

给 `FGeneratorCore::IsSupported(const UPackage*)`（`FGeneratorCore.h:55`，当前**未导出**，跨模块不可链接）补 `SCRIPTCODEGENERATOR_API`，判定改 `IsSupported(Blueprint->GetOutermost())`：

- 实测 replica：**1.1 µs/趟（0.069 µs/项）** ⇒ N=3 000 时 **0.36 ms/次**，会话 ~**4 ms**（仅剩固定 0.154 ms）。
- 语义：`FAssetData::GetPackage()` 对已加载对象就是 `FindPackage(PackageName)`，与 `GetOutermost()` 同一 `UPackage`；`FullyLoad()` 对已加载包是 no-op。
- 代价：`FGeneratorCore.h` 一行 `SCRIPTCODEGENERATOR_API`（不是新 API）；需重编依赖模块。

**建议**：A 先行（零公开面变更、零跨模块风险），B 作为后续可选收尾。

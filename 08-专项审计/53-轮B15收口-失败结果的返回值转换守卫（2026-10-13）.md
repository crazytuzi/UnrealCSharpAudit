## 1. 缺口与机制

### 1.1 `Invoke` 返回值的四个消费点（B-14 之后）

| 消费点 | 是否有判定 | 失败句柄（`0` / `-1`）的实际后果 |
|---|---|---|
| `FManagedFunctionDescriptor::Invoke` | ✅（B-14 加） | 不写返回槽、不 `GCHandle_Free` ✓ |
| `TMethodHelper::Invoke`（绑定侧） | ❌（本轮补） | **原语结果：`UnboxValue` ⇒ `nullptr` ⇒ 空指针解引用（AV）**；对象/结构/字符串结果：`Default`／空 |
| `FDomain::GetTraceback` | ❌（本轮补） | 字符串路径本身有守卫 ⇒ 空串（**安全**，但会多走一次无效 `StringToFString` 与 `Free`） |
| 🆕 `FScriptDomainImpl::GetClassesWithAttribute`（`:569`，**Core 层**） | ❌（**B-16 补入清单**） | 哨兵通过判据，但 `int32 OutLength{}` 初值 **0**（异常时 C# 未写回）⇒ **循环 0 次**；`Free(-1)` 走 C# `TryGetValue` ⇒ 无操作 ⇒ **无后果**（实测核实见 [`08-…/54`](54-轮B16核实-ref写回路径与消费点普查更正（2026-10-13）.md)） |
| `FClassReflection` ×3 ／ `FDomain::Initialize`·`DeinitializeSynchronizationContext` ×2 | —— | 返回值被丢弃 ⇒ **丢弃方，不是消费点**（本清单经轮 B-16 更正：原文误列 `FClassReflection`、漏列 Core 那处） |

### 1.2 为什么 `0` 与 `-1` **同等**

```
FPropertyValue<原语>::Get(handle) → FDomain::Object_Unbox(handle) → IScriptDomain::UnboxValue(handle)
    if (IManagedHandleIsValid(handle))          // 判据 = (handle != InvalidManagedHandle)，即只排除 0
    { …11 个 Unbox 桥… }                        // -1 会"通过"判据 ⇒ 逐个调用，全部返回 0（C# 侧是防御式的）
    return nullptr;                             // ← 两种情况都落到这里
```
- `0`：判据**拒绝** ⇒ 直接落 `return nullptr;`；
- `-1`：判据**通过** ⇒ 白走 11 次跨边界调用 ⇒ 同样落 `return nullptr;`。

⇒ 因此这是**先于 B-14 存在**的缺口（B-14 之前异常也返回 `0`）；B-14 的哨兵只是让它多走 11 次无效调用。**这也说明"把哨兵塞进全局判据"（我最初的方案）并不能治这个崩溃** —— 治它的是**消费点的判定**。

### 1.3 判据通道（用于 A/B）

C++ 侧夹具 `FTestMethodHelper::Test()` 用 `TMethodBuilder<Result>::Invoke(this, TEXT("..."))` 按名字调用**托管**方法（`TMethodBuilder.inl:11` → `TMethodHelper<std::tuple<Result, …>>::Call`），C# 对侧是手写 partial 类 —— 正好是"原语返回值 ＋ 可注入异常"的组合 ⇒ **判据可构造**。

## 6. 复用价值（方法论）

1. **借现成夹具做 A/B**，比自造装置便宜得多：`TMethodBuilder` 夹具 ＋ 手写 C# 对侧本来就在库里，注入一个 `throw` 就得到"原语返回值 ＋ 异常"的完整组合 ⇒ 把"可能崩"变成"**确实崩**（`0xC0000005` ＋ 无 CSV）"。
2. **"守卫分布"要先量**：本轮先量出"域层 11 座 Unbox 桥全守卫、判据只排除 `0`、消费点无判定"，才定位到唯一缺口；反之若按直觉去改判据，既治不了崩溃（`0` 也崩）又会牵动 84 处语义。
3. **失败语义的分层**：在**这些消费点上**"异常"与"无句柄"**等价**（都只能给默认值）⇒ 因此不需要在每个消费点区分 `-1` 与 `0`，只需要**都拒绝**；真正需要区分的场景（要对异常做特殊处理）目前不存在。
4. **同轮发现＋同轮闭合的条目也要留账**：`F-CS1-042` 在 `01` 留行、在 `05 §15` 归档，附逐字原状描述与 A/B 读数，避免"修了什么、凭什么说修好了"只有口头结论。

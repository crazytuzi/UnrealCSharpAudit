## 1. 双写与单源化方案（已回滚）

```csharp
// CoreCLR.Build.cs（submodule）
var HostFxrFileName = Target.Platform == UnrealTargetPlatform.Win64
	? "hostfxr.dll"
	: Target.Platform == UnrealTargetPlatform.Mac
		? "libhostfxr.dylib"
		: "libhostfxr.so";

PublicDefinitions.Add($"CORECLR_LIB_HOSTFXR=TEXT(\"{HostFxrFileName}\")");
```

```cpp
// FCoreCLRFunctionLibrary.cpp（插件仓库）
-	                       *LIB_HOSTFXR
+	                       *FString(CORECLR_LIB_HOSTFXR)
```

- `Macro.h:85-91` 的 `#if` 块整体删除 ⇒ 全仓 `LIB_HOSTFXR` 归零，命名只在 Build.cs 出现一次；
- 本机 5.6 编译通过（`CORECLR_LIB_HOSTFXR` 经 `CoreCLR` 模块的 `PublicDefinitions` 传播到 `UnrealCSharpCore`，后者是唯一依赖 `CoreCLR` 的模块）。

## 2. 为什么不能交付

| 事实 | 读数 |
|---|---|
| 子模块声明 | `.gitmodules`：`[submodule "Source/ThirdParty/CoreCLR"]` → `crazytuzi/CoreCLR` |
| 插件侧 diff | `0 0 Source/ThirdParty/CoreCLR`（只有指针位置，不含 Build.cs 内容） |
| 干净 checkout 后果 | 插件提交指向**旧** CoreCLR 指针 ⇒ `CORECLR_LIB_HOSTFXR` 未定义 ＋ `LIB_HOSTFXR` 已删 ⇒ `UnrealCSharpCore` 编译失败 |

⇒ 单源化必须与 **CoreCLR 子模块提交/推送** 一起发布（三步：子模块提交 → 推送远端 → 插件更新指针）。这超出"单轮审计只改插件仓库"的工作边界。

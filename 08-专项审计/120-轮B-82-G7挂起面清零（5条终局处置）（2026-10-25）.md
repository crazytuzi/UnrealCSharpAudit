## 2. 逐条事实（HEAD `91fc122a`）

### 2.1 `F-REG2-011` —— 9 个空 `Initialize()` ＋ 1 个空壳回调

- 空 `Initialize()` **9** 个：`FBindingRegistry` / `FContainerRegistry` / `FDelegateRegistry` / `FFieldPathRegistry` / `FMultiRegistry` / `FObjectRegistry` / `FOptionalRegistry` / `FStringRegistry` / `FStructRegistry`（均为 `void F<X>Registry::Initialize() { }`，声明在 `Public/Registry/*.h` 的 public 段）。
- `FCSharpEnvironment::OnUObjectArrayShutdown()` `:340-342` 空实现（引擎契约实为"摘净 listener"，该空壳不构成状态不干净 —— B-77 已复核）。
- **判定**：纯噪音 + 公开面；两条出口分别撞公开面与 G7（注释）⇒ **决定不做**，触发条件 = 注册表重构。

### 2.2 `F-FL-010`（撞名半边）—— 非单射编码

- `FUnrealCSharpFunctionLibrary::Encode` `:1338`；关键字表 `:1340`（`TArray<FString, TInlineAllocator<77>>`）；线性扫描 `:1362`。
- 非单射：`Object` → `__Object`，而真实成员名 `__Object` 也会被原样保留 ⇒ 两者可撞。
- **判定**：撞名检测需日志/异常（G7）；改注入式编码会重写全部产物并改变生成名 ⇒ **决定不做**，触发条件 = 真实撞名实证或允许一次全量换名。

### 2.3 `F-DEL-016` —— 只为两个描述符而存在的 API

- `UDelegateHandler::GetUObject()` `DelegateHandler.cpp:90-92`、`GetFunctionName()` `:95-97`；两个 helper 同形转发（`FDelegateHelper.cpp:73-80`、`FMulticastDelegateHelper.cpp:101-108`）。
- **调用点恰好 2 处**：`FDelegatePropertyDescriptor.cpp:32`、`FMulticastDelegatePropertyDescriptor.cpp:33-34`（都是 `BindUFunction(bridge, CSharpCallBack)`）。
- ⇒ 目标 getter **没有天然消费者**：这两个调用点要的正是"桥对象 + 固定回调名"。E2 的"必须有真实调用方"不满足 ⇒ **决定不做**，触发条件 = 出现需要区分桥/目标对象的调用方。

### 2.4 `F-ABI-007`（`0` 双义半边）—— 唯一消费者不可达歧义

- 唯一消费点：`FDynamicEnumGenerator.cpp:281-295` —— 遍历 `InClassReflection->GetFields()`，把**同名**字段名传回 `GetFieldStaticValue`。
- 字段名来自同一份 C# 反射 ⇒ "字段查不到"在该路径**不可达**；而 C# 侧无法直调 `[UnmanagedCallersOnly]`（编译期禁止）⇒ 当前**无第三方调用者**。
- `long` 值域 = 全 `int64`（UENUM 底层可为任意 `int64` 值）⇒ 任何哨兵都是合法枚举值。
- **判定**：E3 取不到值域证明 ＋ 歧义不可达 ⇒ **决定不做**，触发条件 = 出现第三方调用者或愿意改协议。

### 2.5 `F-PROP2-006 (04b)` —— 被既有用例钉死的契约

- B-74 实测：`FRegisterText.cpp` 改 `WriteToBuffer` 可编可跑（5.0.3/5.6.0 同签名），但套件唯一差异行是 `TextToString, true → false`（`UnitTest/String/FText/UnitTestSubsystem.cs:88-99` 断言 `ToString() == "12"`）。
- 新增序列化 API（`ToSerializeString()`）属 E2′（新增 API），**未获批**；改 `ToString` 语义属改既有契约（比新增更大）。
- **判定**：**决定不做**，触发条件 = `FText` 序列化成为真实需求且维护者批准新增 API。

## 4. 今后新条目遇 G7 的判定路径（本页固化）

1. **先问"是不是在托管边界上"**：若是 `[UnmanagedCallersOnly]` 函数体（或其唯一调用方为边界入口的私有实现）⇒ 可直接用 **E1**（空 catch ＋ 既有失败值），**无需再裁定**。
2. **再问"是不是只是观测"**：若需要的是"读出既有状态"且**确有调用方** ⇒ 可用 **E2**（只读 getter）；**无调用方则不做**（本页 `F-DEL-016` 即此）。
3. **再问"值的合法域有没有空位"**：若有确定空位且能给出证明 ⇒ 可用 **E3**；值域是全 `int64`/全指针空间 ⇒ **不做**（本页 `F-ABI-007` 即此）。
4. 以上都不成立 ⇒ **开待决策页**（格式照 `08-…/118`：现状考证 → 逐条 → 例外提案 → 回执表 → 不拍板代价），**不得在施工轮里自行开口**。

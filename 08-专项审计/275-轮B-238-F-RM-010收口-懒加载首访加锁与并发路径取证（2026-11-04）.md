## 1. 取证：默认配置下首访只在 GT（保留，作为契约依据）

`FClassReflection` 的懒加载入口是 `GetProperties/GetFields/GetMethods/GetDescriptor` → `EnsureDescriptor/EnsureMemberImplementation`（`FClassReflection.h:84-112`），旗标 `bDescriptorLoaded`/`bPropertiesLoaded`/`bFieldsLoaded`/`bMethodsLoaded`/`bInitializing` 都是**普通 bool**。

| 路径 | 证据 |
|---|---|
| 生成器（`FDynamicGenerator::Generator()` / `Generator(fileChanges)`） | 编译线程只**派发**：`FCSharpCompilerRunnable.cpp:695-699` 用 `FFunctionGraphTask::CreateAndDispatchWhenReady(Reload, …, ENamedThreads::GameThread)`，`InFunction` 在 `Reload` 内执行 ⇒ **GT** |
| 绑定/注册（`FCSharpBind`） | 域初始化 / 模块激活路径（`FCSharpEnvironment::RegisterBinding`）⇒ **GT** |

| `OnAsyncLoadingFlushUpdate` | 默认由 `FAsyncLoadingThread2::ProcessAsyncLoadingFromGameThread`（`AsyncLoading2.cpp:9166`，注释 "Call update callback once per tick on the game thread"）广播 ⇒ **GT** |

**唯一的非默认路径**（保留取证，供触发条件引用）：

```
FAsyncLoadingThread::ProcessAsyncLoading（AsyncLoading.cpp:4327，ALT 上）→ FCoreDelegates::OnAsyncLoadingFlushUpdate.Broadcast()（:4354）
  → FCSharpEnvironment::OnAsyncLoadingFlushUpdate()（FCSharpEnvironment.cpp:420）
```

该路径要求 **`s.AsyncLoadingThreadEnabled=1`**（引擎默认 `0`，本项目不发布该配置）。

## 2. 裁定：不加锁

| 理由 | 说明 |
|---|---|
| 默认配置无多线程形 | 引擎默认 `s.AsyncLoadingThreadEnabled=0`；上表四条路径全在 GT ⇒ 锁防的是**不发生的运行期形态** |
| 与 B-236 同一取舍原则 | 不为"不会发生的输入/配置"增加机制（`DestroyPropertyTree` 同理撤除） |
| 同步机制有真实代价 | 静态锁会把每次懒加载首访串行化；头文件快路径若也加锁会进热路径；严格无竞争还要把五个旗标改 `std::atomic<bool>` 并改写 `TGuardValue<bool>` 用法 |
| 同前提的兄弟条目 | `F-CONC-004`/`F-REG-009` 虽已加锁（`90f239f4`），但那是 P1 ＋ 已排期；本条按维护者口径不扩面 |

**曾施工后撤除**：提交的加锁写法（`static FCriticalSection CriticalSection` ＋ 两个 `Ensure*Implementation` 首行 `FScopeLock`）已 `reset` 撤除，工作树与撤除前状态 **逐字节相同**（`git diff` 为空；`FClassReflection` 中 `CriticalSection` 命中 0）。

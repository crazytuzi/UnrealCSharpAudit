## 6. 复用价值（给下一轮）

1. **"编译探测"可以取代静态推演**：版本宏/签名类改动，只要在本机能编的版本上插 `#if !defined(...) #error` + `static_assert(值)`，就能把"宏可见性"与"取值"变成硬事实（成本 ≈ 1 次增量构建 40 s）。**本轮据此排除了一个真实陷阱**（该文件不直接 include `UEVersion.h`）。
2. **"注册名 ↔ 目标符号"错配的批次判据**：以"`.Function("X", … &C::Y`）中 `X != Y` 且 `Y != X + "Implementation"`"为唯一规则做机械扫描（58 文件 / 948 个 `.Function(`）即可穷尽这一类；本轮 6 处全部由此定位，**修完应再扫一次**（预期 0 命中）。
3. **产物 manifest 对照是本轮最划算的证据**：16 230 行 `path|length|sha256`，前后对比直接给出 `added/removed/changed` 与逐文件字节数——**既证明"改到了该改的"，也证明"没改到不该改的"**（本轮 changed=13 与预期类型集完全吻合）。
4. **"改前探针"写法**：把缺陷**断言成 true**（而不是断言"它应该是错的"），可以在一轮里同时得到"缺陷存在"与"套件基线全绿"两个结论；探针文件独立成文件、取证后整文件删除，不污染永久用例集。
5. **形状断言 vs 语义断言**：名字/重载类缺陷只有形状断言能锁死（`GetMethods().Count(Name=="X")`、`GetMethod("X", new[]{…})`），语义断言对它们无效。
6. **同名 API 的跨类型形状对照**是很好的旁证：`FVector.SetComponentForAxis`（2 参）/ `FRotator.SetComponentForAxis`（1 参）这种"同名不同形"一眼可见（本轮探针即用此判据）。
7. **`Axis` 映射不可凭直觉**：`FRotator` 的 `X→Roll / Y→Pitch / Z→Yaw` 三版本一致；写用例前回引擎源码（§4.2 踩坑 1）。

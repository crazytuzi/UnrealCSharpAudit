## 6. 环境事故与处置（本轮新踩到的坑，必读）

1. 🔴 **"缺件 + 闸门" 两类状态必须以 `IsScriptPublishOutdated()` 为准来构造**：只改名 `UE.dll` 得到的不是"域说谎"，而是"链没启动"（E5）。任何后续"缺件态"装置，**先确认这道闸门是开还是关**。
2. 🔴 **UE_LOG 探针在"挂起/硬杀"场景不可靠**：本轮第一版读数因此**全空**并一度误判。⇒ 改**文件探针**（append 落盘）后立刻拿到完整链路（§3.1）。
3. 🔴 **构建 Result 必须与运行读数成对记录**：第一次 Mono"改前"跑时构建其实**失败**（`Unable to build while Live Coding is active`），跑的是旧二进制 ⇒ 读数假绿（§3.3 的作废记录）。
4. 🔴 **挂死的 UnrealEditor 进程会长期占用插件 DLL 与 Live Coding 互斥**：`Stop-Process -Force` / `taskkill /F` / WMI `Terminate` 全部返回成功但进程不消失（单线程、`Responding=True`），随后 UBT 报 `Unable to build while Live Coding is active`，绕过该检查（`-NoHotReloadFromIDE`）后又报 `LNK1104`。

## 7. 复用价值（给后续轮）

1. **激活链一行探针就能定位"插件没起来"**：`OnUnrealCSharpCoreModuleActive` → `FScriptDomainScope` → `Domain::Initialize` → `FDomain::Initialize` → `RegisterDynamic`。本轮靠这 5 个点把"没起来/起来了但说谎/起来了正常"三种状态一次分清。
2. **`IsScriptPublishOutdated()` 是"发布产物完整性"的现成闸门，但只覆盖 UE/Game**：任何"缺件"相关的新装置或新修复，都应把它一并考虑（例如若要覆盖 Interop/自定义程序集，入口就是 `:1288-1291` 那个数组）。
3. **被锁 DLL 的改名绕行**：见 §6-4 —— 在没有重启条件时，这是唯一能让链接继续的手段。
4. **文件探针**：见 §6-2。
5. 🆕 **编辑工具会吃掉文件首行 BOM**（本轮两度发生，`FUnrealCSharpFunctionLibrary.{h,cpp}` 与 `FMonoDomain.cpp`）：改完必须做**字节体检**（BOM / CRLF / 行尾空白 / 缩进 TAB），否则 diff 里会混进"整行被改"的假变更 —— 本库对"纯格式差异"历来单独留痕，值得花这 10 秒。
6. 🆕 **改名先取证据、再动手**：同一文件内的**同类谓词实现形态**（本例三处早退）与**命名家族**（`Is*`/`Has*` 各自先例数）是最硬的判据；凭语感引入新前缀（`Are*` 在插件与引擎 Runtime 目录内实测**均无先例**）会被打回。另：`#include` 的增删要看**同文件邻居**怎么做（本例邻居用已包含的 `FPlatformFileManager`，故新增 include 属多余）。

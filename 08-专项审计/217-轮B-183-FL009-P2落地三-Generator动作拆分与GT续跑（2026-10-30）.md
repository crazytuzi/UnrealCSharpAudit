## 1. 施工

### 1.1 拆分点（为什么在分析处切）

```cpp
void FUnrealCSharpEditorModule::Generator(const FString& InPlatformName, const bool bForceCompileInterop)
{
	if (IsRunningCommandlet())          // 命令行：保留原 13 步同步路径
	{
		GeneratorInternal(InPlatformName, bForceCompileInterop, false);
		return;
	}

	static bool bIsGeneratorScheduled = false;

	if (bIsGeneratorScheduled)          // 分析阶段重入 ⇒ 静默返回
	{
		return;
	}

	bIsGeneratorScheduled = true;

	{
		const auto ScriptDomainType = FUnrealCSharpFunctionLibrary::GetScriptDomainType(InPlatformName);

		FScriptDomainTypeScope ScriptDomainTypeScope(ScriptDomainType);

		FSolutionGenerator::Generator();
	}

	FCSharpCompiler::Get().EnqueueTask([InPlatformName, bForceCompileInterop]()
	{
		FCodeAnalysis::CodeAnalysis();          // 编译器线程：dotnet 进程

		AsyncTask(ENamedThreads::GameThread, [InPlatformName, bForceCompileInterop]()
		{
			GeneratorInternal(InPlatformName, bForceCompileInterop, true);

			bIsGeneratorScheduled = false;
		});
	});
}
```

### 1.2 `GeneratorInternal`（原函数体 ＋ 两个跳过分支）

| 原步骤 | 第一段（GT，`bIsCodeAnalysisHandled=false`） | 第二段（GT，`true`） |
|---|---|---|
| `OnBeginGenerator` / 域作用域 / culture | — | **在此重建**（`bIsGenerating` 自第二段起为真） |
| `FScopedSlowTask` | — | 帧数 **13 → 11**（跳过前两步） |
| Solution Generator | ✅ 第一段已做 | ⏭ 跳过 |
| Code Analysis | ⏭ 由编译器线程任务做 | ⏭ 跳过 |
| `CodeAnalysisGenerator` → `EndGenerator` → GC → `ImmediatelyCompile` → `OnEndGenerator` | — | ✅ 原样 |

> 关键点：`OnBeginGenerator` 原来在函数第一行广播，它置 `bIsGenerating=true`；而 `FCSharpCompilerRunnable::Run()` 只在**空闲分支**排空 `TaskQueue` ⇒ 若保持"先广播再投递"，分析任务永远不会执行（GT 又在等它）= 死锁。把它移到第二段是这次拆分能成立的前提。

## 5. 边界（必读）

1. **`ImmediatelyCompile` 仍阻塞 GT**：第二段末尾的 C# 编译在调用线程（GT）执行，本轮未动；探针里第二段 63.9 s 主要是它 ＋ 生成。若要彻底"零 GT 阻塞"，还需把这一步换成异步编译（会改变"动作结束即有新程序集"的语义），属另一议题。
2. **分析期间无进度对话框**：第一段无 `FScopedSlowTask`；第二段才弹 11 步对话框。冷启动/工具过期时分析可能长时间无可见进度（编辑器可正常操作）。若要补进度，需要复用通知通道（新 UI 面），本轮未做。
3. **`SolutionGenerator` 不再处于 `bIsGenerating` 之下**：第一段到投递之间，编译回调触发的生成不再被该标志挡住（窗口极短，且分析任务在编译器线程与 `DoWork` 串行）。登记为已知窗口。
4. **重入只做了"静默返回"**：未构造双击语料；若维护者希望有提示，需要新 UI/日志出口（受 G7）。
5. **退出期竞态**：若编辑器在分析完成前退出，第二段可能不执行 ⇒ 本次不生成；下次触发重跑。
6. **后台读 settings CDO**：`CodeAnalysis()` 仍在编译器线程读 `UUnrealCSharpEditorSetting`/`UUnrealCSharpSetting`（与 B-181/182 同一既有边界，见 [`215`](215-轮B-181-FL009-P2落地-编译器线程任务队列与三处GT外移（2026-10-30）.md) §7）。
7. **命令行路径未实跑**：`-run=GeneratorScriptCode` 走 `GeneratorInternal(…, false)`（原函数体逐字保留），仅编译与静态对照覆盖，未跑整条 commandlet。

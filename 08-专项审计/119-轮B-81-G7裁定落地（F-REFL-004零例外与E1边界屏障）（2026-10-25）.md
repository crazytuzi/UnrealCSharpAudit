## 1. 施工面

### 1.1 `F-REFL-004` —— 零例外路线（`+45/−0`）

> 🔁 **已被轮 B-86 重构（`91fc122a`）**：该私有头已删除，判定并入 `FReflectionRegistry` 的成员谓词（B-86 名为 `HasAllCoreClasses()`，**B-87 已改名为 `IsInitialized()`**）（见 [`124-轮B-86`](124-轮B-86-谓词并入FReflectionRegistry（HasAllCoreClasses）（2026-10-26）.md)）；本页以下读数保留为**当时**的交付记录。

**新文件** `Source/UnrealCSharpCore/Private/Domain/FReflectionRegistryValidator.h`（52 行，CRLF／无 BOM／TAB／最大宽 70）：

```cpp
FORCEINLINE bool IsReflectionRegistryComplete()
{
	auto& Registry = FReflectionRegistry::Get();

	auto bComplete = Registry.GetUtilsClass() != nullptr
	                 && Registry.GetObjectClass() != nullptr
	                 /* …共 29 个无条件项… */
	                 && Registry.GetTFieldPathClass() != nullptr;

#if UE_F_UTF8_STR_PROPERTY
	bComplete = bComplete && Registry.GetUtf8StringClass() != nullptr;
#endif

#if UE_F_ANSI_STR_PROPERTY
	bComplete = bComplete && Registry.GetAnsiStringClass() != nullptr;
#endif

#if UE_F_OPTIONAL_PROPERTY
	bComplete = bComplete && Registry.GetTOptionalClass() != nullptr;
#endif

	return bComplete;
}
```

**三个域的落点**：

| 文件:行 | 改动 |
|---|---|
| `FCoreCLRDomain.cpp:8` / `:209-214` | 加私有头；`Initialize()` 之后 `if (IsReflectionRegistryComplete() == false) { bIsInitialized = false; }` |
| `FMonoDomain.cpp:17` / `:168-173` | 同上（Mono 的 `bIsInitialized` 语义与 CoreCLR 一致） |
| `FLeanCLRDomain.cpp:10` / `:798-800` | 该函数本来就返回 `bool` ⇒ `return IsReflectionRegistryComplete();`（其调用方 `:79-84` 失败即 `UnloadAssembly`，`bIsInitialized` 保持 false） |

**为什么这是"零例外"**：校验只调用**既有公开 getter**（`FReflectionRegistry.h:31-99` 的 32 个 `GetXxxClass()`），失败只写**既有** `bool` 状态（`IScriptDomain::IsInitialized()` → `FDomain::IsLoadSucceed()` → `FClassRegistry.cpp:265` / `FDynamicRegistry.cpp:60`）⇒ 零日志、零 `try-catch`、零断言、零新增公开 API。

### 1.2 E1：`F-CS2B-026`（`Utils.cs`，`+72/−4`）

5 个 `[UnmanagedCallersOnly]` 入口的失败取值各自确定：

| 入口 | 形态 | catch 的失败值 |
|---|---|---|
| `IsOverride(nint)` | 返回 `int` | `0` |
| `GetClassDescriptor(nint, nint*)` | 15 槽 | 槽位 **0..14 全零** |
| `GetClassProperties(nint, nint*)` | 8 槽 | 槽位 **0..7 全零** |
| `GetClassFields(nint, nint*)` | 3 槽 | 槽位 **0..2 全零** |
| `GetClassMethods(nint, nint*)` | 14 槽 | 槽位 **0..13 全零** |

**形态**：每个入口保留原签名（`[UnmanagedCallersOnly]` 与槽位数**逐字未动**），函数体改为 `try { XxxInternal(...) } catch (Exception) { 失败值 }`，原实现迁到同名 `private static XxxInternal`（**缩进零变化**，避免 150 行纯空白 diff）。槽位计数与 C++ 侧 `F-ABI-008` 记录的 **15/8/3/14** 魔术数字对逐项一致。

### 1.3 E1：`F-ABI-037`（`TypeBridge.cs`，`+10/−1`）

`GetTypeImplementation(string)` 的唯一 `Type.GetType(...)` 调用点：

```csharp
Type? Type;

try
{
    Type = System.Type.GetType(InFullName, throwOnError: false, ignoreCase: false);
}
catch (Exception)
{
    Type = null;
}
```

后续的"逐程序集兜底扫描"照常执行 ⇒ 非法名从"抛 `ArgumentException` 穿出边界"变成"返回 `null`"。**位置说明**：catch 落在**非公开实现**而非 `[UnmanagedCallersOnly]` 本体，其调用方只有两个边界入口（`TypeBridge.GetClass` `:23`、`ArrayBridge.NewArray` `ArrayBridge.cs:15`；`TypeBridge.GetFunctionPointer` `:82` 调的是 3 参重载、不含 catch）⇒ 符合 §8.5 E1 的"唯一调用方是边界入口"的实质。⚠️ **字面差异（2026-10-26 全跨度复核发现，当日已裁决）**：该实现是 `internal static`（因 `ArrayBridge` 跨类调用）而非 `private` —— 维护者选 **A**，`_CONVENTIONS.md` §8.5 E1(b) 已改为"全部调用方都是边界入口的**私有/内部实现**（`private`/`internal`）" ⇒ **该形态现已合规**。见 [`130-轮B-95`](130-轮B-95-全跨度复核（B-78至B-94）（2026-10-26）.md) §4。

### 1.4 E1：`F-ABI-007`（`FieldBridge.cs`，`+25/−0`）

`SetStaticValue`（`void`）与 `GetStaticValue`（`long`）各加一层屏障：前者 catch 为空（无返回值可写），后者失败返回 `0`。原实现迁到 `SetStaticValueInternal` / `GetStaticValueInternal`。

### 1.5 E2／E3 的**不施工**结论（两条，均按 §8.5 的硬约束判定）

- **`F-DEL-016`（E2 不满足"必须有真实调用方"）**：目标 getter（`GetTargetObject()` / `GetTargetFunctionName()`）在当前代码里**没有任何消费者** —— 两个描述符用的是 `SrcDelegateHelper->GetUObject()/GetFunctionName()`（`FDelegatePropertyDescriptor.cpp:30`、`FMulticastDelegatePropertyDescriptor.cpp:33-34`），C# 侧也没有对应绑定需求。新增即死 API ⇒ **不施工**，维持暂缓；触发条件 = 出现"需要区分桥对象与 C# 目标对象"的真实调用方（或委托属性赋值语义重做）。
- **`F-ABI-007` 的 E3 不满足"值域证明"**：`GetStaticValue` 返回 `long`，而它服务的 `FDynamicEnumGenerator` 读的是 **UENUM 值域 = 全 `int64`** ⇒ 任何候选哨兵（含 `long.MinValue`）都是**合法枚举值**。⇒ 该半条**不做**，登记为"`0` 双义在枚举路径上不可消解"。

4. **`Interop.dll` 的发布**仍走手工命令（同 B-79 的边界说明），未走 B-68 的自动重建链。
5. **`F-DEL-016` 的改判**只到"无消费者"这一层；若维护者希望**先建 API、后找消费者**，需再开一次 E2 例外（本页按 §8.5 的硬约束未做）。
6. **`F-ABI-007` 的 `0` 双义**在枚举路径上**无法消解**（值域 = 全 `int64`）；若要区分，只能改协议（新增"字段存在"出参）—— 属公开面变更，需另裁。

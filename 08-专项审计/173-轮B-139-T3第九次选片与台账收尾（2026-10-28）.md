## 3. 立项（2 条）

### ① `F-HLP-008`：`TArray.Remove` 的 O(n²) 与反复 `Shrink`（P2/活跃/确认）

- **现状**（`FArrayHelper.cpp:385-403`）：
  ```cpp
  int32 FArrayHelper::Remove(const void* InValue) const
  {
      auto RemovedNum = 0;
      TArray<int32> x;                       // 未使用的局部（死代码）
      auto Index = Find(InValue);
      while (Index != INDEX_NONE) { ++RemovedNum; RemoveAt(Index, 1, true); Index = Find(InValue); }
      return RemovedNum;
  }
  ```
- **修法**（≈12 行、1 文件）：改为一次索引扫描（`Identical` 判定）＋ 循环内 `RemoveAt(Index, 1, false)` ＋ 结尾 `RemovedNum > 0` 时 `Shrink` 一次；删除未使用局部。
- **判据**：微基准（`TArray<int>` 10 000 元素 × 200 轮 `Remove`，对照 B-40 的计时口径）＋ 套件**逐字节不变**（`D520F5AD…`）＋ `-game` 0 红。
- **口径**：G7（无注释/日志/异常/公开 API）；§7 无新 API（`Shrink(Size, Alignment)` 与 `GetRawPtr` 5.0–5.8 均有）。

### ② `F-PROP2-012 (05)`：`FMulticastDelegatePropertyDescriptor` 缺 `FParameter` 覆写（P2/活跃/确认）

- **现状**：`FPropertyDescriptor::Get(void*, void**, FParameter)`（`FPropertyDescriptor.cpp:144-147`）直接转发 `FMember`；`FMulticastDelegatePropertyDescriptor` 没有覆写 ⇒ 参数缓冲区地址被当作属性成员地址传入 → sparse 多播委托的 `ResolveSparseOwner` 按"实例成员地址"反推 owner ⇒ `check(false)`（Development）或 nullptr owner 串扰（Shipping）。
- **修法**（待细化）：在 `FMulticastDelegatePropertyDescriptor` 增 `Get(..., FParameter)` 覆写，参数路径**跳过 sparse owner 解析**（按值缓冲直读）；`FManagedFunctionDescriptor.cpp:37` 的调用面不变。
- **语料**：需要一个"`UFUNCTION` 形参为 multicast delegate"且属性为 **sparse** 的 C++ 宿主（`.`h` 里 `TMulticastSparseDelegate` 成员 + 函数参数）——这是本条的主要成本。
- **判据**：动态 C# 类调用该 UFUNCTION 传委托 → `check` 不再触发 + 参数值正确；控制项 = inline 多播参数两态不变。

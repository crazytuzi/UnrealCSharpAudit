## 2. HEAD 事实与两处口径更正

| 报告原判 | HEAD 事实 |
|---|---|
| "`GetFullClass` 条件表达式重复两遍" | **已不存在** —— `:395-398` 只算一次 `bIsNativeName`，`:403/:407` 两处**使用**同一变量（不是重复计算） |
| "无缓存" | 成立：`GetClassNameSpace` 每次 `GetOuter()->GetName()` ＋ `Replace` ＋ `ParseIntoArray` ＋ `FNameEncode::Encode` ＋ `Join` ＋ `Printf`（`:435-461`）；`GetFullClass` 每次 `Printf` ＋ `Encode`（`:400-408`） |

**为什么不做缓存**：缓存键只能是 `UStruct*`（或名字），而 `UStruct` 是 GC 对象、且可被改名/重定向 ⇒ 需要 `FUObjectArray` 删除监听或引用注册表级失效面；为 ~56 ms/生成引入一套失效逻辑，风险与收益不成比例。

**处置**：🟡 **降级 P3、本体不施工**；触发条件 = 生成 wall 的 profiling 把 `GetClassNameSpace`/`GetFullClass` 排进前列（例如单会话 >10⁶ 次调用）。

## 3. 新立项：`F-ED1-002`（P2 · 活跃 · 新建类向导缺 C# 标识符/关键字校验）

**HEAD 复核（本轮）**：

| 事实 | 位置 |
|---|---|
| 校验只调 `GameProjectUtils::IsValidClassNameForCreation`（UE 类名规则）＋ 重名检查，**无 C# 关键字/标识符校验** | `SDynamicNewClassDialog.cpp:868-920` |
| 生成类名 = **父类为 C++ 原生时加 `A`/`U` 前缀**（`_C` 结尾除外） | `DynamicNewClassUtils.cpp:93-100` |
| 模板替换**不经过** `Encode`（无关键字转义） | 同上 `:107+` |

⇒ **收窄**：原生父类路径下 `class` → `Aclass`（合法，不触发）；**只有 Blueprint 父类路径（无前缀）**才会生成 `public class class …` 这类非法 C#。这正是报告标题"Blueprint 类型路径"的意思，但报告未点明"原生父类被前缀救了"这半边。

**修法（B-151 施工面，≈20 行、1 文件）**：在 `UpdateInputValidity` 里，当"不会加前缀"（非原生父类，或 `_C` 结尾）时，用既有 `FUnrealCSharpFunctionLibrary::Encode(NewClassName, false) != NewClassName` 判定关键字（`Encode` 对关键字返回 `__name`，对普通 ASCII 标识符原样返回），命中则 `LastInputValidityErrorText = LOCTEXT(...)` 并返回 false —— 不新增公开 API、不加日志。

**判据（待 B-151 落地）**：
1. **代码级**：`Encode(name,false) != name` 的判定点存在且只在"无前缀"分支生效；
2. **构建级**：`dotnet build Script/Script.sln` 0/0；套件 **1 987/0 同 SHA**；
3. **语义边界**：原生父类输入 `class` 仍应放行（`Aclass`），Blueprint 父类输入 `class` 必须被拒 —— UI 交互不可自动化，按 B-18 先例记"代码级判据"。

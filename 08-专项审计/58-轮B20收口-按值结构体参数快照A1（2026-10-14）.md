## 1. 设计前提（为什么是这一处、这一条件）

### 1.1 落点唯一：`FManagedFunctionDescriptor::Invoke`

| 事实 | 证据 |
|---|---|
| UE→C# 方向只有两个调用者，且都走**同一个** `Invoke` | `FCSharpFunctionDescriptor::CallCSharp:109`、`FCSharpDelegateDescriptor.cpp:12`（委托路径**同轮一并覆盖**） |
| 地址来源只有两条：**池缓冲**或 **VM 帧 `InStack.Locals`** ⇒ "只打池缓冲补丁"不完整，必须在**索引**层判定 | `FCSharpFunctionDescriptor.cpp:44`（`Params = InStack.Locals`）、`:50`（否则 `Malloc()`） |

### 1.2 判据用**插件自己的** `ReferencePropertyIndexes`，而不是引擎标志

`FManagedFunctionDescriptor` 继承 `FFunctionDescriptor`，`ReferencePropertyIndexes` 是其 `protected` 成员（[FFunctionDescriptor.h:30](D:\file\UnrealProjects\UnrealCSharpTest\Plugins\UnrealCSharp\Source\UnrealCSharp\Public\Reflection\Function\FFunctionDescriptor.h:30)）⇒ `Invoke` **可直接复用**调用方 lambda 用的同一个集合（[FFunctionDescriptor.cpp:51-59](D:\file\UnrealProjects\UnrealCSharpTest\Plugins\UnrealCSharp\Source\UnrealCSharp\Private\Reflection\Function\FFunctionDescriptor.cpp:51)）：

```cpp
if (Property->HasAnyPropertyFlags(CPF_OutParm) && !Property->HasAnyPropertyFlags(CPF_ConstParm))
{
    if (IsNativeFunction || Property->HasAnyPropertyFlags(CPF_ReferenceParm))
    {
        ReferencePropertyIndexes.Emplace(Index);   // ← 地址来自调用方（OutParm），必须保持"视图"
    }
    OutPropertyIndexes.Emplace(Index);
}
```

- **为什么不用 `CPF_ReferenceParm` 直接判**：原生函数的 out 参数**不带** `CPF_ReferenceParm` 也会进该集合（`IsNativeFunction` 分支）—— 用标志判会与调用方 lambda 的判定**不一致**（同一索引，一边给真实地址、一边按拷贝处理）。
- **out-only（非引用）参数**落在集合外 ⇒ 也会被拷贝；其写回由既有路径（`Invoke:72-98` 用 `Set(&handle, OutAddress)` 把副本内容拷到真实 out 地址）完成 ⇒ 语义不变（改动前后 CSV 全表一致已证）。

### 1.3 只覆盖结构体（A1 的"1"）

条件里保留 `Property->IsA<FStructProperty>()`：

- 命中**已实测**的缺陷类（结构体包装器）；
- 其余复合类型（`TArray`/`TMap`/`TSet`/`FString`/委托/接口）**仍是视图** ⇒ 属**同条遗留面**，已登记触发条件（§5.1）；
- 另加 `PropertyAddress != nullptr` 守卫：`Factory` 在函数失效时会落回 `Empty` 分配器（`Malloc()` 返回 `nullptr`，G9 轮的收窄）⇒ 该退化态**保持原路径**，不引入新失败模式。

### 1.4 拥有关系沿用既有路径（不新增释放逻辑）

`PropertyDescriptor->CopyValue(PropertyAddress)` = `FMemory::Malloc(ElementSize)` ＋ `InitializeValue` ＋ `CopySingleValue`（[TCompoundPropertyDescriptor.inl:33-48](D:\file\UnrealProjects\UnrealCSharpTest\Plugins\UnrealCSharp\Source\UnrealCSharp\Public\Reflection\Property\TCompoundPropertyDescriptor.inl:33)）；`Get<FPropertyArgument::FReturn>` 走 `FStructPropertyDescriptor::Get(…, FReturn)` → `AddStructReference<**true**>(Struct, Src, Object)`（**拥有**）⇒ 该内存由 `FStructRegistry::RemoveReference` → `FoundValue->Free()` → `DestroyStruct`（非 POD）＋ `FMemory::Free` 释放（[FStructRegistry.cpp:115-141](D:\file\UnrealProjects\UnrealCSharpTest\Plugins\UnrealCSharp\Source\UnrealCSharp\Private\Registry\FStructRegistry.cpp:115)）。**这条链每个复合返回值今天都在跑**，本轮只是把参数也接上去。

## 6. 复用价值（给下一轮）

1. **"改一处还是改一类"要先分清方向**：本轮只需动 `FManagedFunctionDescriptor::Invoke` 一处，是因为"外泄"只发生在 **UE→C#** 方向（反方向本来就是 `Set` 拷贝）；先定方向再谈改动面，能省掉一多半核验。
2. **复用仓库自己的判定集合，别用引擎标志重新推**：`ReferencePropertyIndexes`（`CPF_OutParm && !CPF_ConstParm` ＋ (`IsNativeFunction` ∥ `CPF_ReferenceParm`)）与调用方 lambda 必须**同源**，否则会出现"一半按引用、一半按拷贝"的错配。
3. **判据要能判别，不能恒真**：留存断言必须配"第 2 次调用带**不同值**"（否则 2 vs 2 恒真）；这也是把它做成**永久**用例的前提。
4. **"零副作用"是可以被证明的**：`Compare-Object` 改前/改后 CSV ⇒ **仅目标行翻转**，比"套件全绿"强得多（后者会被新增行掩盖）。
5. **拥有型路径优先复用**：`CopyValue` ＋ `AddStructReference<true>` ＋ `FStructRegistry::RemoveReference` 这条链已在"复合返回值"上跑了很久 ⇒ 新场景直接接上，避免自造释放逻辑。

## 3. `F-ARCH-009` P2：优雅停止 —— 前提更正，不施工

### 3.1 设计页的前提

> "**G2** 析构强杀：`FCSharpCompiler.cpp:17` `Thread->Kill(true)`，**不调 `Stop()`**"（[`208`](208-轮B-175-T4-4-F-ARCH-009设计裁定-编译请求合并与线程退出（2026-10-29）.md) §3）

### 3.2 引擎源码事实

| 版本 | 文件 | 读数 |
|---|---|---|
| **5.6** | `Engine/Source/Runtime/Core/Private/Microsoft/MicrosoftRunnableThread.h` | `:79 virtual bool Kill(bool bShouldWait)`；**:85-88 `if (Runnable) { Runnable->Stop(); }`**；`:100 WaitForSingleObject(Thread, INFINITE)` |
| **5.0** | `Engine/Source/Runtime/Core/Private/Windows/WindowsRunnableThread.h` | `:79 Kill(bool bShouldWait = false)`；**:85-88 同一段 `Runnable->Stop()`**；`:100 同一句 `INFINITE` 等待` |

⇒ `Kill(true)` **先**走 `Runnable->Stop()`（`FCSharpCompilerRunnable::Stop()` 置 `bIsStopped` 并 `Event->Trigger()`，`Run()` 下一轮即 `return 0`）；`SyncProcess` 的取消谓词（`:353/:583` `bIsStopped || GExitPurge`）会中断正在跑的子进程。**"析构强杀、不调 Stop"不成立。**

### 3.3 为什么原 P2 方案反而危险

设计页 C：`Runnable->Stop()` → `Thread->Kill(false)` → `WaitForCompletion()` 加超时兜底。问题在 `Kill(false)`：

```cpp
// MicrosoftRunnableThread.h:90-113
if (bShouldWait == true) { WaitForSingleObject(Thread, INFINITE); }
CloseHandle(Thread); Thread = NULL;   // 不等待也照样关句柄
```

⇒ `Kill(false)` 返回后线程可能仍在跑；析构函数紧接着 `delete Thread; delete Runnable;` ⇒ **UAF**。而**带超时的等待**在引擎 API 层不存在（`WaitForCompletion` 也是 `INFINITE`）。

### 3.4 裁定

**P2 不施工**。残余（登记，不修）：析构等待无上界——若编译线程卡在不可取消的步骤，析构会阻塞；这是 `FRunnableThread::Kill(true)` 的 API 形态决定，**没有不动公开面的小修法**。触发条件 = 将来若引入"带超时的可取消等待"（自定义 `FRunnable` + `FEvent` 轮询，需自己接管线程生命周期），再单独立项。

## 10. 边界

1. **`F-CS1-002` P2 的口径偏离**：设计页写 `AllocStrong/AllocWeak/AllocPinned`，实际只落 `Alloc/AllocWeak`（理由见 §1.2）——若维护者要求"三件套齐全"，补 `AllocStrong` 即可（1 行别名），但会产生同义双名与"无独立消费者"的取舍。
2. **生成物未重跑**：本轮不改生成器，`Script/Game/Proxy`、`Script/UE/Proxy` 的 `HandleData.Alloc(InObject)` 原样保留（仍强句柄）；未做产物 manifest 对账（无生成器改动）。
3. **`F-ARCH-009` 的"等待无上界"未构造现场**：结论来自 5.0/5.6 源码逐行对照与 `Kill(false)` 的 UAF 推演；未造"编译线程卡死 + 析构"探针（会挂死编辑器）。
4. **`F-CS2B-011`**：`await` 计数为静态 grep；若将来有 generated 代码引入 `await`，触发条件成立。
5. **未跑 Mono/LeanCLR**：本轮改动为 C# 运行库与一个 Editor 模块的 C++ 谓词，仅 CoreCLR 实跑；5.0 只做编译门禁。

### 1.2 `F-CS2B-021` —— 泛型无约束、无判空

`Script/UE/CoreUObject/DataTableFunctionLibrary.cs`（HEAD `8a28ec7f`）：

```csharp
public static bool GetDataTableRowFromName<T>(UDataTable Table, FName RowName, out T OutRow)
{
    return UDataTableFunctionLibraryImplementation
        .UDataTableFunctionLibrary_GetDataTableRowFromNameImplementation(
            HandleData.GetHandle(Table), HandleData.GetHandle(RowName), out OutRow);
```

- 无泛型约束 ⇒ `<int>`、`<UObject>` 都能编译（后者在运行期由 `(T)HandleData.GetObject(...)` 抛 `InvalidCastException`，前者是拆箱路径）。

## 4. 边界与残余

1. **`false` 仍是二义**：`GetDataTableRowFromName` 无法区分"行不存在"与"句柄无效/表为空"；改返回 `T?`/`(bool, string)` 属 API 变更（T4），本轮不做。
2. **行类型未与 `Table.RowStruct` 交叉校验**：`<FVector>`（合法 `IStaticStruct`，但不是该表的行结构）仍会在 `(T)` 转换处抛 `InvalidCastException`。可在 C# 侧比较 `Table.RowStruct` 与 `T.StaticStruct()` 后返回 `false`，但那要引入"结构体标识比较"的语义裁定，留待后续。
3. **`Identical` 的行为变更**：两个 `new TScriptInterface<T>((T)null)` 改前在 `Identical` 下返回 **1**（都包装 nullptr），改后返回 **0**（都未登记）。这是"登记空接口"缺陷被消除的必然结果，已在套件层面确认无既有用例依赖。
4. **C# 侧仍会分配一个弱句柄**：`TScriptInterface_RegisterImplementation` 先 `HandleData.Alloc(this, true)` 再调原生；早退只影响原生登记表，C# 的弱句柄随对象回收（`ConditionalWeakTable`），未观察到登记表增长。
5. **未测**：`GetDataTableRowFromName<T>` 的**成功路径**（语料里没有 `UDataTable` 资源），本轮只覆盖约束与早退；成功路径依赖既有原生实现，行为未变。
6. **只测 Windows / UE 5.6 / CoreCLR**。

## 7. 过程事实（装置坑）

1. **C# 编译级 A/B 必须"先建后删"**：改前先用临时文件跑一次 `Build succeeded`，改后同一文件应报约束错误，最后删文件再跑 0/0 —— 三次 `dotnet build` 分别对应三种状态，缺一条就无法证明"约束确实缺失过"。
2. **`write` 工具写 C# 会改掉 EOL 与文件末尾**：`DataTableFunctionLibrary.cs` 原是 **CRLF + 无末尾换行**，直接覆盖会变成 LF 且多出末尾换行（diff 从 `+8/−0` 膨胀成整文件）。已按原样归一（CRLF、去末尾换行），最终 diff 才是干净的两处。
3. **C++ 探针的清理要连 include 一起**：`HAL/IConsoleManager.h` 与探针块同进同出，否则会留下"无引用的 include"（§8 不查、但属噪声）。

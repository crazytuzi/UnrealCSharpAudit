## A. `F-DEF-003` —— 三后端 `Initialize()` 失败的可见性

### A.1 事实（回 HEAD 复核，均未变）

| # | 事实 | 锚点 |
|---|---|---|
| A1 | `IScriptDomain::Initialize()` 返回 **void**；另有 `virtual bool IsInitialized() const = 0` | `Source/UnrealCSharpCore/Public/Domain/Script/IScriptDomain.h:18`、`:81` |
| A2 | 三个后端的失败路径全部是**裸 `return`**，三文件 `UE_LOG` 计数 **0 / 0 / 0** | `FCoreCLRDomain.cpp`、`FLeanCLRDomain.cpp`、`FMonoDomain.cpp` |
| A3 | 失败**可观测**：`FScriptDomainScope` 已用 `IsInitialized()` 分支；失败被第二个 `if` 静默吞掉 | `FScriptDomainScope.h`；`FDomain.cpp` 的 `Initialize()` 不检查状态 |
| A4 | **Mono 的 `IsInitialized()` 语义特殊**：它是"程序集文件存在"，不是"初始化成功" | `FMonoDomain.cpp:318`（`bIsInitialized = IsAssembliesFileExists(InAssemblies);`） |
| A5 | **运行期没有后端类型查询器**：唯一的 `GetScriptDomainType(PlatformName)` 在 `#if WITH_EDITOR` 内 | `FUnrealCSharpFunctionLibrary.h:289-292` |

### A.2 为什么不能小改（B-213 已施工尝试并否决，事实保留）

1. **补日志**撞 G7（日志/断言/throw/新公开面全封死）；
2. **回滚半初始化域**（原设计页方案 C）被 A4 ＋ A5 否决：一个"初始化成功但工程尚无程序集"的 Mono 会话会被判失败 ⇒ 回滚丢掉已建成的域 ⇒ 下次经工厂**重复 `mono_domain_create`**；且运行期无法只对 CoreCLR/LeanCLR 回滚；
3. 要落地必须先给 `IScriptDomain` 加"初始化是否成功"的能力查询 ⇒ **新增纯虚方法 = 新公开面** ⇒ 撞 G7。

### A.3 契约条款（**生效**）

| 条款 | 内容 |
|---|---|
| **C-DEF-1** | `Initialize()` **失败** ⇒ 该后端 `IsInitialized()` 返回 `false`（CoreCLR/LeanCLR）。调用方**不得**以"`Initialize()` 没抛/没返回错误"推定成功。 |
| **C-DEF-2** | **三后端 `IsInitialized()` 语义不同**（Mono = 程序集文件存在）。任何跨后端复用的判据**必须**先声明"目标后端"，禁止把它当统一的"初始化成功"标志。 |
| **C-DEF-3** | `FScriptDomainScope` 的"第一个 `if` 尝试初始化、第二个 `if` 决定是否执行函数体"是**既有的失败表达**；失败时函数体不执行且**无诊断**（受 G7 约束，非缺陷）。 |
| **C-DEF-4** | 要"调用方感知失败" ⇒ 走设计页 [`249`](249-设计页-F-DEF-003三后端初始化失败的可见性（2026-11-02）.md) **方案 B**（E2 只读 getter，**必须有真实调用方**）；要"失败原因" ⇒ 方案 D（接口变更，需先开 G7 口子）。 |
| **C-DEF-5** | 三个域实现文件里的 `UE_LOG` 计数保持 **0** 是**当前口径**，不是遗漏；新增诊断必须走"Roslyn 诊断码 / MSBuild `WriteError`"这类既有先例。 |

### A.4 归档类别与触发条件

- **归档类别**：**不适用（纯契约 · 维护者口径 2026-11-02）**。保留编号与全部事实，**不写"已修"**。
- **触发重估**：① 出现"初始化失败但无人察觉、且排查耗时"的实证；② G7 放开"新公开面"（届时上方案 B／能力查询 ＋ 方案 C）；③ 三后端 `IsInitialized()` 语义被统一（`F-DOM-007` 的邻居问题）。

## B. `F-CMP-014` —— `DotnetVersion` 可选 `V8`/`V9` 的产品口径

### B.1 事实（回 HEAD 复核）

| # | 事实 | 锚点 |
|---|---|---|
| B1 | 捆绑运行时**只有 10.0.x**：CoreCLR `10.0.4`、LeanCLR `10.0.4`、Mono `10.0.1` | `Source/ThirdParty/CoreCLR/CoreCLR.Build.cs:13-17`、`LeanCLR.Build.cs:11-15`、`Mono.Build.cs:13-15` |
| B2 | 设置项是 `UPROPERTY(Config, EditAnywhere)`，枚举提供 **V8=8 / V9=9 / V10=10 / Latest** | `UnrealCSharpSetting.h:190`、`:66-71` |
| B3 | 设置值**直接决定**所有 C# 工程的 TFM：`GetDotnetVersion()` → `ReplaceTargetFramework()` → `<TargetFramework>net%d.%d</TargetFramework>` | `FUnrealCSharpFunctionLibrary.cpp:1530-1540`（`:1539` 是 `Latest-1`）、`FSolutionGenerator.cpp:285-295`（`:289`） |
| B4 | **默认** `Latest` ⇒ 主版本 **10**，与捆绑运行时一致（默认配置无缺陷） | 同上 |
| B5 | `.csproj` / `Shared.props` **每次生成都覆盖**（`CopyTemplate` 默认 `bReplaceExistingFile=true`；唯一例外 `Game.csproj`）⇒ 改回设置后**跑一次生成器**即可重写 TFM；但生成器**不在启动路径上** | `FSolutionGenerator.cpp` / `.h:11/15`、`:141/151` |
| B6 | 跨主版本 roll-forward **默认不允许**（.NET 运行时行为，本机未实测） | 本条置信度 = 中（沿用原报告） |

### B.2 产品口径（**维护者 2026-11-02 裁定：保留现状，只写契约**）

> **口径一句话**：插件**只保证与其捆绑运行时同主版本（10.x）的产物可运行**；`V8`/`V9` 是**保留的历史选项**，选它之后产物的可运行性**不由插件保证**。

| 决策 | 结论 | 理由 |
|---|---|---|
| 移除枚举值 `V8`/`V9` | ❌ 不做 | 会让既有工程 ini 里的值变成非法枚举（UE 反序列化落警告 + 静默回默认），破坏面大于收益 |
| 生成时钳制到 `10.x`（`min(设置, DOTNET_MAJOR_VERSION)`） | ❌ 不做 | 静默改写用户意图（违背"失败收敛到既有值域"的可解释性），且掩盖了配置错误 |
| 分发 .NET 8/9 运行时或要求用户自备 | ❌ 不做 | 属产品扩张，包体与支持面成本最高 |
| **保留选项 ＋ 契约说明** | ✅ **采用** | 0 行代码；把"不支持"写成显式约定，触发时再重估 |

### B.3 契约条款（**生效**）

| 条款 | 内容 |
|---|---|
| **C-CMP-1** | **受支持组合 = `Latest` / `V10`**（二者都产出 `net10.0`，与捆绑运行时一致）。其余取值属"高级选项 / 不受支持"。 |
| **C-CMP-2** | 用户选择 `V8`/`V9` 后，**必须自行提供对应主版本运行时**（安装 8/9，或用 `DOTNET_ROLL_FORWARD=Major` 等显式策略）；插件不随包分发、也不检测。 |
| **C-CMP-3** | 改了 `DotnetVersion` 之后**必须手动跑一次生成器**（工具栏 / `UnrealCSharp.Editor.Generator` / cook）才会重写 `.csproj` 的 TFM；`Game.csproj` 仍旧"只在缺失时写"。 |
| **C-CMP-4** | `Latest - 1` 这个"枚举末项减一"的约定（`F-CMP-015`，P3）**继续有效但脆弱**：任何新增枚举值都必须同步核对 `DOTNET_MAJOR_VERSION`，否则 TFM 与捆绑运行时脱钩。 |
| **C-CMP-5** | 本条**不**新增任何运行期检测/日志/断言（G7）；"选了不支持的版本"不会被诊断，属于**已接受的取舍**。 |

### B.4 归档类别与触发条件

- **归档类别**：**不适用（产品口径 · 保留现状，维护者裁定 2026-11-02）**。保留编号与全部事实，**不写"已修"**。
- **触发重估（任一命中则重开）**：
  1. 出现"用户选 `V8`/`V9` ⇒ 运行期 `You must install or update .NET` / 程序集加载失败"的**实证**；
  2. 决定支持旧 TFM（届时必须分发 8/9 运行时或强制自备，属产品变更）；
  3. `F-CMP-015`（`Latest-1`）被改动 —— 两条同一处数据源，必须一起处理；
  4. G7 放开"配置校验的新出口"（届时可把非法组合变成可见诊断）。

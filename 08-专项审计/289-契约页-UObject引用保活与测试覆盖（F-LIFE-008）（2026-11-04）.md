## 2. 契约

| 条款 | 内容 |
|---|---|
| **C-REF-1** | `AddReference`/`RemoveReference` 是**显式 opt-in**：插件**不会**在创建句柄/包装对象时自动保活；用户必须按"一次 Add 配一次 Remove"使用（`AddUnique`/`Remove`，按 UObject 去重）。 |
| **C-REF-2** | `ObjectArray` 的生命周期 = `FReferenceRegistry` 的生命周期：域卸载（`FCSharpEnvironment::Deinitialize()` 删除 registry）时整体 `Empty()` ⇒ **跨域不残留**；但**域内** Add 后未 Remove 的对象会一直保活到域卸载（`TObjectPtr` 强引用，GC 不回收，且无任何日志/断言 —— G7 封死新出口）。 |
| **C-REF-3** | `AddToRoot`/`RemoveFromRoot`（`FRegisterObject.cpp:141/142`）是**另一条独立**的保活机制，与 `ObjectArray` 不互相替代；同一对象两条都使用时须**各自**配对。 |

- **可达性：活跃 → 潜伏**（依据：插件内部 0 调用、套件 0 覆盖；唯一入口是用户 C# 代码）。
- **覆盖缺口（如实登记）**：1 991 例套件**不覆盖**这条路径 ⇒ 任何"`ObjectArray` 单调增长"的回归**不会**被现有套件发现。触发时需要专门探针（§4）。

## 4. 探针配方（本轮形态，可复用）

1. 在 `FReferenceRegistry::AddReference(UObject*)` / `RemoveReference(UObject*)` 内计数，并按 `(adds + removes) % 100 == 0` 打 `[b254] add|remove num=%d adds=%d removes=%d miss=%d`（`num` = `ObjectArray.Num()`，`miss` = `ObjectArray.Remove` 返回 0 的次数）。
2. 跑 `run-batch.ps1`（或含 `AddReference` 用户代码的工程会话），从会话日志 grep `[b254]`。
3. 判据：`num` 单调增长且 `adds` 明显大于 `removes` ⇒ 保活泄漏；`miss > 0` ⇒ 用户 Remove 未配对（对象已不在保活表）。

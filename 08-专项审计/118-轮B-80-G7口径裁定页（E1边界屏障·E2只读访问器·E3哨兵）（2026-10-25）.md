## 2. 逐条（事实 → 撞哪条 → 收益/代价 → 退路）

### 2.1 `F-REFL-004`（P2·2.71）—— **不需要例外**：用既有状态通道

**HEAD 事实**：`FReflectionRegistry::Initialize()` `:21-874`；全文件 `GetClass(` 共 **288** 处（B-73 口径 = 32 核心 ＋ 256 attribute 的赋值），其中单行 `= GetClass(` 形态 **285** 处；全文件 `UE_LOG|check(|ensure(|checkf(` **0**；`GetClass(NS,Name)` `:961-983`，未命中 `:983 return nullptr`。调用点 3 处：`FCoreCLRDomain.cpp:208`、`FLeanCLRDomain.cpp:797`、`FMonoDomain.cpp:167`。

**关键时间序（本轮新读）**：`FCoreCLRDomain.cpp:128` 先把 `bIsInitialized = true`，`:208` 才调 `Initialize()`；而 `:185` 的 `if (TypeBridgeGetFunctionPointerFn != nullptr)` 一旦为假，**整段（含 `:208`）被跳过** ⇒ 注册表零初始化而域自称已初始化。B-28（`F-CS1-040`）的 fail-closed 只覆盖了 `RegisterBinding()` 那一侧。

**为什么不需要例外**：既有状态通道已经存在且**已被消费方尊重** —— `IScriptDomain::IsInitialized()`（`FCoreCLRDomain.h:83` 等）← `FDomain::IsLoadSucceed()`（`FDomain.cpp:105-112`）← `FClassRegistry.cpp:265` / `FDynamicRegistry.cpp:60`。缺的只是"注册表失败时把既有状态翻成 false"。

**零例外修法（推荐）**：
1. 新增**私有头**（先例：`Private/Domain/Interop/FRegisterForceInit.h`、`FRegisterObjectFlags.h` —— 全仓私有头目前 2 个），内联一个 `bool IsReflectionRegistryComplete()`：对 **32 个核心类**逐个 `FReflectionRegistry::Get().GetClass(NS, NAME)` 判非空；
2. 三个域的 `Initialize()` 之后各加 6 行：`if (!IsReflectionRegistryComplete()) { bIsInitialized = false; }`；
3. 零新公开 API、零日志、零 `try-catch`、零断言 —— **逐条落在 Q2 白名单内**（"既有取值域"= 既有 `bool` 状态）。

**判据**：临时把一个 C# 核心类改名（如 `TArray` 的脚本名）⇒ 改前 `IsLoadSucceed()` 全程 **true**（域"说谎"）、套件照跑；改后 **false**，`FClassRegistry`/`FDynamicRegistry` 的消费路径按既有语义降级。恢复后复跑同 SHA。

**代价**：32 次字符串查表（启动期一次性，微秒级）；私有头是新文件但**不在 `Public/`**。

### 2.2 `F-CS2B-026`（P2·2.63，半修）—— **只卡 E1**

**HEAD 事实**：`Utils.cs` 5 个入口 `:622/:636/:684/:716/:733`；3 处可空解引用已由 B-79 修掉；全文件 `catch` 仅 `:36/:102` 两处，且都只捕 `ReflectionTypeLoadException`。

**判据**：注入一个 `[UClass]` 带 `null` 实参的 attribute ⇒ 改前 CoreCLR 进程消失、改后套件继续且该类型元数据缺失（0 条属性）。

### 2.3 `F-ABI-037`（P2·2.63）—— **只卡 E1**

**HEAD 事实**：`TypeBridge.cs:459` `System.Type.GetType(InFullName, throwOnError: false, ignoreCase: false)`；`throwOnError:false` 只抑制"找不到"，**不抑制名字语法非法**（`ArgumentException`）。

### 2.4 `F-ABI-007`（P2·2.63，半修）—— **E1 ＋ E3**

**HEAD 事实**：`FieldBridge.cs:22-32` `GetStaticValue` 无屏障；`:59-67` `FieldToLong`（B-79 已补 `ulong` 分支）。`GetStaticValue` 用 `0` 同时表示"字段不存在"和"字段值就是 0"。
**撞哪条**：`try-catch`（屏障）＋ **值域**（`0` 双义不是"既有取值域"问题，是"该域本身有歧义"）。
**E3 提案**：为"字段不存在"约定一个保留值（如 `long.MinValue`），并在 C#/C++ 两侧成对声明 —— 属 Q2 的"既有取值域"扩展，但需要**值域证明**（合法字段值域不含该值）。
**判据**：对一个"值恰为 0"的静态字段读回 ⇒ 改前与"不存在"不可区分、改后二者可区分。

### 2.5 `F-DEL-016`（P3·2.63）—— **E2 只能解一半**

**HEAD 事实**：`DelegateHandler.cpp:90-97`：`GetUObject()` 返回 `ScriptDelegate->GetUObject()`（即桥对象自身）、`GetFunctionName()` 返回固定 `CSharpCallBack`；绑定点 `:62`。真正的 C# 目标在 `FDelegateWrapper::Object/Method`，**无 getter**。
**撞哪条**：**公开面**（重命名 ＋ 新增 getter 双撞）。
**E2 只解锁**："新增只读 getter（`GetTargetObject()`/`GetTargetFunctionName()`）"，**不改名** ⇒ 命名误导仍在，但调用方第一次有了自证手段。
**判据**：对同一委托断言 `GetTargetObject() != GetUObject()`（后者是桥对象）。

### 2.6 `F-PROP2-006 (04b)`（P2·2.71，已撤下）—— **不推荐开口**

**事实**：`FRegisterText.cpp` 的 `FText→C#` 走 `ToString()`（显示串），往返丢 key/namespace；B-74 实测改 `WriteToBuffer` 会打红既有 `TextToString` 契约用例。
**撞哪条**：新增序列化 API（公开面）。
**为什么不推荐**：E2 只开"只读 getter"，**不开"新 API"**；而改 `ToString` 语义是**改既有契约**（比新增更贵）。⇒ 维持现状，等"FText 序列化"成为真实需求再说。

## 3. 三类例外提案（措辞可直接进 `_CONVENTIONS` §8.1-A①）

### E1 边界屏障（推荐：**开口，但收窄**）

> **允许**在 `[UnmanagedCallersOnly]`（含 `CallConvs` 变体）的函数体内新增 **一层** `try { 原函数体 } catch (Exception) { return <该函数既有的失败值>; }`。
> **必须同时满足**：① `catch` 内**不得**新增日志 / 断言 / `throw` / 公开 API；② 返回值必须落在该函数**既有**的失败取值（`0` / `InvalidManagedHandle` / `default` / 空数组），不得新增错误码；③ 只允许一层，不得嵌套或 `when` 过滤；④ `try` 必须覆盖**整个**原函数体，不得部分包裹。
> **不覆盖**：`ensure`/`check`（Shipping 崩溃面，B-73 判例维持）；`UE_LOG`（既有诊断通道已够）；`throw`；公开面。

**为什么值得开口（一句话）**：CoreCLR 上"托管异常穿出边界 = fail-fast 终止进程"，而 E1 把它**收敛回该函数本来就有的失败返回值** —— 这不是给产品加新出口，而是补上"既有取值域"在**异常路径**上的缺口；且 E1 一旦成立，3 条 P2 同时解锁。

**风险与护栏**：① "空 catch"会吞掉错误 —— 护栏是"返回值必须可区分失败"（E3 管）；② 可能被复制到非边界函数 —— 护栏是"只准 `[UnmanagedCallersOnly]` 函数体"这条机械可查的判据（`grep 'catch ('` 出现在非边界函数即 FAIL）。

### E2 只读访问器（推荐：**只开"新增只读 getter"**）

> **允许**在导出类上**新增只读访问器**（`const` 或只读语义，返回**既有成员**的值，无副作用、不分配）。**不得**重命名 / 删除 / 修改既有签名 / 新增可写 setter。

**适用**：`F-DEL-016` 的一半；`F-REG2-011` 的"想知道注册表是否为空"之类**观测需求**。
**不适用**：`F-PROP2-006 (04b)` 的序列化 API（它改变的是值语义，不是观测）。

### E3 极端值哨兵（推荐：**采纳一个，按条目逐例**）

> **允许**为"返回整数/句柄的跨语言函数"定义一个**保留哨兵值**，条件：① 必须给出**值域证明**（合法值不覆盖该值）；② C# 侧与 C++ 侧**成对声明**同名常量；③ 只允许一个哨兵，不得一个函数两个。

**适用**：`F-ABI-007` 的"字段不存在 vs 值为 0"。

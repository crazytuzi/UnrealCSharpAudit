### 1.3 🔴 `F-FL-016`：报告原文一处前提被实测否定（本轮最重要的事实更正）

- 原文（[`02-…/07`](../02-UnrealCSharpCore核心/07-函数库宏与模板Trait.md) `F-FL-016`）称"当前实例化的 `T` 是自由函数/静态成员函数指针（`&TFunctionBuilder<…>::Invoke`），所以现在成立"，并自注**未穷尽验证**；
- **本轮实测（UBT 报错原文）**：按报告建议写 `reinterpret_cast<void*>(InFunction)` 后，**首次构建即失败**：
  ```
  FClassBuilder.inl(15,65): error C2440: 'reinterpret_cast': cannot convert from 'T' to 'void *'
        with [ T=const void * ]        note: Conversion loses qualifiers
  … 模板实例链：TBindingClassBuilder<T,true> → TClassBuilder<T,true>::Constructor(const void* InMethod, …)
                → FClassBuilder::Function<const void *>(…)
  ```
- ⇒ `T` 的**四类**实际取值：**函数指针**（`decltype(&…::Invoke)`、`&FVector::Zero` 等）、**`void*`**（`BINDING_*` 宏的展开结果）、**`const void*`**（`Constructor(const void* InMethod, …)` 一族，`TClassBuilder.inl:34/44`）、**`std::nullptr_t`**（`BINDING_READONLY_PROPERTY` 传 `nullptr`，`Macro/BindingMacro.h:257/:259` —— ⚠️ **该类在 MSVC 下被宽松接受、在 clang 下被正确拒绝**，交付后由维护者的 **Android (ASTC) 打包**暴露，见 **§7 补丁 1**）。
- 🔴 **交叉核对缺口（本轮教训）**：审计库 [`01-…/08`](../01-UnrealCSharp运行时/08-绑定层公开头文件（模板元编程）.md)（`F-ABI-004`）**第 836/846/860 行**早已写明"`FClassBuilder.inl` 会对 `decltype(InSetMethod) = std::nullptr_t` 实例化 `TFunctionPointer<std::nullptr_t>`（`BINDING_READONLY_PROPERTY` 传 `nullptr`）"并建议"给 `BINDING_READONLY_PROPERTY` 显式传 `static_cast<void*>(nullptr)`" —— 本轮只数了**调用点**（19 处）而没列**实例化类型**，也没做跨报告 `nullptr_t` 检索 ⇒ 见 §6-8 的方法学更正。
- **推论**：报告"改用标准工具"的方向正确，但**写法必须同时覆盖四类**；`if constexpr (std::is_null_pointer_v<T>)` ＋ `const_cast<void*>(reinterpret_cast<const void*>(…))` 对四类都成立：函数指针 →（实现定义、MSVC/GCC/Clang 均支持）`const void*` → `void*`；`void*` → 加 const 再去除；`const void*` → 先 identity 再 `const_cast`；`std::nullptr_t` → 走 `nullptr` 分支。
- **同时它仍是编译期守卫**：成员函数指针 → `reinterpret_cast<const void*>` **ill-formed**（§3.1 实测 C2440）⇒ 不需要额外 `static_assert`。

### 1.4 为什么最终形态是"一次显式转换"而不是"union ＋ 断言"

| 候选 | 取舍 |
|---|---|
| **`void* Value;` ＋ ctor 内 `if constexpr (std::is_null_pointer_v<T>)` / `const_cast<void*>(reinterpret_cast<const void*>(InFunction))`（采用，含补丁 1）** | ① **消除 UB**：不再"写一个 union 成员、读另一个"（原文问题 1）；② **根除报告问题 2 的一半**：成员函数指针**编译期**被拒（实测 C2440），而不是"读出前 8 字节、静默错"；③ **四类 `T` 统一处理**（§1.3）——`std::nullptr_t` 走独立分支（改前那版"单表达式"写法只在 MSVC 通过，clang 拒绝 ⇒ §7）；④ **零新增惯用法**（`if constexpr` 是本库既有 C++17 基础设施，见 `TArgument.inl` 等） |
| 报告建议的 `static_assert(std::is_pointer_v<T> && std::is_function_v<…>)`（**未采纳**） | ① **前提已不成立**：`T` 允许 `void*`/`const void*` ⇒ 该断言会**误伤既有实例**；② 插件自有代码（514 文件，排除 `ThirdParty`）`static_assert` 计数 = **0** ⇒ 不新增惯用法；③ 约束已由语言强制（`reinterpret_cast` 对成员函数指针 ill-formed），断言只改善报错文案 |
| 保留 union ＋ 只加 `static_assert(sizeof(T) == sizeof(void*))` | ❌ 不消除 UB（原文问题 1 仍在），且对成员函数指针仍会**静默错**（`sizeof` 在 MSVC 单继承下恰好 = 8，断言通过） |
| 提供 `GetPointer()` 并保留原指针成员 | 多一层 API、13 个读点仍要改；收益仅"保留 `T`"（无人使用该信息） |

### 7.2 改法（补丁 1）

```cpp
	explicit TFunctionPointer(const T& InFunction)
	{
		if constexpr (std::is_null_pointer_v<T>)
		{
			Value = nullptr;
		}
		else
		{
			Value = const_cast<void*>(reinterpret_cast<const void*>(InFunction));
		}
	}
```
- **语义与旧 union 版一致**（`nullptr_t` → 空 `void*`）：该结论由**产物级**证据支持 —— `InSetMethod != nullptr` 决定是否生成 C# 写访问器（`FBindingClassRegister.cpp:95`），而全量产物 manifest 与 B-23 **0 差异**（342 个 `EKeys` 只读属性仍无 setter）⇒ 空指针判定未变。
- **未采纳** F-ABI-004 的备选"给宏传 `static_cast<void*>(nullptr)`"：那只修宏这一条路，用户直接写 `.Property("X", GetFn, nullptr)` 仍会踩；本修法把 `nullptr_t` 收进 `TFunctionPointer` 本身 ⇒ 覆盖所有调用方。
- 类型约束仍 fail-loud：`std::nullptr_t` 以外、`reinterpret_cast` 不可转换的类型依旧**编译期报错**。

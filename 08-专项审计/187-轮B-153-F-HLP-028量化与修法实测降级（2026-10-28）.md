## 2. 修法实测（两版，均未通过）

| 版本 | 做法 | 读数 | 结果 |
|---|---|---|---|
| v1 | `FScriptSetHelper(ElementProp, ScriptSet, ScriptSetLayout)` ＋ `FindElementIndexFromHash`/`AddElement`/`RemoveElement` | **Add 1.288 ms / Contains 0.716 ms** | **确定性崩溃** `0xC0000005`（连续两次，无 CSV） |
| v2 | `CastField<FSetProperty>(descriptor->GetProperty())` 后建 helper | Add 0.734 / Contains 0.404 ms，但 `sum = 0` | **静默失效**：`ElementPropertyDescriptor` 里存的是**元素属性**，`CastField<FSetProperty>` 恒失败 ⇒ 全部 no-op |

**根因**：
1. `FScriptSetHelper::AddElement` 内部用 `CopySingleValueToScriptVM` 与自带 desturct lambda；插件原路径用 `FPropertyDescriptor::Set` / `DestroyValue`。对引用/结构体元素两者**不等价**，导致所有权/引用计数错乱 ⇒ 后续测试 AV。
2. helper 的 `(const FSetProperty*, const void*)` ctor 需要 `FSetProperty`，但 `FSetHelper` 只持有**元素属性**（`FSetHelper` 的 `InProperty` 就是 `ElementProp`，layout 由元素 size/alignment 现算）——无法直接取到 `FSetProperty`（其 `ElementProp`/`SetLayout` 是 private，仅 `FScriptSetHelper` 友元）。

**安全修法（下轮方案，已验证 API 存在）**：

```cpp
ScriptSet->Add(InValue, ScriptSetLayout,
    [this](const void* E) { return ElementPropertyDescriptor->GetValueTypeHash(E); },
    [this](const void* A, const void* B) { return ElementPropertyDescriptor->Identical(A, B); },
    [this, InValue](void* New) { ElementPropertyDescriptor->Set(InValue, New); },
    [this](void* E) { ElementPropertyDescriptor->DestroyValue(E); });
```

`FScriptSet::Add/FindIndex`（`Containers/Set.h:1965/1998`）是公开模板 API，可保留描述符的 copy/destroy 语义**同时**增量维护哈希；`Contains`/`Remove` 改用 `FindIndex`（`Remove` 仍走 `DestroyValue` ＋ `RemoveAt`，与现状一致）。交付前需按 §7 核对 **UE 5.0–5.8** 的 `FScriptSet::Add`/`FindIndex` 签名。

# 设计页 `F-REG2-009` —— 注册表裸指针所有权与 `TMapping::Add` 的覆盖语义（2026-10-31）

> **来源**：[`09-问题清单/01`](../09-问题清单/01-全局问题总表.md) 的 `F-REG2-009` 行（P2 · S=2.46 · 潜伏）；[`06`](../09-问题清单/06-P2开放队列（2026-10-28）.md) F 组。
> **性质**：**设计页（0 代码）**。
> **一句话结论**：`TMapping::Add` 的覆盖语义真实存在（`TMap::Add`，`TMapping.inl:27-30`），承载裸指针/内嵌所有权的映射成员共 **21 个**；但**同键重复写在当前调用链不可达** —— 键是当次 `NewObject` 新铸的 `IManagedHandle`（幂等且单调），或写前有地址索引 `Find` 挡着，且这些写入都只发生在对象构造期一次。`FBindingRegistry` 是**唯一**做了"Find ＋ 删旧 ＋ Add"的注册表（`FBindingRegistry.inl:21-31`），可作为将来施工的样板。**处置 = 不施工**：把"`Add` 前必须 Find/释放"写成契约（§6），并登记触发条件（§8）。

## 1. `TMapping::Add` 的语义

```cpp
// Source/UnrealCSharp/Public/Registry/TMapping.inl:27-30
	auto Add(const KeyType& InKey, const ValueType& InValue)
	{
		Map.Add(InKey, InValue);     // ← TMap::Add：键已存在时覆盖，旧值不释放、不返回
	}
```

派生链：`TMapping`（`TMapping.inl:4`）← `TManagedHandleMapping`（`TManagedHandleMapping.inl:7`）← `TValueMapping`（`TValueMapping.inl:12`）；容器/委托/可选三族把 `ValueType` 直接实例化为**裸指针**（`FContainerRegistry.h:19-23`、`FDelegateRegistry.h:18-20`、`FOptionalRegistry.h:20`）。

`TMapping` 其余成员：`operator[]`（`:10-16`，**不存在键会插入默认值**）、`Empty`、`Remove`、`Find`、`Contains`、`Get`。全仓**没有** `FindOrAdd`，也没有 `.Get().Add(...)` 形态。

## 4. 可达性：同键重复写为什么现在进不去

三道挡板：

1. **键是新铸的**：值表键是 `Class->NewObject(true)` 产生的 `IManagedHandle`；`HandleData.Alloc` 对同一对象幂等、句柄号单调（`Script/Interop/Handle/HandleData.cs:41-58`），而 `ObjectBridge.NewObject` 用 `RuntimeHelpers.GetUninitializedObject`，不跑 C# 构造函数（`Script/Interop/Bridge/ObjectBridge.cs:14`）⇒ 每次注册都是新键。
2. **地址侧先 Find**：`NewRef` 一律先 `GetContainerObject<T>(InAddress)`／`GetDelegateObject`／`GetOptionalObject`／`GetStringObject` 等按**地址**查（`FContainerRegistry.inl:30`、`FDelegateRegistry.inl:30`、`FOptionalRegistry.cpp:50`、`FStringRegistry.inl:33`、`FMultiRegistry.inl:33`、`FStructRegistry.cpp:58/82`、`FFieldPathRegistry.cpp:56`）；命中即返回，不再 `new` 第二个 helper。
3. **只在构造期写一次**：C# 侧唯一"重复注册"入口是公开 interop 的 `Xxx_RegisterImplementation`（同一对象二次调用会拿到同一句柄），但仓内全部调用点都在构造函数里且每对象只执行一次：`TArray.cs:19`、`TMap.cs:14`、`TSet.cs:14`、`TFieldPath.cs:11/13`、`FName.cs:29`、`FString.cs:29`、`FText.cs:31`、`TScriptInterface.cs:29-31`、`TOptional.cs:10/12-13`。

**反例**：`FBindingRegistry` 自己不信这三道挡板，写前显式 `Find` 并 `delete` 旧 wrapper（`FBindingRegistry.inl:21-31`），说明"注册表可以自己兜住覆盖"。

**结论**：覆盖语义 = **无防护但当前无触发链**（潜伏）。真正的风险是"将来新增调用方用既有 handle 再注册"：容器/委托/可选/字符串/多值/结构/字段路径会**静默泄漏旧值**，且 `AddReference` 永远 `return true`（`FContainerRegistry.inl:48-50`），失败不可见。

## 5. 路线裁定

| 路线 | 内容 | 裁定 | 理由 |
|---|---|---|---|
| **A** | 改 `TMapping::Add`：覆盖时释放旧值 | ❌ 否决 | 值类型不统一（裸指针 / 值内 wrapper / `TSet<FReference*>`），`TMapping` 不知道 `delete` 还是 `Free()`；且会改变所有族的语义 |
| **B** | 各注册表 `Add` 前统一 `Find` ＋ 释放（照 `FBindingRegistry`） | ⏸️ 暂不 | 当前无触发链 ⇒ 收益 0；而"重复注册"语义（复用还是替换）未定义，改动会引入新的所有权判断，风险非 0 |
| **C** | **只写契约 ＋ 登记触发条件**（本轮采纳） | 🟢 采纳 | 与 §4 的可达性结论一致；把"为什么现在安全"写成可复核的挡板清单 |

## 6. 契约（写进本轮设计页，供后续调用方遵守）

1. `TMapping::Add` = **覆盖且不释放旧值**；对裸指针值，调用方必须在 `Add` 前 `Find`，命中则复用或先释放旧值。
2. 值表键必须是**当次新铸**的 `IManagedHandle`；不得用"从别处读回来的旧 handle"再次注册。
3. 一个 helper 指针只能有一个 owner：正常路径由 `Remove*Reference` 释放，`Deinitialize` 兜底；被覆盖而失联的指针**没有释放点**。
4. 新注册表若需要"重复注册"语义，参照 `FBindingRegistry.inl:21-31`（`Find` → 移旧地址映射 → `delete` 旧 wrapper → `Add`）。

## 7. 相邻事实（本轮普查发现，**不取号**，避免与既有编号冲突）

1. `FOptionalRegistry::AddReference` 不向 `FReferenceRegistry` 注册 owner 级 `FReference`（`FOptionalRegistry.inl:6-19` 无 `FCSharpEnvironment::AddReference`）⇒ `FOptionalHelper` 的释放只依赖 C# `Dispose` 与全局 `Deinitialize`。与 `F-DEL-010`/`F-DEL-011` 相邻，建议归并到那两条的触发条件里复核。
2. `FStrPropertyDescriptor.cpp:14` 的 `AddStringReference<FString, false, false>` 不写地址索引 ⇒ `FString` **成员属性每次读取都新建 helper**（键不同，不是同键覆盖，但属"每次读一次分配"）。归性能类，不在本条。
3. `TMapping::operator[]`（`TMapping.inl:10-16`）对裸指针映射会**插入空值**；当前唯一非 const 使用是 `FReferenceRegistry.cpp:46`（写前有 `Contains`）。若将来有人在裸指针映射上用 `operator[]`，`RemoveReference` 的 `(*FoundValue)->GetAddress()`（`FContainerRegistry.inl:72`）会解引用空指针。

## 1. 为什么这一档是 5.2，以及"静态核查"能替代什么、不能替代什么

| 问题 | 回答 |
|---|---|
| 为什么 5.1/5.2 的实编侧特殊？ | 两点叠加：① **门控档位清点**（[`08-…/71`](71-跨版本实编点扩容-UE5.8与门控新版侧首编（2026-10-16）.md) §1）显示起点 5.1 的宏有 **44** 个（最多的一档），5.2 有 2 个；② **语言标准红线**——UE 5.0–5.2 默认 **C++17**，5.3 起才是 C++20 ⇒ 这 46 个宏的 `#if` 侧只在 5.4/5.6/5.8 编过（**C++20**），在 5.1/5.2 上既没有实编点、也换了一档语言标准 |
| 本机为什么不能真编 5.2？ | 无 5.2 引擎副本；GitHub 不可达（`git ls-remote` ⇒ `SEC_E_INVALID_TOKEN`）⇒ 无法克隆；NuGet 不可达 ⇒ 即便拿到源码也无法重建其 UBT（[`08-…/71`](71-跨版本实编点扩容-UE5.8与门控新版侧首编（2026-10-16）.md) §2.1 的读数在本轮复现）。差异：5.4/5.8 能走通是因为**本机已存在已构建的引擎副本** |
| 静态核查能给出什么 | 对实编侧引用的**每一个**引擎符号：**首个含它的 release tag**、**可见性**（public/protected/private/命名空间作用域）、**精确签名/重载集**、**是否 `UE_DEPRECATED`**（四要素在 5.1.0 与 5.2.1 上分别取）。这足以判定 C2039（成员不存在）/C2661+C2664（重载不匹配）/C2248（访问受限）/C3668（override 不匹配）这类**编译级**失败 |
| 静态核查**不能**给出什么 | ① 编译器实际诊断（§3 就是一条**反面教材**：只做"表达式级"实测会得出与真实 TU 相反的结论）；② 语言标准交互（C++17 vs C++20 的差异面**由既有的 `-Mode Syntax` 全树体检覆盖**，见 §4.3）；③ 链接期与运行期 |

## 3. `UE_F_DATETIME_PLUS`：一条**先报后撤**的失败点 ＋ 一条**真潜伏项**（`F-CV-011`）

> ⚠️ **本条是一次自我更正**，两个探针的结论**相反**，如实留档（过程见 §3.3）。

### 3.1 代码事实

`Source/UnrealCSharp/Private/Domain/Interop/FRegisterDateTime.cpp`（**插件基线工作树，未改动**）：

```cpp
52: 	struct FRegisterDateTime
53: 	{
54: 		static FDateTime PlusImplementation(const FDateTime& In, const FTimespan& Other)
55: 		{
56: 			return In + Other;                     // ← 无门控 ⇒ 四个实编点都编译这一行
57: 		}
58:
59: #if UE_F_DATETIME_PLUS                         // ← 负极性门（!UE_VERSION_START(5,1,0)）
60: 		static FDateTime& PlusImplementation(FDateTime& In, const FDateTime& Other)
61: 		{
62: 			return In + Other;                     // ← 只有 UE 5.0 侧编译（且只有它被引用）
63: 		}
64: #endif
```

**门控语义（`Source/CrossVersion/Public/UEVersion.h:18`）**：`#define UE_F_DATETIME_PLUS !UE_VERSION_START(5, 1, 0)`
⇒ **UE 5.0**：`= 1` ⇒ `:60-63` 编译，且 `:89-92` 的注册行**取它的地址**。
⇒ **UE 5.1 / 5.2**：`= 0` ⇒ `:60-63` 与注册行**都不编译** ⇒ **`PlusImplementation(FDateTime&, …)` 这个重载在本 TU 内无人引用**。

### 3.2 引擎事实（tag 实测，逐字）

| tag | `Engine/Source/Runtime/Core/Public/Misc/DateTime.h` | 结论 |
|---|---|---|
| **5.0.3** | `L136 FDateTime& operator+(const FDateTime& Other)`（**无** `UE_DEPRECATED`，**非 const 成员**） | 5.0 侧：返回引用 |
| **5.1.0** | `L132 UE_DEPRECATED(5.1, "Adding dates doesn't make sense. Please use FDateTime + FTimespan instead")` ＋ `L133 FDateTime operator+(const FDateTime& Other)` | **返回类型 `FDateTime&` → `FDateTime` 且被标记弃用**；仍是**非 const 成员** |
| **5.2.1 / 5.6.0** | 与 5.1.0 **同一对声明**（L132/L133） | 5.1–5.6 同构 |
| **5.8.3** | `git grep 'operator\s*\+\s*\(\s*const FDateTime'` = **0 命中**（该模式在 5.7+ 已不存在） | 更高版本另说（不在本轮范围） |
| 自由函数？ | `git grep` 全 `Engine/Source/Runtime/Core` 于 5.0.3/5.1.0/5.2.1/5.6.0 各只有**上面那一条**成员声明 | **不存在** `operator+(const FDateTime&, const FDateTime&)` 自由函数 |

⇒ 关键事实：**`const FDateTime& + const FDateTime&` 在 5.1.0–5.6.0 上没有可行重载**（唯一候选是非 const 成员），而 `:56` 的形参 `In` 正是 `const FDateTime&`。

### 3.3 🔴 两个探针，两个相反结论（必须并读）

| # | 探针 | 形态 | 读数 |
|---|---|---|---|
| **1** | `Saved/Retest/b32/b32-datetime-probe.cpp` —— 把 `:56` 的表达式**单独提取成被调用的函数**（`FDateTime F(const FDateTime& In, const FDateTime& Other) { return In + Other; }`），用与插件模块逐字相同的编译环境（Shared rsp ＋ Shared PCH ＋ `Definitions.*.h`，CWD = `Engine\Source`，MSVC 14.51）编译 | **表达式级** | 🔴 `error C2678: binary '+': no operator found which takes a left-hand operand of type 'const FDateTime'`（日志 `b32-datetime-probe.log`） |
| **2** | `Saved/Retest/b32/b32-datetime-probe2.cpp` —— **逐字复刻真实 TU 的形状**：同一个匿名 namespace、同样的 `struct`、同样的 `#if UE_F_DATETIME_PLUS` 门、同样的两个重载、**都不被调用** | **TU 级** | 🟢 **C2678 命中 0**；探针文件本身**零 error**（日志里 42 条 `C4141` 全部来自 Windows SDK 的 `strsafe.h`，与本探针无关；`b32-datetime-probe2.cpp` 在错误行里出现 **0** 次） |

**判读**：探针 1 证明了**"这个表达式在 5.1+ 的语义下 ill-formed"**，但它**不成立**为"插件编不过"——探针 2 证明**真实 TU 里 MSVC 不对未被 odr-use 的类内静态成员函数体做完整语义检查**（否则四个实编点早就该报错：`:56` 在 **5.0/5.4/5.6/5.8 上同样编译**，而 5.4/5.6/5.8 的候选运算符与 5.1/5.2 完全同类）。
⇒ **结论：`UE_F_DATETIME_PLUS` 的门控极性正确、5.1/5.2 无编译错误**；我在本轮中途曾据探针 1 判定"5.1/5.2 编不过（拟登记 P1）"，**该判定已撤回**。

### 3.4 真潜伏项 `F-CV-011`（P3/潜伏）

- **事实**：`:56` 的函数体在 5.1+ 语义下 ill-formed（§3.2＋探针 1）；它能编过**完全依赖"该重载在 5.1/5.2 上无人引用"**这一前提。
- **触发条件（写清以便复查）**：出现下列任一情形即**立刻变成编译错误** —— ① 有人把 `PlusImplementation(FDateTime&, const FDateTime&)` 的引用从 `#if UE_F_DATETIME_PLUS` 里挪到门外（或新增调用点）；② 有人在 5.1+ 上调用 `FRegisterDateTime::PlusImplementation(FDateTime&, const FDateTime&)`；③ 引擎在 5.7+ 恢复/新增该运算符的重载集（5.8.3 该模式已 0 命中，方向相反）。
- **建议（不施工）**：把 `:56` 写成**在两个版本都良构**的形态，代价 1 行 —— 例如 `FDateTime Value = In; return Value + Other;`（左操作数变非 const 左值 ⇒ 5.1+ 的非 const 成员可调用、5.0 的引用版亦可）；⚠️ 副作用 = 5.1+ 上引入 **C4996 弃用告警**（与本插件既有告警同级，非错误）。**是否值得改由维护者裁量**（属"防御性改写"而非缺陷修复）。
- **级别理由**：无当前可复现故障 ⇒ **P3（潜伏）**，不进 T2。

### 3.5 方法学教训（已写进 [`_CONVENTIONS.md`](../_CONVENTIONS.md) §7.3）

> **"表达式级"实测不能替代"TU 级"实测**：跨版本核查若用最小 TU 复现某个**函数体**，必须先证明该函数体在真实 TU 里**真的被实例化/odr-use**；否则会得到与真实构建相反的结论（反例 = 本轮探针 1 vs 探针 2）。**可复用的判定手法**：把待验证的**声明/定义形状逐字复刻**进最小 TU（含门控、含 namespace、含"是否被调用"），再编译。

## 1. 施工面（3 处 hunk）

| 位置（改后） | 改前 | 改后 |
|---|---|---|
| `DynamicDataSource.cpp:539-542` `CanEditItem` | `return true;` | `return GetFileItemDataPayload(InItem).IsValid();` |
| 同文件 `:553-563` `BulkEditItems` | 逐项 `EditItem(Item);`（丢返回值）→ `return true;` | `auto bIsEdited = true;` ＋ 循环内 `bIsEdited = EditItem(Item) && bIsEdited;` ＋ `return bIsEdited;` |
| 同文件 `:565-568` `CanDeleteItem` | `return true;` | `return GetFileItemDataPayload(InItem).IsValid();` |

**为什么这是"同源判据"**：`GetFileItemDataPayload`（`:793-799`）只在 `GetOwnerDataSource() == this && IsFile()` 时返回有效指针 —— 而 `EditItem`（`:544-551`）与 `DeleteItem`（`:570-613`）的**第一个守卫**正是同一个返回值（`DeleteItem` 对文件夹项在 `:578-581` 必然 `return false`）。改后 `Can*` 与两个动作函数**共用同一判据**，引擎的"能删/能编"使能与实际执行不再分叉。

**G7 对照**：新增注释 0 / 日志 0 / `throw` 0 / `try-catch` 0 / `ensure`·`check` 0 / **公开 API 0**（`Can*` 与 `BulkEditItems` 都是既有虚函数覆写，签名未动）；新逻辑为单一出口（`if(条件)` 形态不需要，直接 `return`），布尔局部量沿用仓内 `auto bXxx =` 先例（`b30-style-lint` 判 PASS）。

## 1. `F-CS1-036` —— 归档（本树 0 实例）

**原判**：`ProcessRpcMethods` 生成的 `{Name}_Implementation` 丢失泛型参数、参数名与除 `[Override]` 外的全部自定义属性，且属性位被强行改成 `Public`（P2 · S=2.80 · 活跃）。

**复核（只读）**

| 项 | 证据 |
|---|---|
| 触发条件（代码级） | `Script/Weavers/UnrealTypeWeaver.cs:849-866`：先取**同一方法**上带 `[UFunction]` 的方法，再在其中筛"同一方法上带 `[Server]`／`[Client]`／`[NetMulticast]` 之一" ⇒ 两条注释级前提缺一不可 |
| 语料普查（本工程） | `Script/**` 共 **16 424** 个 `.cs`；含 `[UFunction]`（含命名空间限定写法）**8** 个文件；含 `[Server]`／`[Client]`／`[NetMulticast]`（含限定写法）**0** 个文件；**两者同时出现 0 个文件** |
| 复跑命令 | `Get-ChildItem Script -Recurse -Filter *.cs \| Select-String -Pattern '\[(?:[A-Za-z_][A-Za-z0-9_]*\.)*UFunction\b'`（`Server/Client/NetMulticast` 同法） |

**结论**：🟢 **归档（不适用 · 无实例）**。机制成立（`:1119` 的 `new MethodDefinition(Method.Name + "_Implementation", MethodAttributes.Public, …)` 确实不复制 `GenericParameters`、参数名与其它特性），但**本树不存在可触发的语料**；且该路径属"用户声明 RPC 方法"的使用面，不是插件自身链路。

**触发条件（写入台账）**：出现**同一方法**同时带 `[UFunction]` 与 `[Server]`／`[Client]`／`[NetMulticast]` 的 C# 语料时，重跑上述普查并按本报告 §1 的锚点核对生成物。

## 2. `F-LIFE-015` —— 前提更正（留队）

**原判（B-219 §6 的复核备注）**：「2 秒上限仍在；**当前五平台全 LeanCLR ⇒ `Context` 恒 null ⇒ 该段不执行**」。

🔴 **该前提不成立**（本轮实读配置）：

| 证据 | 内容 |
|---|---|
| `Config/DefaultUnrealCSharpSetting.ini` | `WindowsScriptDomainType=CoreCLR`、`LinuxScriptDomainType=CoreCLR`、`MacScriptDomainType=CoreCLR`、`AndroidScriptDomainType=Mono`、`IOSScriptDomainType=Mono` ⇒ **不是"五平台全 LeanCLR"** |
| `UnrealCSharpSetting.cpp:18-22` | 同值的内置默认（ini 未覆盖时也一致） |
| 运行期佐证 | 套件 CSV 名为 `UnrealCSharp-**CoreCLR**-Windows-Development-…` |
| native 调用点 | `FCoreCLRDomain.cpp:257-259`：`if (AssemblyLoaderUnloadFn != nullptr) { AssemblyLoaderUnloadFn(); }`（`UnloadAssembly` 内） |
| 被调方 | `Script/Interop/AssemblyLoader/AssemblyLoader.cs:38-70`：`Context.Unload()` ＋ `WeakReference` ＋ `TimeLimit = 2000` 循环 |

**结论**：🟡 **可达性由"潜伏"改判"活跃（CoreCLR）"**，条目**留队**（P2 不变）。真实后果 = 可回收 ALC 若在 2 s 内未回收，则**永久驻留且无任何上报**（弱引用循环结束即返回，不记录"仍未回收"）。

**未取得**：`UnrealAssemblyLoadContext` 实际回收耗时的分布（需要重复卸载会话的计数探针）；`Unload()` 在三后端各自的调用频次。

## 3. `F-REFL-001` —— 数字更正（留队）

**原判**：「`Deinitialize()` 删除了全部 `FClassReflection`，却不把 **285** 个成员指针置空，留下悬垂访问器」（P2 · S=2.80 · 活跃）。

**复核（只读）**

| 项 | 证据 |
|---|---|
| 缓存成员数 | `FReflectionRegistry.h` 中 `FClassReflection* X{};` 形态共 **288** 个（含条件编译成员；报告记 285） |
| 清理面 | `FReflectionRegistry.cpp:876-886` 的 `Deinitialize()`：`Field2Class.Empty();` → 对 `FullName2Class` 的每个 `Class` `delete` → `FullName2Class.Empty();` —— **不动任何成员指针** |
| 重填面 | `FReflectionRegistry.cpp:23-57` 起的 `Initialize()` 逐个 `X = GetClass(...)` 重新赋值 ⇒ **窗口 = `Deinitialize()` → `Initialize()` 之间** |
| 消费面 | `GetInt32Class()` 等 getter 被 `TPropertyValue`／`FTypeBridge`／`FCSharpBind` 等大量调用；窗口内若有调用即读到**已 delete 的对象** |

**结论**：🟡 **留队（P2 不变）**，并把措辞从"悬垂访问器"收紧为"**窗口型悬垂**：`Deinitialize` 与 `Initialize` 之间 288 个成员全部指向已释放对象"。

🔴 **B-219 的"全插件无解引用该悬垂指针的路径"未取得证据**（本轮只核到窗口存在、消费面很宽），按新约定**不得**据此归档。

**下一步取证建议**（不属本轮）：在 `Deinitialize()` 与 `Initialize()` 之间加一次性 `ensure` 型探针（G7 禁，需走待决策页）或**只读**地用脚本核对该窗口内的调用链（`UnloadAssembly` → 各 `Reset()` → 生成器 → `GetXxxClass()`）。

> 🟢 **后续（2026-11-04 轮 B-237）**：本节 §3 的 `F-REFL-001` 已收口 —— 窗口读者复核为 0（288 个悬垂成员无可观测路径）、`IsInitialized()` 的"反初始化后仍返回 true"已修（新增私有 `bool bIsInitialized{}`，短路原判空链），288 个成员**转契约、不置空**。见 [`08-…/274`](274-轮B-237-F-REFL-001收口-反射注册表初始化标志与窗口读者复核（2026-11-04）.md)（插件提交 `72360284`）。

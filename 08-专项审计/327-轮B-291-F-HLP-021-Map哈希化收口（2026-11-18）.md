## 1. 前提翻转：G10 的"被证伪"不再成立

### 1.1 原判（2026-09-29，G10 收口轮）

归档行原文（[`05`](../09-问题清单/05-已完成（P2与P3）.md)）：「"换引擎哈希入口"的修法**被证伪**（C# 引用类型键写的是**托管句柄**、`GetValueTypeHash` 无句柄解析、引擎对**查找值**取哈希）⇒ 转独立轮次」。

### 1.2 三条理由逐条对照现状

| 原理由 | 现状 | 依据 |
|---|---|---|
| C# 引用类型键写的是**托管句柄** | **仍成立，但已不是阻塞**：句柄经 `KeyDescriptor->Set` 转成 **native scratch** 后再参与哈希/比较 | B-289 读数（[`324`](324-轮B-289-F-HLP-028探针读数与分支判定（2026-11-17）.md) §2）+ 本轮实现 |
| `GetValueTypeHash` **无句柄解析** | **成立**，所以**不能**对入参缓冲直接取哈希；本轮只对 native scratch 取哈希 | [`325`](325-契约页-容器元素原生比较语义（C-IDENT-C-HASH-C-VALUE）（2026-11-17）.md) C-HASH-1 |
| 引擎对**查找值**取哈希 | **不成立（引擎侧明确保证）**：`FindPairIndex` 的 `GetKeyHash` 只对传入 Key 调用（`Map.h:1989` 注释 "We 'know' that the implementation of Find doesn't call GetKeyHash on anything except Key"），相等谓词第二参拿到的是 **pair 指针**（key 在 offset 0，`GetScriptLayout` 有 `checkf(KeyOffset == 0)`） | 5.6 `Map.h:1982-2002`、5.0 `Map.h:1774-1796` |

⇒ **三条理由中两条已被 B-289/B-290 消解、一条本就是引擎保证** ⇒ 前提翻转，按"独立轮次"施工（本轮）。

## 2. 设计与实现

### 2.1 改动对照

| 函数 | 旧（`44fa66d8`） | 新（`f11a1072`） |
|---|---|---|
| `Set` / `Add` | 全表 `KeyPropertyDescriptor->Identical(Data, InKey)` 扫描 → 命中则 `DestroyValue(value)` ＋ `Set(value)`；未命中 `AddUninitialized` ＋ `Set(key)` ＋ `bNeedRehash = true` | `PrepareKeyBuffer`（handle → native）→ `FindPairIndex`；命中则**只**改 value（与旧语义一致：key 不重建）；未命中 `ScriptMap->FindOrAdd(scratchKey, Layout, GetKeyHash, KeyEquality, ConstructPairFn)`，`ConstructPairFn` 内 `KeyDescriptor->Set(InKey, NewKey)` ＋ `ValueDescriptor->Set(InValue, NewValue)` |
| `Get` / `Contains` / `Find` | 全表扫描 | `FindPairIndex` → `Data + ValueOffset` |
| `Remove` | 全表扫描 ＋ `EnsureRehash()`（**全表 `Rehash`**）＋ 双 `DestroyValue` ＋ `RemoveAt` | `FindPairIndex` ＋ 双 `DestroyValue` ＋ `RemoveAt`；**保留原 `do…while` 语义**（"删所有相等键"，哈希化后实际只可能 1 个 ⇒ 行为零变化） |
| `FindKey`（按值反查） | 全表扫描 | **不变**（见 §2.3） |
| `bNeedRehash` / `EnsureRehash` | 延迟重哈希机制 | **退役**（全库 grep = **0**） |

### 2.2 key scratch 与等价谓词（只做一个 scratch）

- **只分配 key scratch**：`FindOrAdd` 只收 `Key`；value 在 `ConstructPairFn(void* NewKey, void* NewValue)` 里**直接由入参句柄构造**，无需第二个 scratch。
- **等价谓词**：`FindPairIndex` 内部把 `(InKey, InPair)` 交给我们的 lambda（`Map.h:1995`），而 key 位于 pair 偏移 0 ⇒ `KeyProperty->Identical(A, B, 0)` 可直接用。
- **哈希**：查找期 `GetKeyHash(scratchKey)`；插入期必要时由 `AddNewElement → Rehash` 对**已构造的 pair** 逐个取哈希（key 在 offset 0）⇒ 两条路径语义一致。
- **scratch 生命周期**（C-SCRATCH-1 落地）：`Memzero` → `Property->InitializeValue` → `Descriptor->Set`；用完 `Descriptor->DestroyValue`；`Deinitialize` 释放。

### 2.3 `FindKey` 为什么必须保持线性（能力边界，不是缺陷）

`TScriptMap` 只对 **key** 建哈希索引（`GetScriptLayout(KeySize, KeyAlignment, ValueSize, ValueAlignment)` 只给 key 的 hash/相等留接口），**没有 value 索引** ⇒ `FindKey`（按 value 找 key）无法用哈希加速。本轮**不改**该函数，也不新造 value 反向索引（那会是新数据结构与新一致性问题）。**登记**：`FindKey` 维持 O(MaxIndex)。

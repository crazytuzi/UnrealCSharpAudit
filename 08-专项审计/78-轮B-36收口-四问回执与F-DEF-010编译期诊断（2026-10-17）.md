## 2. 方案 C 的实现（插件 `Script/SourceGenerator`，＋90 行）

### 2.1 诊断描述符（`UC_ERROR_08`）

```csharp
        public static readonly DiagnosticDescriptor ErrorSealedEventOverridden = new DiagnosticDescriptor(
            "UC_ERROR_08",
            "Sealed event cannot be overridden",
            "{0} cannot override the sealed event \"{1}\" declared in \"{2}\"",
            "UnrealCSharp",
            DiagnosticSeverity.Error,
            isEnabledByDefault: true);
```

**为什么用诊断而不是日志/异常**：Q2 白名单明确包含"**Roslyn 既有诊断** `UC_ERROR_0N`"；而日志/`ensure` 是**未开放**的开口。诊断还能把失败**前移到编译期**，与 UHT 在原生侧的行为（`UhtFunctionParser.cs:432` 置 `FUNC_Final` ＋ `UhtFunction.cs:1057-1065` 两条诊断）**对齐**。

### 2.2 检测逻辑（语法级，不依赖 SemanticModel）

```csharp
        public void ValidateSealedEventOverride()
        {
            foreach (var declarations in ClassDeclarations.Values)
            {
                foreach (var declaration in declarations)
                {
                    var baseTypeName = GetBaseTypeName(declaration);

                    if (baseTypeName != "")
                    {
                        foreach (var member in declaration.Members)
                        {
                            if (member is MethodDeclarationSyntax method &&
                                method.Modifiers.Any(SyntaxKind.OverrideKeyword) &&
                                GetAttributeFromMember(method, "UFunction") != null &&
                                HasSealedEvent(baseTypeName, method.Identifier.Text,
                                    new HashSet<string>(StringComparer.Ordinal)))
                            {
                                Errors.Add(Diagnostic.Create(
                                    UnrealTypeSourceGenerator.ErrorSealedEventOverridden,
                                    Location.Create(declaration.SyntaxTree, method.Identifier.Span),
                                    $"'{declaration.Identifier.Text}.{method.Identifier.Text}'",
                                    method.Identifier.Text, baseTypeName));
                            }
                        }
                    }
                }
            }
        }
```

- **数据来源**：`UnrealTypeReceiver.ClassDeclarations`（`名字 → 所有 partial 声明`）在 `OnVisitSyntaxNode` 阶段**收集全量**、`Execute` 阶段才校验 ⇒ 基类即使写在**另一个文件**也能查到，**不需要 SemanticModel**。
- **基类链**：`HasSealedEvent()` 递归向上（带 `visited` 防环），因此"基类没写、祖父类写了"的形态也覆盖。
- **调用点**：`Execute()` 里紧跟 `ValidateInheritanceChain()` 之后 —— 与既有校验同一位置、同一错误集合（`Errors` → `Context.ReportDiagnostic`）。

## 5. 覆盖边界（如实登记）

| 边界 | 说明 |
|---|---|
| **只覆盖"基类在同一次编译里"** | `ClassDeclarations` 只收集本编译的语法树 ⇒ 基类来自其它程序集（例如插件随包的 `UE.dll`）时**不诊断**。⚠️ 但那种基类的 `FUNC_Final` 来自 **C++ UHT**，C# 侧没有 `[SealedEvent]` 特性可继承 ⇒ **没有可达的绕过路径** |
| **只覆盖 `override`** | `new`/同名隐藏不诊断（C# 里 `new` 隐藏**不会**被反射当成 override，生成期也不会创建"覆写"语义的函数）—— 若将来出现"同名隐藏"的真实用法，另行裁定 |
| **`#pragma warning disable` / `NoWarn` 可抑制** | 诊断可被用户侧抑制；届时会回到"生成期遮蔽"。这正是 Q4 里 **D = C+B** 存在的理由（B 兜底未施工，登记为可选） |
| **未做 Roslyn driver 电池** | 判据用**真实构建 A/B**（正向 1 错、控制 0 错）替代；[`08-…/67`](67-轮B27收口-源生成器不抛半边与CodeAnalysis构建闸门（2026-10-15）.md) 的 22 例电池手法可在需要时补齐（覆盖更多语法变体：泛型基类、多级继承、`partial` 跨文件） |
| **未跑 5.0/5.4/5.8** | `Script/SourceGenerator` 由 **dotnet** 编译（netstandard2.0），**不参与 UBT** ⇒ 与引擎版本无关，不触发 [`_CONVENTIONS.md`](../_CONVENTIONS.md) §7 的三步核查。🟢 **2026-10-17 维护者裁定「直接标记任务完成」⇒ 工作面关闭、不再排期**（与 [`08-…/72`](72-跨版本实编点-UE5.2静态核查（2026-10-16）.md) §7 的 UE 5.2 同处置）；**事实面不变**：三版上仍未实编 |

## 8. 复用价值

1. **"编译期诊断"是 Q2 口径下唯一能把失败变可见的通道**：同样的语义（拒绝覆写 final），用日志/`ensure` 全部撞口径，用 `UC_ERROR_0N` 则**合规**且**前移到构建期**。
2. **诊断必须同时给"正向 ＋ 控制"两组判据**：只证"能报"会留下"处处报"的风险；本轮用两个控制形态（无 `[UFunction]` 的覆写、非 sealed 基函数）证明判据**精确**。
3. **判据会随缺陷退役**：修好之后，"强制覆写"形态**编译不过** ⇒ 记录缺陷的两条判据**必须删除**并换成诊断判据；台账要写"因修法而作废"，不能写"丢了判据"。
4. **模板 ≡ 部署副本**要做成一次**可复核的等价性判据**（替换占位符后逐行对比），否则"改的是模板、验的是副本"会成为隐患。

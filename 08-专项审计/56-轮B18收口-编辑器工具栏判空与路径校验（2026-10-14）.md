### 2.2 `F-ED2-020` ②：`Deinitialize()` 与 `Initialize()` 对称（`UnrealCSharpPlayToolBar.cpp`）

```cpp
void FUnrealCSharpPlayToolBar::Deinitialize()
{
	if (const auto ToolMenus = UToolMenus::TryGet())
	{
		ToolMenus->RemoveSection("LevelEditor.LevelEditorToolBar.PlayToolBar", "UnrealCSharpEditor");
	}
}
```

- **为什么是 `TryGet()` 而不是 `Get()`**：`UToolMenus::Get()` 在 `bHasShutDown == true` 时会**返回 nullptr**（`ToolMenus.cpp:513-524`）；而 `Deinitialize()` 的调用点就在 `ShutdownModule()`（`UnrealCSharpEditor.cpp:237-240`）⇒ 必须用引擎自己的 **null-safe 且不强制加载模块** 的入口。这也正是同文件 `:201` `UToolMenus::UnregisterOwner(this)` 的内部分支（`ToolMenus.h:123-129` 的 `TryGet` ＋ null 判断）——**沿用仓内既有形态**。
- **为什么是移除 section 而不是 entry**：`Initialize()` 既 `AddSection("UnrealCSharpEditor")` 又 `AddEntry(...)`；`UToolMenu::RemoveSection` 移除整段（含条目，`ToolMenu.cpp:382-385`），一次操作把两者都收干净，且对"段不存在"是 no-op（`UToolMenus::RemoveSection` 先 `FindMenu`，`ToolMenus.cpp:3309-3315`）。
- **不改调用顺序**：`UnregisterOwner(this)`（模块 owner 清理）在 `Deinitialize()` **之前**，本轮显式移除与该作用域**互不依赖**（幂等），故不动 `ShutdownModule()` 的顺序，避免把"对称性"扩成"重排初始化/反初始化"。
- **跨版本核查**（引擎 git tag 逐 API 比对）：`UToolMenus::TryGet` 在 **5.0.3-release / 5.1 / 5.2 / 5.3 / 5.4 / 5.5 / 5.6 全存在**；`UToolMenus::RemoveSection`、`UToolMenu::RemoveSection` 在 **5.0.3-release 即存在** ⇒ **新增 `UE_F_*` 宏 0、`#if` 0**。

### 2.3 `F-ED2-023`：`IsValidPath` 的前缀边界 ＋ 存在性（`DirectoryPathCustomization.cpp`）


## 4. 唯一发现：E1(b) 的"私有实现"用词与 `internal` 不符

§8.5 E1 的措辞是「或在"唯一调用方是边界入口"的**私有实现**里做同样的事」；`TypeBridge.GetTypeImplementation` 实际是 **`internal static`**（因为 `ArrayBridge` 要跨类调用），不是 `private`。

- **实质完全符合**：调用方只有两个 `[UnmanagedCallersOnly]`（`TypeBridge.GetClass`、`ArrayBridge.NewArray`）；`TypeBridge.GetFunctionPointer:82` 调的是 3 参重载、不含 catch；失败值 `null` 落在既有值域。
- **字面不符**：`internal` ≠ `private`。
- ✅ **维护者选 A，已落地（2026-10-26）**：`_CONVENTIONS.md` §8.5 E1(b) 改为「**全部调用方都是边界入口**的**私有/内部实现**（`private`/`internal`，非公开、不被公开 API 引用）」，机械判据同步；变更记录新增 2026-10-26 一行。**代码零改动**，本轮之后 `TypeBridge.GetTypeImplementation` 的 `internal` 形态**合规**。
- **（原选项，供追溯）**：
  - **A. 改口径（推荐）**：把 §8.5 E1(b) 的"私有实现"改为「**私有/内部实现**（`private`/`internal`），且其**全部调用方都是边界入口**、不得被公开 API 引用」—— 这样现有代码合规，且口径能覆盖同类情形。
  - **B. 改代码**：把 catch 移进 `GetClass` / `NewArray` 两个 `[UnmanagedCallersOnly]` 本体（E1(a) 形态），`GetTypeImplementation` 恢复"可抛出"。代价：多一层冗余、捕获面变大（会把 `HandleData.Alloc` 等也纳入）。
- 已在 [`119`](119-轮B-81-G7裁定落地（F-REFL-004零例外与E1边界屏障）（2026-10-25）.md) §1.3 就地标注该字面差异（原文"两个边界入口"的计数是**对的**）。

> 另：`SetStaticValue` 的**空 catch** 是 E1 允许的"无返回值可写"形态，119 §1.4 已写明，不构成问题。

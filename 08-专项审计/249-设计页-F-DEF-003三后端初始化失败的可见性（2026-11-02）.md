# 设计页 `F-DEF-003` —— 三后端 `Initialize()` 失败的可见性（2026-11-02）

> 分析范围：`F-DEF-003`（P2 · S=2.80 · 潜伏）—— 「三个后端的 `Initialize()` 失败路径全部静默返回，且三个域实现文件里 `UE_LOG` 出现次数为 0」
> 状态：设计完成，**未施工**（结论：**方案 C＋B 组合，分两步**；本轮 0 代码）

## 1. 代码事实（回 HEAD（B-211 交付）复核）

- `IScriptDomain::Initialize()` 返回 **void**（`IScriptDomain.h:18`），另有一个 `virtual bool IsInitialized() const = 0`（`:81`）。
- CoreCLR 的失败点（`FCoreCLRDomain.cpp`）：`:37` 重入守卫 → `:43` hostfxr 句柄为空 `return;` → `:63` 两个导出为空 `return;` → 后续 hostfxr 初始化失败亦 `return;`。**全部是裸 `return`，无任何诊断**。
- LeanCLR / Mono 同构（`FLeanCLRDomain.cpp` / `FMonoDomain.cpp`），三文件 `UE_LOG` 计数 **0 / 0 / 0**（审计原判成立）。
- **关键新事实（本轮补）**：失败**并非不可观测** ——
  - `IsInitialized()` 是既有 API（`IScriptDomain.h:81`，三后端各自 `override`）；
  - **`FScriptDomainScope` 已经在用它做分支**：
    ```cpp
    if (!ScriptDomain->IsInitialized()) { ScriptDomain->Initialize(); }
    if (ScriptDomain->IsInitialized())  { InFunction(); }          // ← 失败时静默跳过
    ```
    即：**失败被"吞"在 `FScriptDomainScope` 的第二个 `if` 里**，调用方看到的是"函数体没执行、什么也没发生"。
  - `FDomain::Initialize()`（`FDomain.cpp:33`）只调 `ScriptDomain->Initialize();`，**完全不检查**返回值/状态。
- Mono 的 `bIsInitialized` 语义特殊：它在 `LoadAssembly` 里按"程序集文件是否存在"赋值（`FMonoDomain.cpp:309`），**不是"初始化成功"**；CoreCLR 在 `:128`、LeanCLR 在 `:86` 才是"成功后置真"。⇒ 同一个 `IsInitialized()` 在三后端语义不一致。

## 2. 为什么不能小改

| 障碍 | 说明 |
|---|---|
| G7 禁止新增日志 | 最直观的修法是"失败时 `UE_LOG(Error, …)`"，但 G7 把日志/断言/throw/公开面全封死；`E1` 只开 `try/catch`（这里是 C++，无关）、`E2` 只开**有消费者的只读 getter** |
| 接口是 `void` | 要让失败"传出去"，要么改 `Initialize()` 签名（3 后端 ＋ 全部调用点），要么用既有 `IsInitialized()` |
| 三后端语义不一致 | `IsInitialized()` 在 Mono 下含义是"程序集在"，直接拿它当"初始化成功"会误判 |

## 3. 方案

### 方案 A：只写契约，不改代码（最小）
在契约页写明：**失败 ⇒ `IsInitialized() == false` ⇒ `FScriptDomainScope` 跳过函数体**；调用方若需要知道，自己查 `IsInitialized()`。
- 代价：0 行；没有任何"提醒"，运维仍只能靠"功能没生效"反推。
- G7：完全合规。

### 方案 B：给 `FScriptDomainScope` 加只读查询（E2）
```cpp
class FScriptDomainScope
{
public:
    bool IsValid() const { return bIsValid; }   // 新增只读 getter
private:
    bool bIsValid = false;                      // 由构造函数里的第二个 if 赋值
};
```
调用方（目前 5 处 `FScriptDomainScope` 使用点）可选择"失败即走既有失败分支"。
- G7：走 **E2**（只读访问器）；**硬约束 = 必须有真实调用方**（E2 要求），否则就是新增死 API。
- 代价：`+6/-0` 行 ＋ 至少 1 个调用方改造。
- 隐患：把"静默跳过"变成"可查询的静默跳过"，**仍然没有诊断**。

### 方案 C：把失败收敛到既有值域（推荐第一步）
`FDomain::Initialize()` 与 `FScriptDomainScope` 的现有分支**已经能表达失败**，无需新 API：
- `FDomain::Initialize()`：在 `ScriptDomain->Initialize();` 之后加一次 `IsInitialized()` 检查，**失败时把 `IScriptDomain::Set(nullptr)` 回滚**（避免留下半初始化域被后续调用误用）——这是**既有值域内的状态收敛**（Q2），不加日志、不加公开面。
- 同步在契约页写明三后端 `IsInitialized()` 的**不同语义**（Mono = 程序集存在），并规定"`Initialize()` 之后的 `IsInitialized()` 才是有效性判据"。
- 代价：`+4/-0` 行 ＋ 契约页。
- G7：合规（无日志/断言/throw/新公开面）。

### 方案 D（仅记录，不推荐现在做）：`Initialize()` 返回 `bool` 或错误枚举
最"正确"，但要改 `IScriptDomain` 接口 ＋ 3 后端 ＋ 2 个调用点，属接口变更；只有在"必须区分失败原因"时才值得。

## 4. 推荐与触发条件

- **推荐**：先做 **方案 C**（回滚 ＋ 契约），若将来需要"调用方感知"再上 **方案 B**（E2，必须有调用方）。
- **判据**（方案 C）：编译通过；构造一次"域初始化失败"（如临时把 `GetHostFxrPath()` 指向不存在路径）后，`IScriptDomain::Get() == nullptr`（回滚生效）、后续 `FScriptDomainScope` 不再进入半初始化域；套件 **1 992/0 同 SHA**。
- **触发升级到 D 的条件**：① 出现"初始化失败但无人察觉、排查耗时"的实证；② 需要按失败原因给出用户可读提示（新 UI/日志口径放开）。
- **不施工的理由（当前）**：失败已经**可观测**（`IsInitialized()`），只是"没人看"；方案 C 是纯粹的状态卫生，不改语义。

## 5. 残余与登记

1. 三后端 `IsInitialized()` 语义不一致（Mono vs CoreCLR/LeanCLR）**不在本条修**，只写进契约；若要统一，属 `F-DOM-007` 的邻居问题。
2. 本条**不含**"给用户提示"的需求：那需要新 UI 或放开日志口径（G7），另立条目。
3. `FDomain::Initialize()` 的回滚若与"域复用"路径冲突（例如某些调用方期望失败后重试），需在方案 C 落地前回核 5 处 `FScriptDomainScope` 使用点。

## 6. v2 更正（B-213 施工尝试，2026-11-02）—— **方案 C 未能落地，改判纯契约**

施工时按 §3 方案 C 动手（在 `FDomain::Initialize()` 里"失败则 `IScriptDomain::Set(nullptr)`"），**在提交前发现两个阻塞事实**，遂**放弃该方案**：

| 阻塞 | 事实 | 后果 |
|---|---|---|
| Mono 的 `IsInitialized()` 语义不同 | `FMonoDomain.cpp:309` 里 `bIsInitialized = IsAssembliesFileExists(InAssemblies)` ⇒ 它是"**程序集文件存在**"，不是"初始化成功" | 一个**初始化成功但工程尚无程序集**的 Mono 会话会被判定为"失败" ⇒ 回滚会把**已建成的域**丢掉；下次 `FScriptDomainScope` 会通过工厂**再建一个 FMonoDomain**（`Domain == nullptr` ⇒ 再 `mono_domain_create`）⇒ 重复建域 |
| 运行期无法区分后端 | 唯一的后端类型查询器 `FUnrealCSharpFunctionLibrary::GetScriptDomainType(PlatformName)` 位于 `#if WITH_EDITOR` 内（`FUnrealCSharpFunctionLibrary.h:289-292`） | 打包运行期无法写"仅对 CoreCLR/LeanCLR 回滚"的分支 |

**要落地方案 C 的前提**：给 `IScriptDomain` 加一个"初始化是否成功"的能力查询（例如 `virtual bool IsInitializeSucceeded() const`）——**这是新增纯虚接口方法 = 新公开面，撞 G7**，且要三个后端各自实现（Mono 的语义还得重新定义）。

**改判（本轮生效）**：`F-DEF-003` **不施工**，退回 **方案 A（纯契约）**：
- 契约写明"`Initialize()` 失败 ⇒ `IsInitialized() == false` ⇒ `FScriptDomainScope` 跳过函数体"（已成立的事实）；
- 契约同时写明**三后端 `IsInitialized()` 语义不同**（Mono = 程序集存在），调用方不得把它当"初始化成功"用；
- 触发重估：① 出现"初始化失败但无人察觉且排查耗时"的实证；② G7 放开新公开面（届时上能力查询 ＋ 方案 C）。

> 📌 **这一条的方法学价值**：设计页的"三后端语义不一致"当初只当**风险**写了一句，实际落地时它就是**否决理由**。⇒ 今后凡涉及"三后端共同语义"的设计，必须在设计阶段就把"是否有一个运行期可达的统一判据"写死，而不是留到施工。

# 设计页 轮 B-225 `F-DOM-005` CoreCLR 初始化失败的重试与清理语义（2026-11-03）

> **分析范围**：`F-DOM-005`（P2 · S=2.82 · 潜伏）——「CoreCLR 初始化失败早退时既不关闭 host 上下文又留下门闩，下次初始化彻底跳过运行时」
> **规模**：**0 代码**（只读复核 ＋ 方案设计）；基线 = 插件 HEAD `efdca39f`（含 B-224 的 1 行修复）
> **结论**：原文**低估**了后果 —— 失败不只是"跳过运行时"，而是**在下一次 `Initialize()` 里被改写成一次"假成功"**（`bIsInitialized = true` 而全部桥函数指针为 null），并把 `bIsInitializeCompleted` 永久置位；同时 `FScriptDomainFactory::Destroy` 因 `IsInitialized()` 为假而**跳过 `Deinitialize()`**，静态句柄与 host 上下文一起泄漏
> **推荐**：**方案 A**（A1 失败回滚 ＋ A2 `Destroy` 无条件 `Deinitialize`），约 **30 行 / 3 文件**；**不本轮施工**，待维护者对 §7 三个决策点定口径

## 1. 现状：四条失败出口与两个静态门闩

### 1.1 出口与残留状态（`FCoreCLRDomain.cpp`，HEAD `efdca39f`）

| # | 出口 | 触发条件 | 离开时 `HostFxrDllHandle` | `HostFxrHandle` | `bIsInitialized` | `bIsInitializeCompleted` |
|---|---|---|---|---|---|---|
| 0 | `:38` 早退 | 已 completed | 不变（成功时为非空） | 不变 | 不变 | **true** |
| 1 | `:49` | `GetDllHandle` 失败 | **null** | null | false | false |
| 2 | `:75` | 两个 hostfxr 导出缺失 | **非空** | null | false | false |
| 3 | `:104` | `hostfxr_initialize_for_runtime_config` 失败（且 ≠ `0x8`） | **非空** | 可能非空 | false | false |
| 4 | `:113` | `hostfxr_get_runtime_delegate` 失败 | **非空** | **非空（不 close）** | false | false |

- 两个句柄是 **static 成员**（`:30`/`:32`）⇒ 即使 `FCoreCLRDomain` 对象被销毁重建，残留状态**跨实例存活**。
- 只有出口 1 是可重试的（`HostFxrDllHandle == nullptr` 使 `:43` 的整块重新进入）；出口 2/3/4 都会让下一次 `Initialize()` **跳过 `:43-118` 整块**。
- **第 5 条出口（不在上表）**：`:122` 的 `IsAssembliesFileExists(AssemblyPublishPath)` 为假时函数直接结束（无 else）。此时 hostfxr **已完整建立**、`LoadAssemblyAndGetFunctionPointerFn` 有效 ⇒ 下一次调用跳过 setup 后 `RegisterInterop` 能正常解析 ⇒ **自愈**，不属于"毒化"路径；但同样不清理（宿主保持到进程退出，可接受）。

### 1.2 第二次 `Initialize()` 的代码路径（按代码推定）

```
:38  bIsInitializeCompleted == false            → 继续
:43  HostFxrDllHandle != nullptr                → 整块 hostfxr 建立被跳过（不重试、不 close）
:120 发布目录存在                                → 继续
:125 RegisterInterop(...)                       → 宏内走 :325 的 null 守卫 ⇒ 全部桥指针保持 null
:129 bIsInitialized = true                      → ★ 假成功
:131 InitializeAssembly(...)                    → TypeBridge 指针为 null ⇒ :190 分支不进，只剩 LoadAssembly
:133 bIsInitializeCompleted = true               → ★ 永久锁死
```

> `LoadAssemblyAndGetFunctionPointer`（`:321-335`）对 null **是安全的**（整段 no-op），所以第二次调用**不会崩**，只会安静地把域标记为"已初始化"。

## 2. 两条可达的"第二次 Initialize"路径

| 路径 | 证据 | 说明 |
|---|---|---|
| **每次生成** | `FDynamicGenerator.cpp:36`／`:178` 各构造一个 `FScriptDomainScope`；`FScriptDomainScope.h:25-27` 在 `!IsInitialized()` 时调 `Initialize()`；`:37` 析构为 `= default`（不 `Deinitialize`） | 初始化一旦失败，**下一次生成立即重试**；重试即 §1.2 |
| **域重载** | `FCSharpEnvironment.cpp:366-374`：模块 `Active`/`InActive` 广播 → `Initialize()`/`Deinitialize()`；`FDomain` 析构（`FDomain.cpp:15-18`）→ `Destroy` | 编辑器内热重载/模块重载会重建域；静态句柄跨实例存活 |

### 2.1 已观测到的现场（B-224 生成会话，**间接证据**）

`Saved/Retest/b224/b224-fixed-corpus/editor.log`：

```
15:34:49  Rotator.cs 写入（生成完成）
15:35:42  LogUnrealCSharp: Error: Initialization request is expected to be non-null for requests other than the first one
15:35:42  LogUnrealCSharp: Error: Failed to initialize context for config: …\CoreCLR.runtimeconfig.json. Error code: 0x80008081
```

- 这是**同进程第二次** `hostfxr_initialize_for_runtime_config`（第一次在启动期已成功 —— 否则不会有 15:32:46 的绑定注册期日志）。
- 该形态在本库已被登记为"同进程重载 C# 域的已知装置形态"（`08-…/106`、`176`、`217`），但**从未分析其后果**：按 §1.2，这次失败之后如果再有一次 `Initialize()`，域会被标记为"已初始化"而桥指针全空。
- 本机没有在失败后继续驱动业务，所以**后果未实测**；§5 给出可判别的注入口。

## 3. 三个后果（按代码推定，待 §5 实测）

1. **假成功**：第二次 `Initialize()` 置 `bIsInitialized = true` ＋ `bIsInitializeCompleted = true`，而 `RegisterInterop` 的 20+ 个桥指针全为 null ⇒ `FScriptDomainScope` 会**执行**生成/业务闭包，后续任何托管调用要么 no-op、要么空指针。
2. **双泄漏**：`FScriptDomainFactory::Destroy`（`FScriptDomainFactory.cpp:29-32`）只在 `IsInitialized()` 为真时调 `Deinitialize()`；失败态下 `bIsInitialized == false` ⇒ **不 close host 上下文、不 `FreeDllHandle`**，且静态句柄跨实例保留 ⇒ 进程生命周期内不可回收。
3. **永久锁死**：一旦第二次调用把 `bIsInitializeCompleted` 置 true，`:38` 使**之后所有** `Initialize()` 直接返回；只有 `Deinitialize()`（把该标志清 false）能解锁，而失败态下没人会调它（见后果 2）。
4. **附加窗口（同族）**：`InitializeAssembly` 内 `:215-218` 在反射注册表未初始化时把 `bIsInitialized` 改回 false，但 `:133` 随后仍把 `bIsInitializeCompleted` 置 true ⇒ 同样进入"completed 但未 initialized"的锁死态，且 `Destroy` 同样跳过 `Deinitialize`。

## 4. 方案

### 方案 A（推荐）：失败回滚 ＋ 销毁无条件 teardown

| 子项 | 改动 | 规模 |
|---|---|---|
| **A1** | `FCoreCLRDomain` 内新增私有 `bool InitializeHostFxr()`（DLL → 导出 → runtime config → delegate，**单一失败出口**）与 `void ReleaseHostFxr()`（close ＋ free ＋ 清 `LoadAssemblyAndGetFunctionPointerFn`）；`:43-118` 整块搬进前者，失败时调后者并 `return` | ≈25 行，`.h/.cpp` 各 1 |
| **A2** | `FScriptDomainFactory::Destroy` 去掉 `if (InScriptDomain->IsInitialized())` 前置，**无条件**调 `Deinitialize()`（三后端的 `Deinitialize()` 都已幂等：CoreCLR 的 teardown 段本就在 `bIsInitialized` 之外（`:159-179`），Mono/LeanCLR 有 `if (!bIsInitialized && !bIsInitializeCompleted) return;`） | 1 行 |

- **语义**：初始化失败 ⇒ 静态门闩回到"未建立" ⇒ 下一次 `Initialize()` **从零重试**；重试仍失败则继续失败（不再假成功）。域对象销毁时无论成败都释放 host 资源。
- **G7**：0 新增日志/断言/`throw`/公开 API（新增两个 **private** 成员）。**Q2**：失败继续收敛到 `IsInitialized() == false`（既有取值）。
- **风险**：① 永久性失败（如机器无 .NET）会**每次生成重试一次** hostfxr 初始化（毫秒级，可接受）；② `hostfxr_initialize_for_runtime_config` 返回 `0x8`（already initialized）时句柄归属需按 hostfxr 契约确认后 close（§5 判据之一）；③ A2 改共享工厂，需三后端各跑一次构建/套件。

### 方案 B：失败终态标志（最省）

- 新增 `bool bIsInitializeFailed`：四条失败出口置位；`Initialize()` 首行 `if (bIsInitializeFailed) return;`；`Deinitialize()` 清位。
- ≈6 行；**不泄漏治理**（`Destroy` 仍跳过）、**不重试**。只消除"假成功"。
- 适合"产品口径 = 一次失败即终态"；但静态句柄仍要到进程退出才释放。

### 方案 C：维持现状 ＋ 契约

- 只补契约："`Initialize()` 失败即终态，调用方必须 `Deinitialize()` 后重建"。
- **不成立**：失败态下 `Destroy` 的 `IsInitialized()` 前置使 `Deinitialize()` 根本不会被调用；契约与实现矛盾。若选 C，至少要 A2。

### 比较

| 维度 | A | B | C |
|---|---|---|---|
| 消除假成功 | ✅ | ✅ | ❌ |
| 失败后同进程重试 | ✅ | ❌ | ❌ |
| 释放 host/DLL | ✅ | ❌ | ❌（需 A2） |
| 行数/文件 | ≈30 / 3 | ≈6 / 2 | 0 / 0 |
| G7 | 合规 | 合规 | 合规但契约与实现不符 |
| 判据可取得 | 故障注入 A/B（§5） | 只读 ＋ 探针 | 静态 |

## 7. 决策点（需维护者定口径）

1. **失败后是否允许同进程重试**？A = 允许（每次重试一次 hostfxr）；B = 一次失败即终态。倾向 A：生成/热重载天然会重复调用，终态等于把一次瞬时故障放大成整会话不可用。
2. **是否接受 A2 改共享工厂**（1 行、三后端）？若否，可只做 A1 ＋ 把 CoreCLR 的 teardown 挪进析构 —— 但那样 Mono/LeanCLR 仍留同族窗口。
3. **`0x8`（already initialized）句柄的关闭语义**：需按 hostfxr 契约确认"返回的 handle 是否仍需 close"，这决定 A1 的回滚是否覆盖该分支；本机可用注入配方验证（§5）。

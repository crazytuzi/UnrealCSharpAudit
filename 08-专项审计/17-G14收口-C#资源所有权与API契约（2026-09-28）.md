## 2. 逐条改法

### 2.1 `F-CS2A-015` —— `Set` / 带值构造的值句柄：**native 侧消费后释放**

**为什么由 native 释放**（两条独立依据）：

1. **本仓既有先例**：`FDomain::GetTraceback()`（`FDomain.cpp:122-134`）就是"取出句柄 → 消费 → `GCHandle_Free`"；`FDomain::GCHandle_Free`（`:104-110`）是 `IScriptDomain::Free` 的家法包装。
2. **同型契约就在隔壁**：`FReflectionRegistry::GetClass`（`:929-953`）在"缓存命中"分支同样 `ScriptDomain->Free(InManagedClass)` ⇒ **"native 消费者释放自己不保留的句柄"是本仓已确立的契约**。
3. 审计原文 `06-…/02a` 的**建议 1** 也正是这个方向（其建议 2"值类型不走句柄"会改动 ABI，本轮不取）。

改动（2 处，各 +2 行，`+4`）：

```cpp
// Source/UnrealCSharp/Private/Domain/Interop/FRegisterOptional.cpp:39-76（Register2Implementation 尾部）
			}
		}

		FDomain::GCHandle_Free(InValue);   // :75  消费者释放调用方临时分配的装箱句柄
```


**安全性依据（为什么"调用后立即可释放"）**：`InValue` 只被消费一次，且**所有**接收方都在调用内把句柄解析成真值（逐文件回核，见 §3 的 E3/E4）——
`FObjectPropertyDescriptor::Set`（`:18-27`，`GetObject` → `SetObjectPropertyValue`）、`FStrPropertyDescriptor::Set`（`:37-47`，`GetString` → `SetPropertyValue`）、`FStructPropertyDescriptor::Set`（`:46-56`，`GetStruct` → `CopySingleValue`）、`FArrayPropertyDescriptor::Set`（`:20-32`，`GetContainer` → `CopyCompleteValue`）、`FOptionalPropertyDescriptor::Set`（`:42-52`，`GetOptional` → `CopyCompleteValue`）、`FDelegatePropertyDescriptor::Set`（`:20-34`）、`FMulticastDelegatePropertyDescriptor::Set`（`:20-49`）、`FFieldPathPropertyDescriptor::Set`（`:37-47`）。**没有任何一条把传入的句柄本身存进 native 存储**。

**引用计数不变量**：C# 每次调用都先 `HandleData.Alloc(InValue)`（`:48` `Count++`），释放侧 `FreeImplementation`（`:76-81`）先 `Count--`、**仅在归零时**才移除条目并 `GCHandle.Free()` ⇒ 与注册表共享的包装句柄只做计数递减，**不会误放他人的句柄**；对装箱值（`Count` 恒为 1）则真正回收。
**早退路径也覆盖**：释放语句在 `if` 之外 ⇒ 即便 `Class == nullptr` / `Factory` 失败 / 可选句柄查不到，句柄照样回收（这正是 native 侧释放相对于 C# 侧配对释放的优势）。

### 2.2 🆕 `F-CS2A-024` —— `Get()` 的**装箱句柄**：C# 侧取的即放（**G9 改法的连带后果**）

🔴 **这是本轮最重要的新发现，而且是上一轮（G9）修复引入的新泄漏**：

- G9 把 `FRegisterOptional::GetImplementation` 从"2 参裸拷贝"改成了 **`FPropertyArgument::FMember` 装箱**（`fca72a8c` 的 diff，`FRegisterOptional.cpp:115-131`），这条修法本身是对的（修掉了 `F-CS2A-014` 的"裸字节当句柄"）；
- 但 **`FMember` 对 primitive/enum 走 `Class->BoxValue(...)` ⇒ 每次调用 `HandleData.Alloc(装箱值)`**（`TPrimitivePropertyDescriptor.inl:21-24`、`FEnumPropertyDescriptor.cpp:4-12`、`Box*` 家族 `TypeBridge.cs:205-267`），而这**正是"每次调用新建一个强 `GCHandle`"**；
- C# 侧 `TOptional_GetImplementation` 拿到句柄后**只 `GetObject` 从不释放** ⇒ **每次 `TOptional<int>.Get()` 泄漏 1 个强 `GCHandle` + 1 个字典项，并永久钉住装箱值**。
- 改前（G9 之前）该路径根本不创建箱 ⇒ **本条的账应记在"G9 的连带面"上**，不是原报告的遗漏。

改动（`Script/UE/Library/TOptionalImplementation.cs:55-72`，并把调用点泛型化）：

```csharp
        public static unsafe T TOptional_GetImplementation<T>(nint InOptional)   // :55
        {
            var Handle = __TOptional_GetImplementation(InOptional);             // :57

            if (Handle != 0)
            {
                var Object = HandleData.GetObject(Handle);                      // :61

                if (typeof(T).IsValueType)                                      // :63
                {
                    HandleData.FreeImplementation(Handle);                      // :65
                }

                return (T)Object;
            }

            return default;                                                     // :71
        }
```

**判别式 `typeof(T).IsValueType` 为什么恰好等价于 native 的"是否装箱"**：

| native `Get(FMember)` 行为 | 返回物 | C# 侧 `T` | `IsValueType` | 是否可释放 |
|---|---|---|---|---|
| `TPrimitivePropertyDescriptor` / `FEnumPropertyDescriptor` → `BoxValue`（**新建**句柄） | 装箱值（`System.Int32`/`Boolean`/…，**值类型**） | `int`/`bool`/枚举 | **true** | ✅ 必须释放（本次修复） |
| `FObjectPropertyDescriptor::Get` → `Bind(...)` | 注册表拥有的**包装类实例**（`UObject` 子类） | 包装类 | false | ❌ 不可释放 |
| `FStrPropertyDescriptor`/`FFieldPathPropertyDescriptor`/`FStructPropertyDescriptor`/容器/可选/委托 → `Add*Reference`/`NewWeakRef` | 同上（注册表拥有） | 包装类 | false | ❌ 不可释放 |

**自洽性论证（比"约定"更强的一条）**：该函数末尾必须 `(T)Object` 转换成功，而**只有"native 装箱值"这一支的 `Object` 才是 `T` 的装箱体**；任何注册表句柄的目标都是包装**类**实例，`T` 必为类 ⇒ `IsValueType == false`。⇒ 判别式与 native 的 `IsPrimitiveProperty()` 二分**同构**，且由"转型必须成功"保证（含枚举：`TOptional<E*>` 走 `FEnumPropertyDescriptor`，同样 `BoxValue`、同为值类型）。写法取家法：`TArray.cs:78` 用的就是 `typeof(T).IsValueType` 二分。

**为什么这一半必须由 C# 释放**（与 §2.1 相反）：native 无法释放——句柄是**交付物**，C# 要在返回后才读它。家法先例是 `FString_ToStringImplementation`（`FStringImplementation.cs:37-51`）：native 分配 → C# 取对象 → `FreeImplementation` → 返回（**先取对象再放句柄是安全的**，`GetObject` 已把托管引用取到局部量）。

## 6. 复用价值（给下一轮）

1. **"句柄区间存活扫描"是无探针、可永久的泄漏判据**：`Alloc` 探针 → 做事 → `Alloc` 探针 → 用 `GetObject` 扫区间存活数。它不碰私有状态、不需要临时日志，且**能给出精确条数**（本轮 2000 → 0）。凡"每调用一次分配一个句柄"的泄漏族（`F-CS2A-007`/`019`、`TypeBridge` 的 `Alloc(Type/Method)`、各处 `Alloc(InValue)`）都可照此量化。
2. **"谁消费谁释放"在本仓是分裂的，判据是"消费者是否保留"**：native 端有 `FReflectionRegistry::GetClass`（命中即释放）与 `FDomain::GetTraceback`（消费后释放）作先例；C# 端有 5 个字符串包装（`FString_ToStringImplementation` 一族）作先例。**返回值句柄只能 C# 释放，参数句柄优先 native 释放**。
3. **判别"句柄是否为新建装箱"的等价式**：`typeof(T).IsValueType` ⟺ native 的 `IsPrimitiveProperty()`/`BoxValue` 支，**由"末尾转型必须成功"保证**，不是经验约定（§2.2 的表）。改任何 `Get(FMember)` 路径前先用这张表过一遍。
4. **改前对照的排版纪律**：把"改前必然抛异常"的用例排在最后，测量块排最前，否则对照那一轮量不到数（§4.5 第 1 条）。
5. **临时探针的移除自检**：终形态日志里 grep 探针前缀（本轮 `[G14]`）**0 命中**即证已移除 —— 比"人工记得删"可靠。

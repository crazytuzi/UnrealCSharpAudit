## 1. 施工面（weaver：3 个 helper ＋ 17 处解析 ＋ 提前返回）

**改法**（`Script/Weavers/UnrealTypeWeaver.cs`，插件模板与工程部署副本**同改**）：

1. `GetAllMeta()`：`void` → `bool`；开头 `bHasMetaError = false`；UE 程序集路径先 `File.Exists` 再 `ReadModule`（失败即 `WriteError` ＋ `return false`）；结尾 `return !bHasMetaError;`。
2. 新增 3 个私有 helper（每个都 `WriteError` 并置位 `bHasMetaError`）：
   - `GetMetaType(ModuleDefinition, string)` —— 17 处中的 15 处类型解析；
   - `GetMetaMethod(TypeDefinition, string)` —— 12 处方法解析（`Type == null` 时不重复报错，避免级联）；
   - `GetInteropType(string)` —— 2 处 `Interop.HandleData` 解析（同时补掉报告指出的"`FirstOrDefault("Interop")` 为 null 后传给 `Resolve`"）。
3. `Execute()`：`GetAllMeta();` → `if (!GetAllMeta()) { return; }`。
4. 20 个 `definition.GetType(...)` / `.Methods.FirstOrDefault(...)` 逐点替换为 helper 调用（类型只解析一次：`UStructImplementation` / `FPropertyImplementation` / `FFunctionImplementation` / `HandleData`）。

**G7 对照**：新增注释 0 / 日志 0（`WriteError` 是 Fody 的 **MSBuild error 通道**，按 B-36 的 `UC_ERROR` 先例计"诊断"）/ `throw` 0 / `try-catch` 0 / `ensure`·`check` 0 / **公开 API 0**（全部 `private`）。

## 4. `F-PROP2-006 (04b)` 撤离记录（回归抓到的契约冲突）

**改法**：`FRegisterText.cpp:80` 的 `NewString(TCHAR_TO_UTF8(*Text->ToString()))` → 先 `FTextStringHelper::WriteToBuffer(Buffer, *Text)` 再 `NewString(...)`（`WriteToBuffer` 在 **5.0.3 / 5.6.0 签名一致**：`void(FString&, const FText&, bool, bool)`，buffer 在首位 ⇒ 零门控）。

**实测**：5.6 编译 **Succeeded**、5.0 门禁 **0 error**；套件仍 1 970 行，但 SHA 由 `70C740F4…` → **`20A4A05C…`**，`Compare-Object` 只差 **1 行**：

```
<= TextToString, true      （基线）
=> TextToString, false     （改后）
```

**根因**：仓内既有用例 `Script/Game/UnrealCSharpTest/UnitTest/String/FText/UnitTestSubsystem.cs:88-99`：

```csharp
var Text = new FText("12");
TestCoreSubsystem.TestEqual("TextToString", Text.ToString(), "12");
```

即 `FText.ToString()` 的**事实契约 = 显示串**。`WriteToBuffer` 输出的是可解析串（带引号/命名空间形式），直接破坏该契约 —— 与 B-73 §3 标注的"`ToString` 不再人类可读"风险一致，且**比预估更硬**：它不是"可接受的语义变化"，而是**已有用例把旧语义钉死**。

**处置**：**回退**（`git checkout`），重建后套件回到 `70C740F4…` ×2。`F-PROP2-006 (04b)` 维持开放，**降为候补/暂缓（需口径）**：
- A 改 `ToString` 语义 ⇒ 既有无用例红，且用户侧 `FText.ToString()` 的显示用法会变；
- B 新增序列化 API（如 `ToSerializeString()`）⇒ **撞 G7 的"不新增公开 API"**；
- C 维持现状 ⇒ 与"往返保真"目标冲突。

> **对 B-73 的更正**：B-73 §3 的立项 ③（"1 行闭合"）**被本条实测推翻** —— 1 行改动确实能编、能跑，但会打红既有契约用例。这也说明"1 行修法"在 C# 公开面上必须先用**套件**验证语义，而不只是看 diff 大小。

## 2. 施工

`Source/Compiler/Private/FCSharpCompileProgress.cpp`（`+11/−5`）：

```cpp
// 改前：每行 Left 一次 + MidInline 把剩余缓冲整体前移 ⇒ O(L·B)
int32 Index = INDEX_NONE;
while (PendingOutput.FindChar(TEXT('\n'), Index))
{
    auto Line = PendingOutput.Left(Index);
    PendingOutput.MidInline(Index + 1);
    ProcessLine(Line);
}
```

```cpp
// 改后：单遍前向扫描 + 结尾一次裁前缀 ⇒ O(B)
int32 Start = 0;
for (auto Index = 0; Index < PendingOutput.Len(); ++Index)
{
    if (PendingOutput[Index] == TEXT('\n'))
    {
        ProcessLine(PendingOutput.Mid(Start, Index - Start));
        Start = Index + 1;
    }
}
if (Start > 0)
{
    PendingOutput.RightChopInline(Start);
}
```

- **语义**：空行仍被 `ProcessLine` 的 `TrimStartAndEndInline` ＋ `IsEmpty` 丢弃；未完成行仍留在 `PendingOutput`；`SetStage` 的 `Empty()` 语义不变。
- 🔴 **一次 API 实测纠错**：原计划用 `PendingOutput.FindChar(TEXT('\n'), Index, Start)` 的 3 参重载，**UE 5.6 编译报 `C2660: 'FString::FindChar': function does not take 3 arguments`** ⇒ 改为手写扫描（`operator[]` ＋ `Len()`）。这就是 §7「签名不能只凭印象」的现场反例。
- 无新增注释 / 日志 / `throw` / `try-catch` / 公开 API（G7）。

## 8. 复用价值

- **"先量化、再动手"这次抓到的是反例**：报告说 `FindChar` 有带起点的重载，实测 5.6 没有 —— **接口签名必须回引擎头/实编确认**，§7 的三步不能省。
- **O(L·B) 的识别特征**：循环体里出现"取前缀 + 把剩余部分整体前移"（`Left` + `MidInline`/`RightChop`）就一定是二次型；等价的线性写法是"游标 + 结尾一次裁前缀"。
- **基准要带语义对照**：只报 ms 不够，同一条探针顺带记录 `Stage`/`Flush` 后的状态，才能在"快了 10 倍"之外证明"行为没变"。

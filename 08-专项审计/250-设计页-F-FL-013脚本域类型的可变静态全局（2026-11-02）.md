# 设计页 `F-FL-013` —— `ScriptDomainType` 的可变静态全局（2026-11-02）

> 分析范围：`F-FL-013`（P2 · S=2.22 · 潜伏）—— 「`ScriptDomainType` 是可被跨模块写入的可变静态全局（RAII 保存/恢复）」
> 状态：设计完成，**未施工**（结论：**方案 A，收窄写入面**；本轮 0 代码）

## 1. 代码事实（回 HEAD（B-211 交付）复核）

```cpp
// FUnrealCSharpFunctionLibrary.cpp:39
EScriptDomainType FUnrealCSharpFunctionLibrary::ScriptDomainType = EScriptDomainType::CoreCLR;   // 静态、可变

// 读写全是 public static，且整体在 #if WITH_EDITOR 内
void SetScriptDomainType(const EScriptDomainType);     // :1837
EScriptDomainType GetScriptDomainType();               // :1852（读全局）
EScriptDomainType GetScriptDomainType(const FString& InPlatformName);   // :1842（读 setting，不读全局）
```

```cpp
// FScriptDomainTypeScope.h（唯一"合法写法"，但它不是唯一写入者）
explicit FScriptDomainTypeScope(const EScriptDomainType InScriptDomainType) :
    ScriptDomainType(FUnrealCSharpFunctionLibrary::GetScriptDomainType())    // 保存旧值
{
    FUnrealCSharpFunctionLibrary::SetScriptDomainType(InScriptDomainType);   // 改全局
}
~FScriptDomainTypeScope() { FUnrealCSharpFunctionLibrary::SetScriptDomainType(ScriptDomainType); }
```

事实清单：

| 事实 | 读数 |
|---|---|
| 可见性 | **全部在 `#if WITH_EDITOR` 内**（`:1835-1856`）⇒ **对打包运行期零成本、零风险** |
| 写入者 | `SetScriptDomainType` 是 **public static**，**任何模块**都能直接改，绕过 RAII |
| 读取者 | `GetScriptDomainType()`（无参）只被 `FScriptDomainTypeScope` 构造函数与 `FSolutionGenerator.cpp:239` 读 |
| 线程 | 无锁、无原子；调用点都是编辑器 GT 路径（生成/编译） |
| 嵌套 | RAII 保存/恢复**支持嵌套**（内层存外层值），这一点是对的 |

⇒ 真实风险不是"可变"，而是**写入面没有收窄**：一个忘记加 scope 的直接 `SetScriptDomainType(x)` 会把全局永久改掉（下次 scope 的"保存旧值"保存的就是错的）。

## 2. 方案

### 方案 A：收窄写入面到 scope（推荐）
```cpp
class FUnrealCSharpFunctionLibrary
{
    …
private:
    friend struct FScriptDomainTypeScope;                 // 唯一写入者
    static void SetScriptDomainType(EScriptDomainType);   // 从 public 移入 private
};
```
- 代价：`+2/-1` 行 ＋ 1 处 `friend`（`FScriptDomainTypeScope` 是 `#if WITH_EDITOR` 结构体，位置在 `Common/`，与 `FUnrealCSharpFunctionLibrary` 同模块）。
- 收益：**"误写全局"从"可能"变成"编译不过"**。这正是本条要解决的问题。
- G7：无日志/无限言/无新公开面；反而是**收缩**公开面（`SetScriptDomainType` 由 public → private，属删除既有公开 API —— 需要确认仓外无消费者：全库 grep 只有 scope 一处调用）。

### 方案 B：`thread_local`
把静态变量改成 `thread_local`。
- 收益：多线程各一份，无数据竞争。
- 代价：语义变化 —— "全局当前域类型"变成"每线程当前域类型"，而**读取者（生成器）在别的线程读时会拿到默认值**，静默错判。⇒ **不推荐**。

### 方案 C：`std::atomic` ＋ 契约
- 收益：消除数据竞争（如果真有跨线程读写）。
- 代价：**治不了"绕过 scope 误写"**（本条的主危害），只治一个当前**没有实证**的竞争。⇒ 仅作为"将来出现跨线程读写"时的补丁。

### 方案 D：删除全局，改为显式传参
最彻底：`FScriptDomainTypeScope` 改成把类型作为参数一路传下去。
- 代价：`GetScriptDomainType()`（无参）有 `FSolutionGenerator.cpp:239` 等消费者，且生成器深处没有参数入口，改造面大。⇒ 记录，不推荐现在做。

## 3. 判据与触发条件

- **判据（方案 A）**：编译通过；全库 grep `SetScriptDomainType` **只剩 `FScriptDomainTypeScope` 内的 2 处**（构造函数 1、析构 1）；`GetScriptDomainType()` 的 2 个消费者行为不变（生成器用到的平台域类型仍按 setting 取）；套件 **1 992/0 同 SHA**；`b30-style-lint` PASS。
- **风险点（必须先查）**：`SetScriptDomainType` 是 public API，若有**仓外插件/工程侧**调用（不在本仓），改成 private 会破坏外部构建。落地前必须：① 全仓 grep（含 `Script/`、工程侧 `Source/`）；② 若仓外有消费者 ⇒ 退化为"public 但标记 deprecated"（`UE_DEPRECATED` 不触发编译失败、只是告警）。
- **触发条件（升级到 D）**：出现"生成器在非 GT 线程读 `GetScriptDomainType()` 拿到错值"的实证，或生成器需要并行处理多平台。

## 4. 残余

1. **线程安全不在本条范围**：本条只收窄写入面；若将来确认有跨线程读写，按方案 C 补原子（`EScriptDomainType` 是 `uint8` 枚举，`std::atomic<EScriptDomainType>` 无需锁）。
2. 本条在 `#if WITH_EDITOR` 内 ⇒ **对打包运行期没有任何影响**，这也是它 P2 而非 P1 的原因。
3. `FScriptDomainTypeScope` 的 RAII 语义本身**不需要改**（嵌套保存/恢复是正确的）。

# 轮 B-173：T4-3 `F-CS2B-011` 设计裁定 —— `Deinitialize` 丢弃 `TaskList` 的取消语义（2026-10-29）

> **来源**：[`09-问题清单/07-P2优先级评估（2026-10-28）.md`](../09-问题清单/07-P2优先级评估（2026-10-28）.md) §5 T4-3；原条目 [`06-CSharp运行时与脚本/02b`](../06-CSharp运行时与脚本/02b-对象字符串与工具类型包装.md) §F-CS2B-011。
> **性质**：**设计页（0 代码）**。
> **一句话结论**：`SynchronizationContext.Deinitialize()` 只把静态 `Context` 置空（`SynchronizationContext.cs:19-24`），`TaskList` 里已入队的续体与跨线程 `Send` 的 `ResetEvent` 一起失去消费者 ⇒ `await` 永久挂起、`Send` 永久阻塞。**P1 = 拆除前"排空一次"（`old.Process()`，无新公开 API，托管边界内允许 E1 异常处理）**；**P2 = 引入 `CancellationTokenSource` 让 `await` 收到取消（新公开面，需维护者批准）**；不做"诊断日志"（G7）。

## 1. HEAD 事实

### 1.1 C# 侧（`Script/UE/CoreUObject/SynchronizationContext.cs`）

```csharp
public static void Deinitialize()          // :19-24
{
    SetSynchronizationContext(null);
    Context = null;                        // :23  只丢引用，TaskList/PendingTaskList 未清、未执行
}

public static void Tick(float DeltaTime)   // :26-30
{
    Context?.Process();                    // Context 为 null 后变 no-op
}

public override void Post(SendOrPostCallback InCallback, object? InState)   // :55-66
{
    lock (TaskList) { TaskList.Add(new TaskInfo { CallBack = InCallback, State = InState }); }
}

public override void Send(SendOrPostCallback InCallback, object? InState)   // :68-92
{
    if (Thread.CurrentThread.ManagedThreadId == ThreadId) { InCallback(InState); return; }
    using var ResetEvent = new ManualResetEvent(false);
    lock (TaskList) { TaskList.Add(new TaskInfo { …, WaitHandle = ResetEvent }); }
    ResetEvent.WaitOne();                  // :91  等 Tick 执行 + TaskInfo.Invoke 的 finally Set()
}
```

`TaskInfo.Invoke()`（`TaskInfo.cs:14-24`）在 `finally` 里 `WaitHandle?.Set()` ⇒ **只要任务被执行，`Send` 就会解除阻塞**；反之永不。

### 1.2 C++ 侧调用顺序（`Source/UnrealCSharp/Private/Domain/FDomain.cpp`）

```cpp
void FDomain::Initialize()      { … ScriptDomain->Initialize(); InitializeSynchronizationContext(); }   // :31-36
void FDomain::Deinitialize()    { DeinitializeSynchronizationContext(); FScriptDomainFactory::Destroy(ScriptDomain); } // :39-47
```

- `DeinitializeSynchronizationContext()`（`:152-163`）在**销毁脚本域之前**反射调用 C# 的 `Deinitialize` ⇒ 排空期间反射对象/域仍有效。
- `Tick` 由 `IScriptDomain::Tick` → C# `SynchronizationContext.Tick` 驱动（`FScriptDomainImpl.inl:19-21`、`RegisterSynchronizationContextTick` `:663-667`）。

## 2. 缺口

| ID | 缺口 | 机制 | 影响 |
|---|---|---|---|
| **G1** | 已入队续体被静默丢弃 | `Context = null` 后 `Tick` no-op | `async` 方法停在 `await` 永不返回；无任何诊断 |
| **G2** | 跨线程 `Send` 永久阻塞 | `WaitOne()` 等的 `ResetEvent` 只能由 `TaskInfo.Invoke` 置位 | 停 PIE 时若恰有线程在 `Send`，该线程挂死 |
| **G3** | 无取消契约 | .NET 无法"中止"任意 `await`；只有被等待的操作可取消 | 无法透明修复；只能协作式 token 或排空 |
| **G4** | 排空可能抛异常 | `TaskInfo.Invoke` 只有 `finally`，没有 `catch` | 一个续体抛异常会中断 C++ 侧 `Deinitialize`（域销毁被跳过） |

## 3. 方案对比

| 方案 | 内容 | 改动面 | 风险 | 判定 |
|---|---|---|---|---|
| **A. 排空一次（P1）** | `Deinitialize` 里：`var Old = Context; SetSynchronizationContext(null); Old?.Process(); Context = null;`（顺序：先摘全局，再排空旧实例，最后清引用） | C# 1 文件 ~6 行 | 中：续体可能在"PIE 已结束/世界正在拆"时执行；`Process` 无 `catch`（G4）。缓解见 §4 | ✅ **推荐 P1** |
| **B. 协作取消（P2）** | `SynchronizationContext` 持 `CancellationTokenSource`；`Deinitialize` 里 `Cancel()`；对外暴露 `public static CancellationToken Token`，插件内所有可等待 API（`Delay`/网络/加载）接受并传递 token | C# 1–2 文件 ＋ 调用面改造 | 中高：**新公开 API**（G7 需批准）；只对"传了 token 的 await"有效 | 🟡 **P2，需维护者批准** |
| **C. 诊断日志** | 统计丢弃数量并打日志 | — | G7 禁新增日志 | ❌ 不可行 |
| **D. 不排空，改为 `Send` 用超时** | `Send` 改 `WaitOne(timeout)` 并返回失败 | C# 数行 | 治 G2 不治 G1；`Send` 语义变成可失败（调用方需处理） | ⏸ 备选 |

## 4. 裁定（推荐路线）

1. **P1 = A（排空一次）**，并处理 G4：排空在**托管边界**上，可用 **E1**（`_CONVENTIONS` §8.5「托管边界上直接用 E1」）包住每个续体的异常，保证"一个坏续体不阻断域销毁"；异常不吞日志（E1 允许 `catch`，但不得新增日志出口 —— 只保证流程继续）。
2. **P1 附带**：`Context` 置空放在排空**之后**，避免排空期间新 `Post` 落进"即将丢弃"的实例（新 `Post` 在 `SetSynchronizationContext(null)` 之后本就走不到这个实例；顺序仍按"先摘全局 → 排空 → 清引用"）。
3. **P2 = B**：`CancellationTokenSource` ＋ `Token` 公开属性；仅在维护者批准"新增公开面"后做；届时应同时把插件内 `Delay`/异步加载等可等待点接上 token。
4. **不做 C**；D 仅作为 `Send` 超时的备选，不并入 P1。
5. **不改变** `[UnmanagedCallersOnly]` 签名与 C++ 侧 ABI（P1 纯 C# 方法体改动）。

**建议**

- ① 摘除成功后补 `Field->Next = nullptr;`（断链，消除"从被摘节点继续走"的面）；
- ② 把 `Children` 摘链抽成独立私有函数并**显式只服务 `FRegisterClass` 路径**（或在本函数内先判 `InFunction` 是否真在 `Children` 里，命中才做 —— 现状是"扫一遍没命中就静默返回"，无法区分"不在链里"与"链结构变了"）；

### [F-CMP-036] `IsDotNetSdkSupported` 的判据退化为"只比 major"：minor 分支恒真、patch 与 `global.json` 不参与、Linux 恒假

- **类别**: Bug（判据无效）/ 平台 · **严重度**: **P3** · **可达性**: 潜伏（当前无 `global.json`、Linux 无编辑器目标、TFM minor 恒 0）

- **置信度**: 高（宏值、TFM 拼接、恒真推导逐字）／中（Linux 发行版布局未实机；`global.json` 失败文案未实测）

**现状（代码事实）**

```cpp

	{
		return false;
```

`DOTNET_MINOR_VERSION` 来自域模块的硬编码（`Source/ThirdParty/CoreCLR/CoreCLR.Build.cs:15` = `const int MinorVersion = 0;`，Mono/LeanCLR 同值），`DOTNET_MAJOR_VERSION` = **10**。

**问题**

1. **minor 分支恒真（死条件）**：`MinorVersion` 是 SDK 目录名（如 `10.0.403`）的**第二段**，对所有真实 .NET SDK 恒为 `0`（feature band 在第三段）；`DOTNET_MINOR_VERSION` 也恒为 `0` ⇒ `0 >= 0` **恒真**。⇒ 判据实际退化为 **`SDK_Major >= 10`**。
2. **反向埋雷**：若将来把 TFM 提到 `net10.1`（`CoreCLR.Build.cs:15` 改成 1），判据变成"要求 SDK 目录名第二段 ≥ 1"，而 SDK **不存在** `10.1.x` 这种号 ⇒ **所有候选都判不支持**，`GetDotNet()` 静默回退"第一个存在的"，新逻辑整段失效且无诊断（G7 禁止新增日志）。
3. **patch / feature band 与 `global.json` 完全不参与**：`GetDotNetSdkVersion` 只取 `[0]`/`[1]` 两段（`:1880-1889`）；`dotnet build` 真正的 SDK 解析由 muxer 按 `global.json` ＋ CWD 链决定 ⇒ 两套独立机制。库内当前 **0 个 `global.json`**（工程与插件仓 glob 0 命中）⇒ 现状不触发；用户一旦自备 pin（如 `{"sdk":{"version":"10.0.100","rollForward":"disable"}}`），"判据通过但 muxer 拒绝"就会以构建错误的形式出现。
4. **Linux 符号链接布局下判据恒假**：`GetDotNetSdkVersion` 用 `FPaths::GetPath(InDotNetPath)` 当安装根（`:1870`）。deb/rpm 的 `dotnet` 通常在 `/usr/bin/dotnet`（符号链接到安装根），⇒ 判据去看 `/usr/bin/sdk/*`（不存在）⇒ 该候选永远 `false`；而 `#else` 补的 `/usr/share/dotnet` 在 deb 布局下也不存在 ⇒ 整机候选全判不支持 ⇒ **退化为提交前行为**（不是回归，但新闸门在 Linux 上等于没写）。`LinuxScriptDomainType=CoreCLR` 说明 Linux 是被支持的平台（编辑器目标当前不存在 ⇒ 潜伏）。
5. **命名与实现不一致**：`IsDotNetSdkSupported` 的实际语义是"该安装根是否含能编译 `net{major}.{minor}` 的 SDK"，而 `major != Target` 的三目把 `>` 与 `==` 写成两种含义 —— 读代码的人会以为"高于目标主版本也要检查 minor"（实际不会）。

**建议**

- ① 把 minor 判据改成**明确的**语义：要么删掉（只比 major，并在命名上体现"SDK major ≥ 目标 major"），要么改成"SDK 目录名第三段（feature band）满足 `global.json` 的 `rollForward`"——后者需要读 `global.json`，属新面，按 §7 版本兼容先做门控；
- ② 安装根不要用 `FPaths::GetPath(exe)` 推断：Linux 上先 `realpath` 再取父目录（或读 `/usr/share/dotnet`、`/usr/lib/dotnet` 两个已知根）；
- ③ 若维持现状，把"判据只看 major、不看 patch/global.json"写进契约页，避免下一个人以为它管住了 patch。

**验证方式**

- 静态：`printf` 出 `DOTNET_MINOR_VERSION`（编译期 `static_assert(DOTNET_MINOR_VERSION == 0)` 即证恒真，不改代码）；
- 动态：在 Linux 上 `which dotnet` → `ls -l` 确认符号链接，跑一次 `GetDotNet()` 并打印候选/判定（当前应全部 `false`）；再在 `Script/` 放一份 `global.json` pin 到旧 feature band，判"判据通过但构建失败"。

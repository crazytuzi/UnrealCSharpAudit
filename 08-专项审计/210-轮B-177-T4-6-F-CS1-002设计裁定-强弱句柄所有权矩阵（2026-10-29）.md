# 轮 B-177：T4-6 `F-CS1-002` 设计裁定 —— 强/弱句柄的所有权矩阵（2026-10-29）

> **来源**：[`09-问题清单/07-P2优先级评估（2026-10-28）.md`](../09-问题清单/07-P2优先级评估（2026-10-28）.md) §5 T4-6；原条目 [`06-CSharp运行时与脚本/01`](../06-CSharp运行时与脚本/01-Interop桥接与程序集加载.md) §F-CS1-002。
> **性质**：**设计页（0 代码）**。
> **一句话结论**：审计"所有句柄都是 `Normal` 强根"的前提**已被 `3da38bb6` 改成"对象级引用计数 ＋ CWT ＋ 可选 Weak"**；现在真正的缺口不是"强句柄"本身，而是**没有写下来的所有权矩阵** —— 哪些 `Alloc` 该强、哪些该弱，全靠调用点自觉。另外发现一处**改名引入的语义翻转**：`ArrayBridge.cs:19` 的 `Alloc(array, true)` 在旧签名 `(object, bPinned, bWeak)` 下表示 **pinned**，改名成 `(object, bIsWeak)` 后变成 **weak** —— 探针实测弱数组句柄的 `Target` 在下一次 GC 后即被回收（`weak_alive=False`），而它没有其它托管根。**P1 = 把该调用改回强句柄（1 行）＋ 补所有权矩阵文档**；**P2 = 用 `AllocStrong`/`AllocWeak` 命名替代 `bool`（需批准）**；默认 `Normal` **不改**。

### 1.2 调用点分类（`grep HandleData.Alloc(`，排除 obj/bin）

### 1.3 探针（独立 `net10.0` 控制台，引用 `Content/Script/Interop.dll`）

```csharp
var WeakHandle   = HandleData.Alloc(new int[4], true);
var StrongHandle = HandleData.Alloc(new int[4]);
GC.Collect(); GC.WaitForPendingFinalizers(); GC.Collect();
// 读数：weak_alive=False  strong_alive=True
```

结论：**弱句柄不阻止回收；强句柄保持存活**。弱句柄的语义依赖"C# 侧另有强根"，否则句柄很快变成 `Target == null`。

## 2. 与审计原文的差异 ＋ 新发现

| 审计原文（`06/01:291-370`） | HEAD 现状 |
|---|---|
| 所有 `Alloc` 都是 `GCHandleType.Normal`（强根），终结器永不执行 | 🟡 **已收窄**：`Alloc` 支持 `bIsWeak`，包装类（字符串/容器/委托/软引用/属性 helper）已改弱；强句柄仅用于 C++ 持有对象 |
| `Free` 是唯一解绑路径 | ✅ 仍成立（弱句柄也需 `Free` 才能从 `Handles` 移除；`Target` 已空时 `FreeImplementation` 会直接移除） |
| 改为弱句柄即可 | 🟡 部分采纳：包装类弱化；但**默认仍强**，因为 C++ 持有的对象必须被 root |

**新发现 G0（本轮最重要）**：`ArrayBridge.cs:19`

```csharp
return HandleData.Alloc(Array.CreateInstance(Type, InLength), true);
```

- `3da38bb6` 之前的签名是 `Alloc(object, bool bPinned = false, bool bWeak = false)` ⇒ 这里 `true` = **pinned**（强根 ＋ 固定地址）。
- `3da38bb6` 把签名改成 `Alloc(object, bool bIsWeak = false)`（`git show 3da38bb6 -- HandleData.cs`），**这个调用点没有一起改** ⇒ 现在 `true` = **weak**。
- 弱数组没有其它托管根：`NewArray` 返回 handle 后，C# 侧不再引用该 `Array`；探针证明下一次 GC 即可回收 ⇒ 之后 `ArrayGet`（`GetObject` 返回 `null`）取不到元素；若曾有代码期望 pinned 地址，还会失去固定语义。
- **当前影响面有限**：`FClassReflection::NewArray` 在 `Source` 内**没有调用点**（`git grep '->NewArray('` 只命中定义本身），`ArrayBridge.NewArray` 目前是**休眠路径**；但语义已经错了，属"随时会被踩"的雷。

## 3. 剩余缺口

| ID | 缺口 | 影响 |
|---|---|---|
| **G0** | `ArrayBridge` 由 pinned 变 weak（改名遗漏） | 弱数组无根 ⇒ GC 后可回收；休眠路径，但语义错误 |
| **G1** | 没有所有权矩阵文档 | 新调用点选强/弱全靠猜；选错 = 泄漏（强）或悬垂/提前回收（弱） |
| **G2** | 弱句柄也要显式 `Free` 才能从 `Handles` 移除 | 漏 `Free` ⇒ 表项与句柄号泄漏（对象本身可回收）；`Clear()` 只在程序集重载调用 |
| **G3** | 强句柄仍 root 对象，终结器不执行 | 设计选择（C++ 所有权）；依赖终结器的释放路径不可用 |
| **G4** | `Clear()` 只在 `AssemblyLoader.cs:33` | 域关闭依赖逐句柄 `Free`；若有遗漏，`Handles` 表残留到进程结束 |

## 5. 裁定

1. **P1 = A ＋ D**：`ArrayBridge` 的数组句柄改回**强**（`Alloc(array)`）；同时把"强/弱/引用计数/谁 Free"的矩阵写进维护文档。
2. **P2 = B**：`AllocStrong/AllocWeak` 命名化，消除 `bool` 位置参数歧义；需维护者批准（C# 公开 API）。
3. **默认 `Normal` 不改**：C++ 持有对象必须被 root；弱化只用于"包装类自注册/临时 helper"。
4. **G2/G4 不并入**：弱句柄表项清扫/域关闭兜底属另一个问题（可与 F-CS1-001 的句柄号单调一起看）。

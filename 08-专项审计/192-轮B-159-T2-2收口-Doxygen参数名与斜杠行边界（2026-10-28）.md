## 1. HEAD 事实（施工前）

`FDoxygenConverter.cpp`（HEAD `8a28ec7f`，475 行）的三个点：

```cpp
// ① Name 分支（:276-286）：`[` 处 EatWhile 消费 0 字符，却仍返回 Name
OutTextReader.EatWhile([](const int InChar)
{
    return InChar > 0 && InChar < 128 && (FChar::IsAlnum(InChar) || InChar == '_');
});
OutExpect = EExpect::Description;
return ETokenKind::Name;

// ② GetTokenRange（:120-123）：从未 Save() 时 Begin/End 仍是构造值 0/0
return FTextRange(BeginIndex, EndIndex + 1);      // → (0,1)，长度 1，"非空"

// ③ `/` 分支（:246-256）：谓词没有换行判断
OutTextReader.Bump();
OutTextReader.EatWhile([](const int InChar)
{
    return InChar != '@' && InChar != '\\';        // 会一路吃到下一个标签，跨任意多行
});
return ETokenKind::Trivial;
```

`operator()` 的两个消费点直接用 `Slice(InText, Token.TextRange)`：`Name` → `ParamName`（`:403`）、`TagOther` → 标签名（`:396`）。于是"未消费却返回 token"必然切到**整段注释的第 0 个字符**。

### 1.1 三条新取证（本轮实测，非纸面推演）

1. **UHT `Comment` 元数据保留 `/**` 前缀**：4 个真实站点的产物是 `<param name="/">`，而 `Slice((0,1))` = 注释首字符 ⇒ 首字符就是 `/`。所以 `/` 分支在**每次转换的第一个 token** 就会触发（不是"偶尔的续行"）。
2. **真实语料的三种 `@param` 写法**：`@param Foo`（正常）、**`@param: UniqueID`**（Interchange 四个节点类，冒号）、**`@ param TypeData`**（`ParticleSystem.h` 的 `ContainsEmitterType`，`@` 后空格）。后两种在旧词法下都产出 `name="/"` 或空名标签。
3. **行首 `/` 的另一种来源**是引擎头注释里的路径/平台行（如 `Engine\Binaries\<Platform>` 前面的 `\`、`* / Foo` 行）。

## 2. 施工（`+40/−6`，三处）

### 2.1 `@param` 修饰符（`+32/−3`）

```cpp
case EExpect::Name:
{
    if (OutTextReader.GetCurrentChar() == ':')          // @param: Foo
    {
        OutTextReader.NextChar();
    }

    if (OutTextReader.GetCurrentChar() == '[')          // @param[in] / [out] / [in,out] Foo
    {
        while (!OutTextReader.IsEof() && OutTextReader.GetCurrentChar() != ']')
        {
            OutTextReader.NextChar();
        }

        if (!OutTextReader.IsEof())
        {
            OutTextReader.NextChar();
        }
    }

    while (!OutTextReader.IsEof() &&
        (OutTextReader.GetCurrentChar() == ' ' || OutTextReader.GetCurrentChar() == '\t'))
    {
        OutTextReader.NextChar();                        // 跳空格/制表（不进入 token 范围）
    }

    OutExpect = EExpect::Description;

    if (OutTextReader.EatWhile(名字谓词) == 0)
    {
        OutTextReader.Save();                            // 不许返回"未 Save"的空名 token

        return ETokenKind::Trivial;
    }

    return ETokenKind::Name;
}
```

所有跳过都用 `NextChar()`（**不 Save**），因此参数名 token 的范围仍只覆盖名字本身。

### 2.2 行首 `/` 止于行边界（1 行）

```cpp
return InChar != '@' && InChar != '\\' && InChar != '\n' && InChar != '\r';
```

### 2.3 空名标签不再产出（`+7/−2`）

`@`/`\` 分支在 `EatWhile(IsAlpha) == 0` 时返回 `Trivial`（而不是 `TagOther`），并先 `Save()`：

> 🔴 **这一处是本轮自己抓到的回归**：第一版写的是 `Bump()`（消费掉下一个字符）。全量生成后发现产物里 `&lt;Platform&gt;` 变成了 `lt;Platform&gt;`（`&` 被吃）——原因正是 `Engine\Binaries\<Platform>` 里那个裸 `\`。改成 `Save()`（只登记范围、不消费）后复测恢复（见 §3.3 用例 9）。

### 2.4 `GetTokenRange()` 原语**未改**

"未 Save 返回 `(0,1)`"这条仍留在代码里（属 `F-GEN3-013` 口径）；本轮改为**所有会产出 token 的出口都显式 `Save()`**，因此不再有"伪 range"被 `Slice` 消费。`Tokenize` 的空 range `break` 也**未动**。

## 4. 边界与残余

1. **`/` 只修到行边界**：行首 `/` 的**本行剩余内容**仍按标记丢弃（`/**`、`*/`、`///`、以 `/` 开头的路径行）。内容保全属 **`F-GEN3-005`**（无 `@brief` 的注释整体丢弃）→ B-163。
2. **`@ param`（`@` 后空格）现在是"丢弃该行文本"**：旧码把它变成畸形标签块（可见但非法），新码变成默认 tag 的描述（不打印）。两者都不理想；正确做法是把 `@` 当字面文本，需要与 F-GEN3-005 一起做。
3. **裸 `\` 仍被当标签起始**：`Engine\Binaries\<Platform>` 仍产出 `<Binaries>` 标签（`<Platform>` 文本保留）。改它需要"反斜杠在什么上下文才是标签"的裁定，本轮未做。
4. **`GetTokenRange()` 与 `Tokenize` 的空 range 语义未动**（`F-GEN3-013`）：本轮只保证"所有出口都 `Save()`"，原语的 `(0,1)` 伪值仍在。
5. **判据范围**：探针 10 例 + 全量 16 231 文件的行级 diff；未覆盖 Mono/LeanCLR（与转换器无关）与中文注释编码（`F-GEN3-011` 口径）。

## 7. 过程事实（装置坑）

1. **"改前内容"必须重新生成一次**：manifest 哈希能定位"变了哪 8 个"，但要证明"只有文档行变化"必须拿到改前**内容** ⇒ 回退转换器 → 重建 → 重新生成 → 存档 → 恢复。这一轮实际跑了 3 次全量生成。
2. **`Copy-Item <目录> <已存在的目录> -Recurse` 会生成嵌套目录**：一次把 `after\Script` 拷到 `Script` 得到 `Script\Script\…`（8 文件），已删除并改为逐文件复制。清单校验（`changed=0 / total=16231`）才发现该问题。
3. **探针首版掩盖了一个真回归**：`Bump()` 版探针 8 例全"通过"，但产品级 diff 抓出 `lt;Platform&gt;`（丢 `&`）——**探针覆盖不到"空名标签后紧跟内容"这一类**，是 §3.2 的全量 diff 兜住的。

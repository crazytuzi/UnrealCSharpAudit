## 1. 第 0 步：把登记的"最小修法"测掉

登记的候选①是"`CompileParam` 追加 `-nodeReuse:false`"。**实测无效**：

| 观测 | 结果 |
|---|---|
| 该参数是否被 SDK 接受 | ✅ 接受（`dotnet msbuild -help` 列有 `-nodeReuse:<parameters>`，简写 `-nr`）；代价 +0.6 s（2.9 s → 3.5 s） |
| 基线构建后 `MSBuild.exe` 节点数 | **无新增**（全程只剩一个 9/30 就已经存在的 `MSBuild.exe`） |
| 加 `-nodeReuse:false` 构建后 | **同样无变化** |
| 存活的 `dotnet` 宿主 | **6 个**（含两个本轮新起的） |

**结论**：`dotnet build`（SDK 版）跑的是**进程内 MSBuild**，根本不派生 `MSBuild.exe` 工作节点 ⇒ `-nodeReuse:false` 管的那类节点在这里**不存在**；真正可能持锁的是 **SDK 常驻 build server**（`dotnet` 宿主 / VBCSCompiler），而它的开关是 **`--disable-build-servers`**（同样被接受、同样 +0.6 s）。

⇒ **① 由 `-nodeReuse:false` 改为 `--disable-build-servers`**（登记建议就地更正，详见 §4）。

```cpp
// :407-439
void FCSharpCompilerRunnable::ShutdownBuildServer()
{
	static auto CompileTool = FUnrealCSharpFunctionLibrary::GetDotNet();

	void* ReadPipe = nullptr;

	void* WritePipe = nullptr;

	FPlatformProcess::CreatePipe(ReadPipe, WritePipe);

	auto ProcessHandle = FPlatformProcess::CreateProc(
		*CompileTool,
		TEXT("build-server shutdown"),
		true,
		false,
		false,
		nullptr,
		0,
		nullptr,
		WritePipe,
		ReadPipe);

	if (ProcessHandle.IsValid())
	{
		FPlatformProcess::WaitForProc(ProcessHandle);
	}

	FPlatformProcess::CloseProc(ProcessHandle);

	FPlatformProcess::ClosePipe(ReadPipe, WritePipe);
}
#endif
```

**把 `CompileGame` 的单次构建改成一个可重跑的 lambda + 一次失败重跑**：

```cpp
// :441-489
bool FCSharpCompilerRunnable::CompileGame(FString& OutResult, const TFunction<void(const FString&)>& InOnOutput)
{
	if (!IFileManager::Get().FileExists(*FUnrealCSharpFunctionLibrary::GetGameProjectPath()))
	{
		return false;
	}

	static auto CompileTool = FUnrealCSharpFunctionLibrary::GetDotNet();

	const auto BuildGame = [this, &OutResult, &InOnOutput](const bool bDisableBuildServer)
	{
		auto bBuildSucceeded = false;

		const auto CompileParam = FString::Printf(TEXT(
			"build \"%s\" --nologo -c %s%s"
		),
		                                          *FUnrealCSharpFunctionLibrary::GetGameProjectPath(),
		                                          *GetBuildConfiguration(),
		                                          bDisableBuildServer ? TEXT(" --disable-build-servers") : TEXT("")
		);

		FUnrealCSharpFunctionLibrary::SyncProcess(CompileTool, CompileParam,
		                                          [&bBuildSucceeded, &OutResult](const int32 InReturnCode,
		                                                                         const FString& InResult)
		                                          {
			                                          bBuildSucceeded = InReturnCode == 0;

			                                          OutResult = InResult;
		                                          },
		                                          FString(), InOnOutput,
		                                          [this]()
		                                          {
			                                          return bIsStopped || GExitPurge;
		                                          });

		return bBuildSucceeded;
	};

	auto bSucceeded = BuildGame(true);

	if (!bSucceeded && !bIsStopped && !GExitPurge)
	{
		ShutdownBuildServer();

		bSucceeded = BuildGame(false);
	}

	return bSucceeded;
}
```

**四处刻意的设计（都可复核）**

1. **首次带 `--disable-build-servers`、重跑不带** —— 重跑前刚执行过 `build-server shutdown`，此刻链路上已无常驻 server；不带参数可避免"每次失败都额外付一次 server 冷启代价"。
2. **只重跑一次**（`if` 而非 `while`）—— 无循环风险；`bIsStopped`/`GExitPurge` 守卫使关机/退出路径不会多跑一次构建。
3. **失败仍只打印一次结果**（`OutResult` 被重跑覆盖）—— 与既有行为一致（调用方 `CompileInternal` 在 `!bSucceeded` 时打一条 `LogUnrealCSharp: Error`）；**没有新增日志**。
4. **`OnComplete` 由引用捕获改为捕获 `OutResult` 的引用 + 局部 `bBuildSucceeded`** —— 因为 lambda 需要被调用两次，把状态收进每次调用的局部量，避免跨次残留。

## 6. 复用价值（给下一轮）

1. 🟢 **"`dotnet build` 不派生 `MSBuild.exe` 节点"** 是本轮最贵的知识：`-nodeReuse:false` 对它无效，能控的是 `--disable-build-servers` 与 `dotnet build-server shutdown`。**先数节点再选参数**（本轮判据 = 构建前后 `Get-Process MSBuild` 计数）。
2. 🟢 **文件锁不一定快速失败**：同一个 `FileShare.None` 锁，**外部 `csc` 快速失败（27.8 s）**，而**编辑器内构建有时会等锁**（D 趟：68.8 s、零 CS2012、`Game.dll` 正常前进）⇒ **"构建耗时变长"与"构建失败"必须用日志区分**，不能只看时间。
3. 🟢 **`lock-ue-obj-dll.ps1` 是可复用的 CS2012 正控**：支持 `-HoldSeconds`（时长释放）与 `-FlagFile`（**信号释放**，用于卡"首次失败之后、重跑之前"这类窄窗口）。**锁必须由独立进程持有**，否则测试恒真。
4. 🪤 **正控要选对"需要重编"的目标**：锁 `obj/UE.dll` 但只 touch `Script/Game` 下的文件 ⇒ `UE.csproj` 增量判定跳过 ⇒ `csc` 从不打开被锁的文件 ⇒ **锁根本没被碰到**（`FBLD023-B` 实测）。
5. 🪤 **不要在跑装置时并行跑套件**：两者共享 `Content/Script` 与 `Script/**/obj`，会同时污染"套件基线"与"装置耗时"（本轮踩到一次，已重跑）。
6. 🟢 **重跑构建的状态要从 `OnComplete` 里搬进每次调用的局部量**：原实现的 `OnComplete` 闭包捕获的是函数级 `bSucceeded`，一旦构建被调用两次就会跨次残留。

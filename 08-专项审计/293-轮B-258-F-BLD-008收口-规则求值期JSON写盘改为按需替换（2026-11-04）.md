## 2. 施工

```csharp
var JsonText = new StringBuilder();

using (var Writer = new JsonWriter(new StringWriter(JsonText)))
{
	// …与原实现完全相同的 41 行 Write*（仅块作用域多一层缩进）
}

if (!File.Exists(JsonFullFilename) || File.ReadAllText(JsonFullFilename) != JsonText.ToString())
{
	File.WriteAllText(JsonFullFilename, JsonText.ToString());
}
```

**为什么是"内存构建 + 比较"而不是临时文件**：
- `JsonWriter` 有 `JsonWriter(TextWriter)` 重载 ⇒ 直接写进 `StringWriter`，**完全不落盘**；
- `StringWriter.NewLine` 与 `StreamWriter` 一样取 `Environment.NewLine`，`JsonWriter` 的 `WriteLine()` 走 `TextWriter.WriteLine()` ⇒ 内存文本与旧文件**逐字节一致**（见 §3 的首轮 SHA 证据）；
- 只有文本不同才 `File.WriteAllText`（默认 UTF-8 无 BOM，与旧 `StreamWriter` 相同）；
- 相比临时文件方案：**不产生 `.tmp`**、无临时文件清理与异常残留问题、逻辑更短。

## 4. 边界

1. **"内容相同"才有收益**：模块/插件集合变化时仍会写盘（预期行为）。
2. **整份 JSON 在内存中构建**（≈272 KB），相对规则求值本身（秒级）可忽略。
3. **非原子写**：`File.WriteAllText` 截断+写入，与改前的 `StreamWriter` 覆盖等价（本文件是可再生的构件，不需要原子性）。
4. **无临时文件**：不像临时文件方案那样存在 `.tmp` 残留或清理逻辑。
5. 写入失败（磁盘/权限）语义与改前一致：异常冒泡到 UBT。

## 1. 第 0 步前提回核（**两处对审计原文的更正**）

### 1.1 `F-CB-009`：物化点不是"前置生成器"，而是**域初始化**；commandlet 会话里整趟都是 0

审计原文（`:644-649`）说：`FClassGenerator`/`FStructGenerator` 经 `FBindingClass::Get*Names`（`FBindingClass.cpp:31/49`）**顺手物化**，`FBindingClassGenerator` 靠这个副作用拿数据。**探针实测把这条链改写了**：

| 会话 | 判据（同一二进制、环境门控探针） | 读数 |
|---|---|---|
| 编辑器会话 | `Generator()` 函数体**第一行之前**（`phase=pre-scope`，即 `FScriptDomainTypeScope` 之前） | **69** |
| 编辑器会话 | 其后每个相位（solution / code-analysis / dynamic-generator / begin-generator / class 前） | 全 **69** |
| **commandlet 会话** | 同上全部相位 | 全 **0** |

⇒ **两处更正**：
1. **编辑器会话里根本轮不到 `FClassGenerator`**：注册表在 `Generator()` 之前就已被物化（最早可测点在函数入口前，判据 = `pre-scope classes=69`）——物化者是**编辑器启动期的域初始化**（`FScriptDomainTypeScope` 之前），不是类/结构体生成器。原判"依赖前置生成器的副作用"**在编辑器会话不成立**。
2. **commandlet 会话里原判成立、且比原文更严重**：整趟（含 `FClassGenerator` 之后）都是 **0** ⇒ `FBindingClassGenerator::Generator()` **一个绑定类都不生成**，且**没有任何插件侧报错**（该会话 `LogUnrealCSharp` 行数 = **0**）。

⇒ 这条不再只是"API 语义陷阱"：**`-run=GeneratorScriptCode`（CI/打包路径）下 interop 绑定类不重新生成**是**实测症状**（旧产物留在盘上 ⇒ "改了 `Binding/**` 声明却看不到新 API"的静默陈旧）。⚠️ 该会话**不会**删除旧产物 —— 删除面被 `FGeneratorCore.cpp:1065` 的 `if (!IsRunningCommandlet())` 关掉了（见 §3.3）。

### 1.2 `F-GEN2-005`：复算统计 ＋ 把"窗口"定位到**具体两个枚举**

- **复算**（产物侧全量扫描，`Script/UE/Proxy` + `Script/Game/Proxy` = **16 230** 个 `.cs`）：枚举声明 2 396 个，其中 `: long` **426**（审计原文 419；差值来自此后又跑过生成 —— 本轮所有读数都以**本轮实测**为准）。
- **引用面**：426 个 `long` 枚举名在 **13 834** 个非枚举产物中命中 **0**；在 **85** 个手写 `.cs`（非 `Proxy`）中命中 **0** ⇒ 当前语料**无消费者**。
- **窗口定位**（探针 `map` 计数）：改前 `enumpass-enter map=1960 / exit 1960 / endgenerator **1962**` ⇒ **2 个枚举在"枚举声明之后"才被注册**，名字为 **`ETestDynamicEnum`**、**`BP_TestEnum`**。🔴 **但这两个都`不由枚举生成器声明**：前者是动态枚举（被 `FEnumGenerator.cpp:30` 的 `IsDynamicEnum` 过滤）、后者是 BP 枚举（走 `FAssetGenerator` → 回退恒为 `byte`）⇒ **本语料下窗口不产生"声明宽度 ≠ 属性宽度"**。
- **值域分布**（426 个，按新规则）：`byte` 409 / `ushort` 9 / `sbyte` 3 / `uint` 3 / `long` 2。
- ⛔ **审计建议里的两处不采纳**：① "把 `FEnumGenerator::Generator()` 移到 `FClassGenerator` **之前**"——**方向相反**，那样会让**所有**枚举都走回退；② "命中回退时打 `UE_LOG(Warning)`"——与库内口径（不新增日志）冲突。
- 另外核实：`UEnum` **不携带**底层整数类型（`UEnum::CppType` = C++ **类型名**，非宽度；`FEnumParams` 里只有 `CppForm`，宽度只存在于 `FEnumProperty::GetUnderlyingProperty()`/`FByteProperty`）⇒ **"从 UEnum 直接取真实底层类型"这条路不存在**，回退只能用启发式（本轮改为"值域最小可容纳"）。

## 6. 未取得 / 边界（如实登记）

1. **`F-CB-009` 的"绑定类缺失"是"未重新生成"，不是"内容错误"**：commandlet 会话里旧产物留在盘上 ⇒ 若 CI 只看"命令成功 + 退出码"（另见 `F-ED2-021`：该 commandlet 退出码**恒为 0**），症状是**陈旧**而非报错。**未构造**"改声明→跑 commandlet→观察 C# 侧缺 API"的端到端用例。
2. **回退宽度收窄的收益未量化**：426 个枚举当前无消费者 ⇒ **没有**"改前读错值/踩内存"的对照读数；本条的判据是"集合可预测 + 可编译 + 套件无回归"。
3. **`uint` 3 个的符号面**：`ushort`/`uint` 与 C++ 侧可能是有符号类型（值域非负时数值等价，但 `-1` 之类的哨兵取值会不同）—— 未构造用例。
4. **未跑 LeanCLR**（库内长期残留项）；Mono 只跑套件、**未复跑生成器**（生成器是编辑器/命令let 侧，后端无关）。
5. **`_MAX` 哨兵与宽度收窄的交互**：新规则把哨兵值算进取值域 ⇒ 保证"要么哨兵放得下（随后被既有逻辑丢弃）、要么哨兵放不下（同样被丢弃）"，**未逐条对照**哪些枚举因此多/少一个 `_MAX` 成员（本轮 changed 集合里未见成员增减 ⇒ 未发生）。
6. **`ESkeletalMeshAsyncProperties` / `EPropertyBagChildRowFeatures` 仍为 `long`**：它们的取值跨越 int64 ⇒ 若将来被 1 B 属性引用，问题依旧（属"枚举语义本身越界"，不是回退值能救的）。
7. **探针的副作用（已如实登记）**：改后编辑器会话里，`pre-scope` 的早调用会**先**物化并生成 69 个类（此时 `OverrideFunctionsMap` 尚未加载）⇒ 探针跑的那一趟会先写一版内容略有差异的绑定产物；交付态（无探针）已重跑并以其产物为准（manifest diff 与本轮结论均取交付态）。

## 7. 复用价值（方法论）

1. **探针要放在"入口之前"才读得到未物化状态**：同一探针放在 `Generator()` 体内（`BeginGenerator` 之后）读到的是 69 —— 会得出"没有这个问题"的错误结论。**读到 0 的唯一位置是入口第一行之前**，且**只有 commandlet 会话**保持 0。
2. **同一二进制 + 环境门控 ⇒ 一轮构建跑两种会话**（编辑器/命令let），A/B 不受重编差异干扰。
3. **探针文件路径是相对 CWD 的**：UE 编辑器/命令let 的 CWD = `Engine\Binaries\Win64` ⇒ 读数不在工程目录下（本轮实测；库内既有轮次把它当作工程相对路径，值得更正）。
4. **产物清单 diff 必须与"离线预期集合"逐名对照**（本轮双向差集均为 0）：只报 `changed=424` 不能证明"改的正好是该改的"。
5. **生成器改动的"零差异"纪律要与"有意差异"区分**：本轮 `changed=424` 是**有意且可枚举**的（枚举宽度），`added/removed` 必须为 0。
6. **BOM/行尾是独立的回归面**：一次普通的 include 增删就会改掉文件 BOM ⇒ 交付前按 HEAD 逐文件核对 BOM 与 bare-LF（本轮实际踩到并修复）。
7. **harness tag 要重号检查**：`b11`/`b12` 已被上一轮矩阵占用 ⇒ 本轮改用 `b13-*`，避免覆盖他人证据。

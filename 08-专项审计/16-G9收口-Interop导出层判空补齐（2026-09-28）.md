## 2. 逐条改法（含引擎契约回核）

### 2.1 `F-INT2-008` 残余 —— `SpawnActor` 的 `FoundClass` 判空

- **改法**（`FRegisterWorld.cpp:125-146`）：把 `const auto FoundClass = …GetObject<UClass>(InClass);` 提升为**正向 `if` 包裹**，`SpawnActor` 与其后的 `Bind` 整体嵌进去；失败一律落到函数末尾既有的 `return InvalidManagedHandle;`。**零新增成员、零协议面**。
- **改前必崩的依据（引擎行级）**：`UWorld::SpawnActorAbsolute`（`LevelActor.cpp:417-436`）第 424 行 `Template = Class->GetDefaultObject<AActor>();` —— `Class` 无任何判空，而 C# 侧默认 `FActorSpawnParameters()` 的 `Template` 为 `null`（`:419-425` 的分支必然进入）⇒ 传 `nullptr` 类即空指针解引用。
- **可达性（C# 公共 API）**：`World.cs:9` 的 `SpawnActor<T>(UClass Class, FTransform Transform, FActorSpawnParameters = null)` 允许显式传 `null`（`HandleData.GetHandle(null)` = 0 ⇒ `GetObject<UClass>(0)` = `nullptr`）⇒ **本条是活跃崩溃**。运行期判据 `SpawnActorNullClass`（改后返回 `null`，不再进引擎）。

### 2.2 `F-INT2-009` 残余 —— `CreateWidget` 的 `Class` 判空（**含两处口径更正**）

- **改法**（`FRegisterUnreal.cpp:141-177`）：同样把 `Class` 提升为正向 `if` 包裹，五路 `IsA` 与 `Bind` 整体嵌入；失败落 `return InvalidManagedHandle;`。
- 🔴 **更正 1（可达性）**：报告的触发示例 `Unreal.CreateWidget<UMyWidget>(null, typeof(UMyWidget))` **与 C# 公共 API 不符** —— `Unreal.cs:62-80` 的 5 个重载按 **owner 类型**分派、类**取自 `T.StaticClass()`**，调用方**无法**传类。⇒ 本条残余**不是活跃崩溃**，是**防御性补齐**。
- 🔴 **更正 2（后果）**：报告称"`CreateWidget<UUserWidget>(Outer, nullptr)` 在引擎里会解引用 null 的 `UClass`"。实测引擎侧**有显式校验**：`UserWidget.cpp:2523` 的 `if (!CreateWidgetHelpers::ValidateUserWidgetClass(UserWidgetClass))` 早退（该 Helper 定义在 `:2742`）⇒ Class 为 null 的后果是**静默返回 `nullptr`**，不是崩溃。（`UserWidget.h:1778` 的 `FScopeCycleCounterUObject(空类, …)` 是否 null-safe **未逐行确认**，列入 §5 未取得。）
- 另一处**未采纳**：报告建议的"五路 `IsA` 不匹配时打 `UE_LOG` 警告"**按本仓口径不做**（不新增日志）；该分支的现状是 `Bind(nullptr)` → 引擎侧安全（`FCSharpBind.inl:56-61` 首行即判空回 `InvalidManagedHandle`），C# 收到 `default`。

### 2.4 `F-INT2-016`(11) —— 67 处"假判空"清零

- **对象**：`&X != nullptr`（对**引用**恒真、被编译器优化掉）作为"防御性判空"，其 `else` 分支（`decltype(...)()` 兜底）**永不生效**。唯一实际效果是让读者高估安全性。

### 2.5 `F-FN-003` —— `FManagedFunctionDescriptor::Invoke` 的 `InMethod` 守卫

- **改法**：函数体整体包进 `if (InMethod != nullptr) { … }`，末尾 `return false;`（原为恒 `return true;`）。**语义变化**：反射元数据缺失（`GetClass` 或 `GetParentMethod` 之一失败）时，**参数编组与 out 回写整体跳过**并通过返回值暴露失败 —— 这也顺带避免了失败路径上"编组出的复合句柄无人释放"（见 §5 未取得 ③）。

### 2.9 `F-INT2-014` —— **有据延后**（唯一未修项）

- **为什么不能在本轮修**：报告推荐的最小修法是"删掉裸指针重载，只留 `TArray<FVector2D>` 版本"。但该类构造函数的注册名是**按同名计数生成**的（`FClassBuilder::GetFunctionImplementationName` 用 `Algo::Count(Functions, InName)` 生成 `FBox2D`/`FBox2D1`/`FBox2D2`/`FBox2D3`），删除第 3 个重载会让第 4 个（`TArray<FVector2D>`）**从 `FBox2D3` 变成 `FBox2D2`** ⇒ **必须与 C# 产物重生成同轮**（产物头写着 `DO NOT modify this manually!`；手改产物无法证明与真实重生成逐字一致）。
- **本轮取到的证据**（供下一轮直接用）：
  - 触发面实测：产物把 `const FVector2D*` marshal 成**单个 `FVector2D` 的句柄**（`Script/UE/Proxy/Binding/Box2D.cs:79-94`：`*(nint*)InBuffer = HandleData.GetHandle(Points); *(int*)(InBuffer + 8) = Count;`）⇒ C# 侧**只能**提供 1 个 `FVector2D`，任何 `Count > 1` 都是**必然越界读**（`16 × (Count−1)` 字节）。
  - 等价安全重载就在紧邻两行（`:24-25` 的 `const TArray<FVector2D>&`、`:20-21` 的 `(InMin, InMax)`）。
  - 另一个可选路线（本轮**评估后不采用**）：保留注册名不变、把手写 thunk 插在 `TConstructorBuilder<FBox2D, const FVector2D*, const int32>::Invoke` 之前做 `Count` 钳制 —— 需要复制框架的 IN 缓冲布局知识（`TBufferOffset`）且要在 `[UnmanagedCallersOnly]` 语义上解释"Clamp 后的语义"，与本仓"最小、可读、无魔法偏移"的施工口径不符。
- **下一轮的动作清单**：① 删 `FRegisterBox2D.cpp:22-23` 的 `.Constructor(...)`；② 走**真实编辑器会话生成装置**（`Saved/Retest/run-g13-generate.ps1` 一类的会话生成，**不要**用 `-run=GeneratorScriptCode` —— 它会静默删除 107 个平台产物，`F-GENC-002/010`）；③ 用产物 manifest 对照证明只有 Box2D 两个文件变化且 `FBox2D3 → FBox2D2` 位移如预期；④ 用例侧补 `new FBox2D(new TArray<FVector2D>{…})` 与 `new FBox2D(Min, Max)` 两条。

## 2. 改动（6 文件 `+42/−0`）

每个描述符的 `Get(FMember)` 开头插入"值本身为空 ⇒ 返回无效句柄"：

| 文件 | 判空表达式 |
|---|---|
| `FSubclassOfPropertyDescriptor.cpp` | `Property->GetObjectPropertyValue(Src) != nullptr` |
| `FWeakObjectPropertyDescriptor.cpp` | `Property->GetObjectPropertyValue(Src) != nullptr` |
| `FLazyObjectPropertyDescriptor.cpp` | `Property->GetObjectPropertyValue(Src) != nullptr` |
| `FSoftObjectPropertyDescriptor.cpp` | `!Property->GetPropertyValue(Src).IsNull()` |
| `FSoftClassPropertyDescriptor.cpp` | `!Property->GetPropertyValue(Src).IsNull()` |
| `FInterfacePropertyDescriptor.cpp` | `Property->GetPropertyValue(Src).GetObject() != nullptr` |

> **为什么用引擎类型化访问器**：这六个守卫取的是"属性值是否已设置"，用引擎自己的访问器（`Property->GetObjectPropertyValue(Src)` / `Property->GetPropertyValue(Src)…`）即可 —— 这也是**同文件 `Identical` 的既有写法**（六个 `Identical` 均用 `Property->GetObjectPropertyValue(A)`，无一处 `static_cast`）。🔴 **软引用两项（`FSoftObject`/`FSoftClass`）刻意不用 `GetObjectPropertyValue`**：引擎实现是 `return GetPropertyValue(...).Get();`（`Engine/Source/Runtime/CoreUObject/Private/UObject/PropertySoftObjectPtr.cpp:277-280`）⇒ 它**会解析软引用、未加载时触发同步加载**，且会把"路径非空但未加载"也判成空 ⇒ 与"未设置 ⇒ 读回 null"的语义不符；改用 `GetPropertyValue(Src).IsNull()` 同时拿到**类型化访问器**与**不解析**。验证：UBT ＋ 套件（CoreCLR ×2 ＋ Mono ＋ 恢复态）**1922 / 0**、与上一交付**逐行 0 差异**。

```cpp
// 以 FSubclassOfPropertyDescriptor 为例
void FSubclassOfPropertyDescriptor::Get(void* Src, void** Dest, FPropertyArgument::FMember) const
{
	auto Object = InvalidManagedHandle;

	if (Property->GetObjectPropertyValue(Src) != nullptr)
	{
		Object = FCSharpEnvironment::GetEnvironment().GetMultiObject<TSubclassOf<UObject>>(Src);

		if (!IManagedHandleIsValid(Object))
		{
			if (Class != nullptr)
			{
				Object = Class->NewObject(true);

				FCSharpEnvironment::GetEnvironment().AddMultiReference<TSubclassOf<UObject>, false, true>(
					Class, Object, Src);
			}
		}
	}

	*reinterpret_cast<IManagedHandle*>(Dest) = Object;
}
```
> ⚠️ **轮 B-8 当时**的形状是"开头 `if (static_cast<const T*>(Src)->… == nullptr) { 写 InvalidManagedHandle; return; }`"（`+42/−0`）；该形状已按维护者口径先后改为 **`if(条件)` 单一出口**（轮 B-10）与**引擎类型化访问器**（2026-10-12，见上表末注）—— 两次都是纯等价重构，读数逐行 0 差异。

- 与轮 B-5 的 `TMultiPropertyValue::IsNull` **语义逐类型对齐**（`Get()` / `IsNull()` / `GetObject()` 三类），函数值路径不受影响（见 §4）。
- 未新增注释/日志/异常/公开 API。

## 4. 范围界定：为什么只改 `Get(FMember)`

| 路径 | 空值表示 | 两条路径是否一致 |
|---|---|---|
| **属性读**（本轮的 `FMember`） | 绑定读 = `null`（轮 B-5）／反射读 = 本轮的 `null` | ✅ **一致**（本轮修的就是这里） |
| **函数值**（`FParameter` / `FReturn`） | 绑定侧 `TMultiPropertyValue::Get<IsReference>(InMember)` 与反射侧对应重载**都**无条件新建包装 ⇒ **空值 = 空包装** | ✅ **一致**（属**另一套约定**，不是不一致） |

⇒ 上一轮报告里"`FParameter`/`FReturn` 未覆盖"的说法本轮**精确化**为：**函数值的空值约定与属性读不同，但两条路径彼此一致**；若要统一成 `null`，那是一次**跨函数值面的约定变更**（会波及出参/返回值 marshalling），需单独裁定 —— 本轮**不做**，已登记（§5）。

## 6. 复用价值

1. **"撤回理由"必须复查其判据前提**：轮 B-5 撤回 6 处守卫的理由是"无实测效果"，但那是**判据前提错误**（载体属性默认非空 ⇒ 守卫从未被空值触发）⇒ 正确表述应是"**未测**"。**结论：把"没测出来"写成"没效果"，会把真缺陷留在地下。**
2. **一对同族路径要一起建判据**：绑定/反射是同一语义的两条实现，只修一条会让"清空后判空"取决于该属性是绑定的还是反射的 —— 这类**路径相关语义**必须成对判据化。
3. **载体默认值先查构造函数**（轮 B-6 教训的第二次应用）：反射 actor 与绑定 actor 都有非空默认 ⇒ 空值场景一律"先写非空、再写 null"。
4. **范围界定要落到"是否一致"而不是"是否覆盖"**：函数值的空值约定与属性读不同但两路径一致 ⇒ 正确结论是"**另一套约定**"，而不是"未覆盖的缺陷"。

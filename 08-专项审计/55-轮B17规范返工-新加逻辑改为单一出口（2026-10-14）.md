## 1. 逐处对照（原写法 → 新写法）

### 1.1 `TMethodHelper.inl`（B-15 引入；`Result` 转换）

```cpp
// ✗ 返工前（守卫式提前 return）
if constexpr (!std::is_void_v<Result>)
{
    if (ReturnValue == ExceptionManagedHandle || !IManagedHandleIsValid(ReturnValue))
    {
        return DefaultReturn();
    }

    auto Value = TPropertyValue<Result, Result>::Get(ReturnValue);

    FDomain::GCHandle_Free(ReturnValue);

    return Value;
}

// ✓ 返工后（默认值 → if(条件) 内做原逻辑 → 单一出口）
if constexpr (!std::is_void_v<Result>)
{
    Result Value{};

    if (ReturnValue != ExceptionManagedHandle && IManagedHandleIsValid(ReturnValue))
    {
        Value = TPropertyValue<Result, Result>::Get(ReturnValue);

        FDomain::GCHandle_Free(ReturnValue);
    }

    return Value;
}
```
⇒ 兜底**直接声明 `Result Value{};`**（与既有 `DefaultReturn()` 的 `Result{}` 同一语义；**不写"临时对象 ＋ `auto` 拷贝初始化"** —— 维护者复核后细化）。

### 1.2 `FDomain::GetTraceback`（B-15 引入）

```cpp
// ✗ 返工前
const auto Traceback = TracebackMethod->Runtime_Invoke();

if (Traceback == ExceptionManagedHandle || !IManagedHandleIsValid(Traceback))
{
    return {};
}

auto Result = StringToFString(Traceback);

GCHandle_Free(Traceback);

return Result;

// ✓ 返工后
const auto Traceback = TracebackMethod->Runtime_Invoke();

FString Result;

if (Traceback != ExceptionManagedHandle && IManagedHandleIsValid(Traceback))
{
    Result = StringToFString(Traceback);

    GCHandle_Free(Traceback);
}

return Result;
```

### 1.3 `FEnumGenerator::GetEnumUnderlyingTypeName`（B-11 引入；**本轮最严重的一处**）

```cpp
// ✗ 返工前：12 个 if (...) return ...; 串成回退链
if (InEnum->IsA(UUserDefinedEnum::StaticClass()))
{
    return TEXT("byte");
}
… 统计 Min/Max …
if (MinValue >= 0 && MaxValue <= MAX_uint8) { return TEXT("byte"); }
if (MinValue >= MIN_int8 && MaxValue <= MAX_int8) { return TEXT("sbyte"); }
… 共 6 档 …
if (MinValue >= 0) { return TEXT("ulong"); }
return TEXT("long");

// ✓ 返工后：默认值写在第一行 ＋ else if 链 ＋ 单一出口
auto UnderlyingTypeName = FString(TEXT("long"));

if (InEnum->IsA(UUserDefinedEnum::StaticClass()))
{
    UnderlyingTypeName = TEXT("byte");
}
else
{
    … 统计 Min/Max …
    if (MinValue >= 0 && MaxValue <= MAX_uint8)      { UnderlyingTypeName = TEXT("byte"); }
    else if (MinValue >= MIN_int8 && MaxValue <= MAX_int8) { UnderlyingTypeName = TEXT("sbyte"); }
    … 共 6 档 …
    else if (MinValue >= 0)                          { UnderlyingTypeName = TEXT("ulong"); }
}

return UnderlyingTypeName;
```
**为什么这处最严重**：B-11 之前这里是**一条三元 `return`**（`IsA(UUserDefinedEnum) ? "byte" : "long"`），我把它换成了 12 个提前 `return` —— 不只是风格问题：该函数**上方还有先于本轮存在的早退**（映射表命中即返回），两者混在一起后"哪些分支只是枚举、哪个才是默认值"不可读；改写后**默认值就在第一行**。

## 5. 复用价值（方法论）

1. **风格返工必须做产物级证明**：生成器文件的"等价改写"要重跑生成并**逐字节比对**（本轮 0 差异），否则无法排除"分支顺序/默认值被无意改动"；
2. **测试通过 ≠ 规范合规**：本轮 3 处违规里，B-15 的 2 处**已通过编译与 1923/0 的套件**，只有维护者复核才发现 ⇒ 提交前应把"**新加分支是否写成 `if(条件)` ＋ 单一出口**"作为固定自检项；
3. **默认值优先复用既有语义、形态用直接声明**：`Result Value{};` 与既有 `DefaultReturn()` 的 `Result{}` 同义；局部变量**直接声明**（`FString Result;`），不写"临时对象 ＋ `auto` 拷贝初始化"（维护者复核后细化）；
4. **改动面要克制**：既有早退留在原处（§3），把"规范返工"限制在**本轮新加的逻辑**上，避免一次提交混入两种性质的变化。

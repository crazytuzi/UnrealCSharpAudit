## 2. 施工

`Script/Weavers/UnrealTypeWeaver.cs`（类 `ProcessUClassProperty` 与结构体 `ProcessUStructProperty` **两处同改**）：

```csharp
if (backingField != null && RewriteBackingFieldReferences(Type, Property, backingField))
{
    Type.Fields.Remove(backingField);
}
```

新增私有 helper（`private static`，与既有 `IsCompound` / `GetTypeSize` 同形）：

```csharp
private static bool IsBackingFieldReference(Instruction Instruction, FieldDefinition BackingField)
{
    return Instruction.Operand is FieldReference Field && Field.Resolve() == BackingField;
}

private static bool RewriteBackingFieldReferences(TypeDefinition Type, PropertyDefinition Property,
    FieldDefinition BackingField)
{
    var Methods = Type.Methods
        .Where(Method => Method.HasBody)
        .Where(Method => Method != Property.GetMethod && Method != Property.SetMethod)
        .ToList();

    var Instructions = Methods
        .SelectMany(Method => Method.Body.Instructions)
        .Where(Instruction => IsBackingFieldReference(Instruction, BackingField))
        .ToList();

    if (Instructions.Count == 0) { return true; }

    if (BackingField.IsStatic || Instructions.Any(Instruction => Instruction.OpCode != OpCodes.Stfld))
    {
        return false;
    }

    foreach (var Method in Methods)
    {
        var ILProcessor = Method.Body.GetILProcessor();

        foreach (var Instruction in Method.Body.Instructions.ToList())
        {
            if (IsBackingFieldReference(Instruction, BackingField) && Instruction.OpCode == OpCodes.Stfld)
            {
                ILProcessor.InsertAfter(Instruction, Instruction.Create(OpCodes.Pop));
                ILProcessor.InsertAfter(Instruction, Instruction.Create(OpCodes.Pop));
                ILProcessor.Remove(Instruction);
            }
        }
    }

    return true;
}
```

**三个关键决定**：

1. **排除访问器**：getter/setter 自身引用该字段（`ldfld`/`stfld`），但它们随后被 `ilProcessor.Clear()` 整体重写 ⇒ 若把访问器算进扫描，"引用不全为 `stfld`"会**永远成立**、字段永远删不掉（首版即此坑，见 §7）。
2. **`pop; pop` 而不是"删三条指令"**：`stfld` 前是 `[this, value]` 两个栈元素，`pop; pop` **原地平衡**，不需要按栈深度反推值表达式的起点（任意复杂初始化器都安全）。
3. **不能改写时保留字段**：`ldfld`/`ldflda`/静态字段 ⇒ `return false` ⇒ **不删字段**（构建仍有效；这类引用不在初始化器路径上，属极端形态）。

**生成物形状（改后，`UTestPropertyInitializer`）**：

```csharp
// .ctor
ldarg.0
ldc.i4.5
pop
pop
ldarg.0
call UObject::.ctor()
ret
```

字段表 = `StaticClassSingleton` ＋ `__Value`（`<Value>k__BackingField` 已删）。

## 5. 未取得 / 边界

1. **初始化器值被丢弃**：`= 5` **不会**写进 UE 属性（值由 UE 默认值决定）。这是与 `[UProperty]` 设计一致的处置（原报告 §建议 1），但对用户是**静默语义变化**；若需要"初始化器生效"，必须新增"构造后初始化"通道（weaver 生成 init 方法 ＋ `ObjectBridge.NewObject` 在 `Alloc` 之后回调）—— 属新设计，本轮不做。**触发重估** = 出现"用户依赖 `[UProperty] = 值`"的实证。
2. **未做运行期实例化判据**：动态类的 `[UClass]` 实例由原生侧创建（`ObjectBridge.NewObject` = `Activator.CreateInstance` 后 `Alloc`），C# 侧直接 `new` 不代表真实创建路径；本轮判据是"构建 ＋ IL 形状 ＋ 套件回归"，**没有**跑"实例化后读回 Value"。
3. **`ldfld`/`ldflda`/静态字段形态未构造用例**：走"保留字段"分支（构建有效，字段残留）。
4. **只测 CoreCLR / Win64**；weaver 与后端无关，但套件只在 CoreCLR 上跑。
5. **未加诊断**：`[UProperty] = 值` 现在**静默丢弃**；原报告"至少要有诊断（`WeavingException`）"这一选项未采纳 —— 理由：诊断会让带初始化器的用户代码**仍然构建失败**（只是错误更清楚），与本轮"先让构建通过"的目标冲突；登记为可选后续。

## 7. 复用价值

1. **"删元数据但留 IL 引用"的正确判据 = 构建本身**：本例中 Cecil 在 Write 阶段直接抛 `ArgumentException`（exit 1），比"构造运行期用例"更快、更硬；任何 weaver 改动都应把"改前后各构建一次"当第一判据。
2. **`pop; pop` 是"丢弃一次栈写入"的通用手法**：不需要反推值表达式的起点，适用于任意复杂初始化器；比"删除 `ldarg.0` ＋ 值指令"稳。
3. **扫描范围要排除"即将被重写的访问器"**：否则"引用不全为 `stfld`"恒成立、字段永远删不掉 —— 这是本轮第一版的实际坑（IL 检查看到字段仍在才发现）。
4. **部署副本必须同步改**：工程构建用的是 `Script/Weavers/…`（部署副本），插件 `Script/Weavers/…` 是模板；只改模板 ⇒ 构建用旧 weaver、`LookupToken` 照旧。归一化占位符后的 `diff = 0` 是"模板 ≡ 副本"的可复核判据。

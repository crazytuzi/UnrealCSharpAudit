## 2. 机理

```csharp
// TaskInfo.Invoke（TaskInfo.cs:14-24）—— finally 一定放行等待句柄
try { CallBack?.Invoke(State); }
finally { WaitHandle?.Set(); }
```

`Process()`（B-199 之后）逐任务 `catch (Exception) { }` ⇒ 异常不再穿出，但 `WaitHandle` 已在 `finally` 里 `Set()` ⇒ `Send` 的 `WaitOne()` 返回、方法正常结束。**队列保住了，错误却丢了**：`System.Threading.SynchronizationContext.Send` 的契约是"回调的异常抛回发送方"。

## 3. 修法（E4）

```csharp
// SynchronizationContext.cs:109-140（改后）
using var ResetEvent = new ManualResetEvent(false);

ExceptionDispatchInfo? Error = null;

lock (TaskList)
{
    TaskList.Add(new TaskInfo
    {
        CallBack = _ =>
        {
            try { InCallback(InState); }
            catch (Exception Exception) { Error = ExceptionDispatchInfo.Capture(Exception); }
        },

        State = null,

        WaitHandle = ResetEvent
    });
}

ResetEvent.WaitOne();

Error?.Throw();
```

- **只动 `Send`**：`Post` / `Process` / `Deinitialize` / `TaskInfo` 全部不变（`TaskInfo` 也不需要加字段，`Error` 由闭包捕获）；
- **执行顺序不变**：回调仍在 GT 上执行，`WaitHandle` 仍由 `TaskInfo.Invoke` 的 `finally` 释放；
- **栈保真**：`ExceptionDispatchInfo.Capture` ＋ `Throw()` 保留原始抛出点，接收端看到的栈含"回调里 throw → Send 里 rethrow"两段。

## 5. 残余与边界

1. **`Post` 的异常仍被吞掉**：`Post` 没有等待方，无处回传；保持 B-199 的行为（不让异常穿出边界）。
2. **`Send` 仍无超时**：关停期 `Tick` 不跑时，`WaitOne()` 会一直阻塞 —— 与 `F-CS2B-011` 的排空面相邻，未在本轮改（改动会引入新的超时语义）。
3. 本轮不改变"同一线程 `Send` 内联执行"的路径（异常本来就直接抛给调用方）。

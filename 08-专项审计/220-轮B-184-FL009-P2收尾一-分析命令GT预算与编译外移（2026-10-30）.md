## 1. 分析命令对象（GT 预算）

### 1.1 新接口（`FCodeAnalysis.h`）

```cpp
struct FCommand
{
	FString Program;

	FString Param;
};

static FCommand MakeCompileCommand();                              // GT：内含 GetDotNet()/项目路径
static FCommand MakeFileAnalysisCommand(const FString& InFile);    // GT：单文件分析命令
static FCommand MakeAnalysisCommand();                             // GT：全量分析命令
static void RunCompile(const FCommand& InCommand);                 // 任意线程：IsProgramOutdated 闸门 + Run
static void Run(const FCommand& InCommand);                        // 任意线程：SyncProcess
```

- `CodeAnalysis()` / `Analysis(File)` 保留为"GT 同步"便捷入口（命令行/兼容路径），内部改为 `Run(Make…())`。
- 所有 `GetDotNet()`（读 `UUnrealCSharpEditorSetting` CDO）与 `GetScriptDirectory()`（同）**只在 GT 调用**；后台任务只持 `FString Program/Param`。

### 1.2 调用方改法（4 处）

| 调用方 | 改法 |
|---|---|
| `FEditorListener::OnPostEngineInit` | GT 构建 compile＋analysis 两条命令 → 投递任务内依次 `RunCompile`/`Run` → GT 续跑 `CodeAnalysisGenerator` |
| `FEditorListener::OnCompile` | GT 去重文件并逐文件 `MakeFileAnalysisCommand` → 投递一个任务顺序 `Run` |
| `UnrealSharp.Editor.CodeAnalysis` 控制台 | 同 post-init（无续跑） |
| `Generator` 第一段 | 同 post-init（续跑 = `GeneratorInternal`） |
| 工具栏单文件 | GT `MakeFileAnalysisCommand` → 投递 `Run` |

## 2. 编译外移（第二段末尾）

```cpp
// GeneratorInternal（原：FCSharpCompiler::Get().ImmediatelyCompile(bForceCompileInterop);）
	if (IsRunningCommandlet())
	{
		FCSharpCompiler::Get().ImmediatelyCompile(bForceCompileInterop);
	}
	else
	{
		FCSharpCompiler::Get().EnqueueTask([bForceCompileInterop]()
		{
			FCSharpCompiler::Get().ImmediatelyCompile(bForceCompileInterop);
		});
	}
```

- 编辑器路径：编译在**编译器线程**执行；`CompileInternal` 的 `Reload` 仍通过 `CreateAndDispatchWhenReady(..., GameThread)` 派发回 GT（`FCSharpCompilerRunnable.cpp:681-693`），非 GT 调用方会等待其完成 ⇒ **动态类重建仍在 GT**。
- 命令行路径：`IsRunningCommandlet()` ⇒ 原同步行为（进程即退，必须同步）。
- 语义差异：`OnEndGenerator` 现在**早于**编译完成（生成期标志先落，编译随后跑）；`OnCompile` 广播仍在 `Reload` 内。

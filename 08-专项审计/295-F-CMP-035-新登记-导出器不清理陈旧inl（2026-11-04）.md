## [F-CMP-035] 导出器只写不删：全量导出后仍残留其它引擎版本的陈旧 `.inl`

- **类别**: 一致性 / 产物卫生（可优化）
- **严重度**: **P3**
- **文件**: `Source/SourceCodeGenerator/SourceCodeGenerator.cs`（`Finish()` 与 `SaveIfChanged()`；全文件**无任何删除/清理逻辑**——grep `Delete`/`Directory.Delete` 命中 0）
- **函数**: `SourceCodeGeneratorUbtPlugin.SourceCodeGenerator::Finish()` / `SaveIfChanged()`
- **置信度**: 高（产物实测 + 代码事实）

**现状（代码事实）**

```csharp
// SourceCodeGenerator.cs：只有写，没有删
private void SaveIfChanged(string file, StringBuilder builder)
{
	if (File.Exists(file) && File.ReadAllText(file) == builder.ToString())
	{
		return;                       // 内容相同 ⇒ 跳过
	}

	Factory.CommitOutput(file, builder);   // 否则写盘
}
```
全文件 `Delete` / `Directory.Delete` 命中 **0** ⇒ 本次导出**不会**删除上一次导出留下、但本次不再生成的文件。

**产物实测（2026-11-04，5.6 全量导出 1 912 个 `.inl`）**

| 读数 | 值 |
|---|---|
| `Inc/UnrealCSharp/UHT/*.inl` 总数 | **1 912**（B-257 之前目录里只有 631 个陈旧文件） |
| mtime 早于今日（未被重写） | **10**（全部 = `2026-05-16 15:03:18`） |
| 内容指向其它引擎版本的 `#include` 行 | **11** 行，全部指向 `D:\file\UnrealEngine\5.7\…` |
| 例 | `SizeBoxComponent.binding.inl`、`WidgetNavigation.binding.inl`、`MaterialExpressionAggregate.binding.inl`、`BlueprintSpringMathLibrary.binding.inl` |

**调用上下文**
`Finish()` 在每次 UHT 导出末尾调用（`SourceCodeGenerator.cs` 的导出器入口 → `Generate()`）；`SaveIfChanged` 决定是否写盘。目录 = `<Plugin>/Intermediate/Build/<Platform>/<Target>/Inc/UnrealCSharp/UHT/`。

**问题**
1. 产物目录会**跨引擎版本/跨导出配置混用**：本次运行不再导出的类，其旧 `.inl` 原样留着（本例 11 行绝对 include 指向 5.7 安装路径）。
2. 若有消费者（本工程内 `.header.inl`/`.binding.inl` 无编译期消费者，但外部工程可能 include），会拿到**错误引擎路径**的 include。
3. 污染"生成 delta 0"类判据：新旧文件混在一起时，"本机 631 vs 1 912"这类基线读数无法直接比较（B-257 就踩到）。

**建议**
- 在 `Finish()`（或导出开始时对 full export）按"**本次写出的文件名集合**"删除目录内不在集合中的 `*.inl`；或**先清空该目录再写**（需与 UHT 的增量缓存行为对齐，二者在 submodule 里，按 `SourceCodeGenerator` 的分支流程落地）。
- 若暂不删：至少在产物里保留一份"本次导出清单"，供 delta 判据过滤陈旧文件。

**触发条件**
1. 出现"消费者 include 到陈旧 `.inl` 并因此编译/链接失败"的实证；
2. 或某轮生成 delta 判据因陈旧文件产生噪声（≥1 次误判）；
3. 或需要把 `Inc/UHT` 作为可交付产物打包（届时必须先做清理）。

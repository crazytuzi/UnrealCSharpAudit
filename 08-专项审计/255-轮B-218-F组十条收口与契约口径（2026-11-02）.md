### 2.4 附带修正（新登记 `F-ABI-042`，P3 / 已修）—— C# `LoadFromStream` 的参数名笔误

- **事实**：`Script/Interop/AssemblyLoader/AssemblyLoader.cs:14` 的形参写作 **`InInPublishDirectory`**（双 `In`）。全仓 `\bInIn[A-Z]` 命中**仅此 3 处**（声明 1 ＋ 函数体 2），其余 interop 形参一律 `InData`/`InLength`/`InHandle` 形式。
- **为什么可以改**：跨语言契约是 **方法名 ＋ 参数个数**（`IScriptTypes.h:150` 的 `... , 3)`；名字常量 `FunctionMacro.h:33` = `LoadFromStream`）⇒ **参数名不参与绑定**；`[UnmanagedCallersOnly]` 走函数指针，更不涉及参数名。C# 全树也**没有命名实参调用者** ⇒ **ABI / 行为零变化**。
- **改名口径**：只修笔误 → **`InPublishDirectory`**（保留 `In` 前缀 ＋ 契约里的 `PublishDirectory` 语义）。**不与 C++ 侧的 `AssemblyDirectory` 同名** —— 两者描述的对象不同：C# 形参是 **ALC 基目录（发布目录契约）**，C++ 局部变量是 **当前程序集所在目录**。
- **为什么不是 `InBaseDirectory`**：那属**契约改名**（会连带 CoreCLR 的 `GetFullPublishDirectory()` 语义、文档与两后端取值口径：CoreCLR 传发布目录、Mono 传程序集目录），需单独裁定；本轮只修笔误。
- **G7**：§8.5 把"重命名既有公开 API"列在**仍封死**清单 ⇒ 本条记 **例外 E5**（维护者 2026-11-03 点名指出该笔误）。机械判据：① C# 侧 `LoadFromStream` 的调用者 **0 处命名实参**（全树 3 处同名调用均为位置实参/内部重载）；② 原生侧按"名 ＋ 个数"解析；③ 只改形参名，不动签名 / 可见性 / 返回类型。
- **判据**：`dotnet build Script/Interop/Interop.csproj -c Release` **0 Warning / 0 Error**；`Content/Script/Interop.dll` **31 744 B（大小不变，纯元数据）**；套件 ×2 同 SHA。

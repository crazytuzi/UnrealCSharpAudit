## 1. 逐条回核（可复现命令与读数）

### 1.1 ① 空 `Initialize()` 的调用点

```powershell
Get-ChildItem <plugin>/Source/UnrealCSharp/Private/Reflection/Container -Filter *.cpp |
  Select-String 'Initialize\(\)'
```

| 文件 | 构造函数调用 | 定义（空体） |
|---|---|---|
| `FArrayHelper.cpp` | `:24` | `:32` |
| `FMapHelper.cpp` | `:51` | `:59` |
| `FSetHelper.cpp` | `:42` | `:50` |

- 出处报告的依据是 `grep "Helper->Initialize"` = 0 —— 该 grep 抓的是**显式成员调用**（`SetHelper->Initialize()`），**抓不到构造函数里的裸 `Initialize();`**。这是本轮最关键的口径更正：**"grep 无命中" ≠ "无调用点"**。
- F-DEAD-016 的裁定原文（`05`）：「~~4 个空实现且零调用的 `Helper::Initialize()`（Optional / Array / Map / Set）~~ ⇒ 🟢 **维护者裁定：不删，改为「被构造函数调用」** —— 与仓内 15+ 个类的既有形态一致（`FDomain.cpp:12`、`FCSharpEnvironment.cpp:349`、`FClassDescriptor.cpp:11`、各 Registry 等，均 ctor 内调用）」。
- ⇒ 该子项**不再是缺陷**；"空实现 + ctor 调用"是维护者选定的形态。本轮**不重复裁定**。

### 1.2 ② `GetAddress()` 的调用点

```powershell
Get-ChildItem <plugin>/Source -Recurse -Include *.cpp,*.h,*.inl | Where-Object { $_.FullName -notmatch 'ThirdParty' } |
  Select-String 'GetAddress\('
```

- **真实调用点**：`Source/UnrealCSharp/Public/Registry/FContainerRegistry.inl:72`
  ```cpp
  static auto RemoveReference(Class* InRegistry, const IManagedHandle InManagedHandle)
  {
      if (const auto FoundValue = (InRegistry->*ManagedHandle2Value).Find(InManagedHandle))
      {
          const auto Address = (*FoundValue)->GetAddress();   // ← :72
  ```
  该函数是**所有容器引用移除**的公共路径（`FRegisterSet::UnRegisterImplementation` 等都会走到）⇒ `GetAddress()` **每次句柄失效都会被执行**。
- 同族还有 `FOptionalRegistry.cpp:69`（`(*FoundValue)->GetAddress()`，Optional 侧，非本三 Helper）。
- 三个 Helper 的定义：`FArrayHelper.cpp:441`、`FMapHelper.cpp:335`、`FSetHelper.cpp:249`。
- ⇒ 子项②**证伪**；出处报告 `07-容器Helper.md` 的 §7.6 表与 §F 结论**早已自行更正**（"`GetAddress()` 并非死代码"），只是 `01` 的行文仍保留了原始措辞。

### 1.3 ③ `static_cast<int32>(INDEX_NONE)` 与其"类型冗余"

```powershell
Get-ChildItem <plugin>/Source -Recurse -Include *.cpp,*.h,*.inl | Where-Object { $_.FullName -notmatch 'ThirdParty' } |
  Select-String 'static_cast<int32>\(INDEX_NONE\)'
# ⇒ 0 命中
```

- 原证据点 `FSetHelper.cpp:80/94/117/126/176` 属**B-290 之前的线性扫描/删除路径**；B-290 把 `Add` 改 `FindOrAdd`、`Remove`/`Contains` 改 `FindIndex` 后，这些 `static_cast` 全部消失。

- `auto Count = 0`（`FMapHelper.cpp:153`）与 `auto Result = 0`（`FSetHelper.cpp:147`）：`auto` 推导为 `int`，而 UE 的 `int32` **就是 `int` 的 typedef** ⇒ 与返回类型**完全一致**，不存在"类型冗余/不一致"。出处报告亦判"无害"。**不改**（改 `int32` 只是风格偏好，且仓内 `auto` 是主风格）。

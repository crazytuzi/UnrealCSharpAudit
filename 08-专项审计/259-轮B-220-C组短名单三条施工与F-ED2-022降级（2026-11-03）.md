## 2. 代码事实

### 2.1 `F-INT1-013`（6 处，同形改法）

```cpp
// 以 FRegisterString.cpp 为例（改后）
const auto String = FCSharpEnvironment::GetEnvironment().GetString<FString>(InManagedHandle);

const auto ScriptDomain = IScriptDomain::Get();

return String != nullptr && ScriptDomain != nullptr
	       ? ScriptDomain->NewString(TCHAR_TO_UTF8(**String))
	       : InvalidManagedHandle;
```
- 失败值沿用既有的 `InvalidManagedHandle`（Q2 合规）；语义只在"域未建立"时由**崩溃**变为**返回无效句柄**，其余路径逐字不变。
- `FRegisterObject.cpp` 的形状是 `if (const auto FoundObject = …)` ＋ 单条 `return`，同样先取 `ScriptDomain` 再判空。
- **机械判据**：全树 `IScriptDomain::Get()->` 计数 **6 → 0**。

### 2.2 `F-MACRO-001`（`##__VA_ARGS__` 只剩逗号位）

- 本轮先改了 `BINDING_OVERLOADS`（`:285`），随后 grep 发现**还有 4 处非逗号位**：`TDestructorBuilder<##__VA_ARGS__>`（`:302/304`）与 `BINDING_DESTRUCTOR_BUILDER_INVOKE(##__VA_ARGS__)`（`:307/309`），一并改掉。
- **机械判据**：`##__VA_ARGS__` 计数 **17 → 11**，且剩余 11 处**前面都是 `, `**（`…, ##__VA_ARGS__` 的 GNU 逗号吞噬惯用法，属预期保留）。
- 顺带核实：`BINDING_OVERLOADS` 全树 **0 处调用**（该宏本身是死宏；改它只为消除 Clang 硬错误隐患）。

### 2.3 `F-MACRO-002`（剥离宏的 `INDEX_NONE` 保护）

```cpp
// 改后
#define BINDING_REMOVE_LEFT_NAMESPACE_CLASS_STR(Class) \
	(F_STRING_STR(Class).Find(TEXT("::")) != INDEX_NONE \
		 ? F_STRING_STR(Class).Left(F_STRING_STR(Class).Find(TEXT("::"))) \
		 : F_STRING_STR(Class))

#define BINDING_REMOVE_RIGHT_NAMESPACE_CLASS_STR(Class) \
	(F_STRING_STR(Class).Find(TEXT("::")) != INDEX_NONE \
		 ? F_STRING_STR(Class).Right(F_STRING_STR(Class).Len() - F_STRING_STR(Class).Find(TEXT("::")) - 2) \
		 : F_STRING_STR(Class))
```
- 两个宏只在 `BINDING_CLASS`/`BINDING_ENUM` 的 `TGet_Args<0>(...) ? LEFT : RIGHT` 分支里被展开，外层的三元与内层三元靠括号正确嵌套。
- **无运行期影响**：当前工程里走这两个分支的类型名**都含 `::`**（B-219 复核结论），套件同 SHA 佐证。

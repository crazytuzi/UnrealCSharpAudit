# 轮 B-273：`F-BIND-013` 的 5.8 可达性收敛（2026-11-17）

> **性质**：分析轮（**0 行插件代码**）。对象 = `F-BIND-013`（P2，部分修）："`TStaticEnum<T>::Get()` 在 5.8 失败路径返回空名 ⇒ 类型位产出非法 C#"。本轮回答一个问题：**5.8 的 fallback 到底可不可达**。
> **基线**：插件 **`d9c346516663177c76ebedffe0b94fc98d20174c`**（B-271 提交后）。
> **一句话**：**不可达（当前绑定面）**。5.8 的 UHT 对**每一个** UENUM 都生成 `StaticEnum<>` 特化**且**在 `.generated.h` 里给出前置声明（普查 150/150，含普通枚举 `ELifetimeCondition` 与命名空间枚举 `ESearchCase::Type`）⇒ `TIsStaticEnum` 恒 `true` ⇒ fallback 走不到；只有**非 UENUM 的普通枚举**才会落进 fallback，而这类类型在 5.6 上会**链接失败**（`StaticEnum<T>()` 无定义），插件长期链接通过 ⇒ **当前实例化面里不存在这类类型**。⇒ `F-BIND-013` 由 **P2 降为 P3 观察项**，11 处类型位不加防御（G7 ＋ 不可达）。

## 0. 结论摘要

| 问题 | 答案 | 证据 |
|---|---|---|
| 5.8 是否为每个 UENUM 生成 `StaticEnum<>` 特化？ | **是（无条件）** | `UhtHeaderCodeGeneratorCppFile.cs:659-666`（只有导出宏分支差异，没有"是否生成"分支）；`UhtHeaderCodeGeneratorHFile.cs:810-821` |
| `.generated.h` 里有没有前置声明（决定 `TIsStaticEnum`）？ | **有**，含普通枚举 | 普查 **150 个定义 / 150 个声明**；样本 `CoreNetTypes.generated.h:46`（`ELifetimeCondition`，**普通非命名空间枚举**） |
| 命名空间枚举在 5.8 是否 `StaticEnum`-able？ | **是** | **P8 探针** `static_assert(TIsStaticEnum<ESearchCase::Type>::Value)`＋`<ETouchIndex::Type>` 全过（`EXITCODE=0`） |
| fallback 何时可达？ | 仅"**无特化**的枚举"＝非 UENUM 的普通 C++ 枚举 | fallback 的名字来自 `GetGeneratedTypeName`；UEnum 对象名与 C++ 名一致时 `FindFirstObjectSafe` 命中，不一致才空 |
| 当前绑定面有这种类型吗？ | **没有** | 5.6 下 `TStaticEnum<PlainEnum>` 会 odr-use 未定义的 `StaticEnum<T>()` ⇒ 链接失败；插件构建/链接长期通过 ⇒ 实例化集合里没有非 UENUM |

## 1. 5.8 的生成规则（源码级）

```csharp
// UhtHeaderCodeGeneratorCppFile.cs:659-666（.gen.cpp）
if (Module.Module.AlwaysExportEnums)
    builder.Append("template<> ").Append(Module.NonAttributedApi).Append("UEnum* StaticEnum<")...
else
    builder.Append("template<> ").Append("UEnum* StaticEnum<")...
```

- **没有"某些枚举不生成"的分支** —— 唯一的差异是导出宏（`AlwaysExportEnums` / `MinimalAPI`）。
- `.generated.h` 的前置声明（`UhtHeaderCodeGeneratorHFile.cs:810-821`）在 `CppForm == EnumClass || UnderlyingType != Unspecified` 时给出；实测**普通枚举也满足**（UHT 对未写底层类型的 UENUM 会落到 `Uint8` 等默认，见 `UhtEnumParser.cs:124-127` 的 `EnumUnderlyingTypeNotSet` 处理）⇒ 声明覆盖全部 UENUM。

**普查（本机 5.8 安装已生成的 12 个模块）**：

| 口径 | 读数 |
|---|---|
| `.gen.cpp` 数 / `.generated.h` 数 | 188 / 171 |
| `StaticEnum<…>()` **定义**（排除声明） | **150** |
| `StaticEnum<…>();` **前置声明** | **150** |
| 定义有、声明无（⇒ 5.8 走 fallback） | **0** |

样本（普通枚举）：`CoreNetTypes.generated.h:46` → `template<> UE_NODEBUG COREUOBJECT_NON_ATTRIBUTED_API UEnum* StaticEnum<ELifetimeCondition>();`

## 3. fallback 的名字路径（为什么"普通枚举能过、非 UENUM 才空"）

| 类型 | `GetGeneratedTypeName<T>()` | 去前缀后 | UEnum 对象名 | `FindFirstObjectSafe` |
|---|---|---|---|---|
| 普通 UENUM `ELifetimeCondition` | `"enum ELifetimeCondition"` | `"ELifetimeCondition"` | `"ELifetimeCondition"`（注册名） | **命中** |
| 命名空间 UENUM `ESearchCase::Type` | `"enum ESearchCase::Type"` | `"ESearchCase::Type"` | `"ESearchCase"`（`NoExportTypes.gen.cpp:193/210`） | 不命中 —— **但该类型 `TIsStaticEnum == true`，不走 fallback**（P8） |
| 非 UENUM 普通枚举 | `"enum EFoo"` | `"EFoo"` | **不存在** | 不命中 ⇒ `nullptr` ⇒ `GetFullClass(nullptr)` 返回 `""` |

- `GetFullClass(const UEnum*)` 对 `nullptr` **安全返回空串**（`FUnrealCSharpFunctionLibrary.cpp:503-508`）⇒ 不崩，只产出空名。
- 也就是说：**空名只在"没有 UEnum 对象"的类型上出现**；命名空间枚举的"名字不匹配"被 `TIsStaticEnum == true` 提前绕开了（它走 `StaticEnum<T>()`）。

## 4. 为什么当前绑定面没有"非 UENUM"

5.6 的行为链：

1. 5.6 的主模板只有**声明**（无 `= delete`）⇒ `TIsStaticEnum<T>` 的 SFINAE 对任何 `T` 都成立 ⇒ **恒 `true`**；
2. ⇒ `TStaticEnum<T>::Get()` 必然 odr-use `StaticEnum<T>()`；
3. ⇒ 若 `T` 没有特化（非 UENUM），**链接期必失败**。

插件在 5.6 上长期构建/链接通过（B-271 的 UBT `Succeeded`、套件 8 次同 SHA 等）⇒ **当前被实例化的枚举类型都有特化**（UENUM 或 `BINDING_ENUM` 宏类型）⇒ 它们在 5.8 下 `TIsStaticEnum` 亦为 `true`（P8 / 普查）⇒ **fallback 不可达**。

推论：`F-BIND-013` 描述的"静默空名"是 **5.8 引入的降级通道**（把 5.6 的链接失败变成运行期空串），但**当前没有类型走进去**；一旦将来有非 UENUM 枚举进入绑定面（且没有 `BINDING_ENUM` 宏），5.6 会构建失败、5.8 会静默产出非法 C# —— 这就是新的触发条件。

| 项 | 结论 |
|---|---|
| `F-BIND-013` 级别 | **P2 → P3（观察项）**：可达性从"潜伏（5.8）"改为"**当前不可达**；触发条件 = 非 UENUM 枚举进入绑定面" |

## 1. 协议与实现

### 1.1 原生侧（`FRegisterMap.cpp` / `FRegisterSet.cpp`）

```cpp
// TMap
static int32 GetPairsImplementation(handle, InIndex, InCount, OutBuffer, InBufferSize, OutNextIndex)
{
    // 校验 + InCount × EntrySize <= InBufferSize（int64 防溢出）
    for (; Index < MaxIndex && Count < InCount; ++Index)
    {
        if (IsValidIndex(Index))
        {
            Memcpy(Out + Count*EntrySize,        GetEnumeratorKey(Index),   KeySize);
            Memcpy(Out + Count*EntrySize + KeySize, GetEnumeratorValue(Index), ValueSize);
            ++Count;
        }
    }
    *OutNextIndex = Index;   // 下一个待扫描的稀疏索引
    return Count;
}
```

`TSet` 同形（单元素缓冲、`GetEnumerator(Index)`）。新增尺寸导出 `TMap_GetKeyTypeSize` / `TMap_GetValueTypeSize` / `TSet_GetTypeSize` 供 C# 侧比对。

### 1.2 C# 侧（`TMap.cs` / `TSet.cs`）

```csharp
var Handle = HandleData.GetHandle(this);
var KeySize = TMap_GetKeyTypeSize(Handle);
var ValueSize = TMap_GetValueTypeSize(Handle);

if (typeof(TKey).IsValueType && typeof(TValue).IsValueType &&
    KeySize == Unsafe.SizeOf<TKey>() && ValueSize == Unsafe.SizeOf<TValue>())
{
    var EntrySize = KeySize + ValueSize;
    var Buffer = new byte[256 * EntrySize];
    var Index = 0;
    while (true)
    {
        var Count = GetPairs(Handle, Index, 256, Buffer, out var NextIndex);
        for (var Entry = 0; Entry < Count; Entry++)
        {
            var Offset = Entry * EntrySize;
            yield return new KeyValuePair<TKey, TValue>(
                Unsafe.ReadUnaligned<TKey>(ref Buffer[Offset]),
                Unsafe.ReadUnaligned<TValue>(ref Buffer[Offset + KeySize]));
        }
        if (Count < 256) { yield break; }
        Index = NextIndex;
    }
}
// 兜底：compound / 布局不符 ⇒ 原逐元素路径
```

**关键点**：`nextIndex` 让分块在**稀疏索引空间**继续，而不是按"第 N 条"续传（稀疏容器的空洞不会被重复扫描）；`Count < 256` 即判定扫描到末尾。

## 3. 未取得 / 边界

1. **compound 元素仍逐元素**：`FString`/`UObject` 包装等需要"句柄数组"协议（native 返回 nint 数组、C# 逐个 `GetObject`），未做。
2. **只测 `int` 键值**：其他值类型（`float`/`FRotator` 等）路径相同但未逐个计时。
3. **只测 CoreCLR / Win64 / Debug**；Release 未测。
4. **新增 5 个 interop 导出**（`TMap_GetPairs`/`GetKeyTypeSize`/`GetValueTypeSize`、`TSet_GetElements`/`GetTypeSize`）⇒ 协议面变更（维护者指定）。
5. **分块语义**：块间重新取 `MaxIndex`，容器在遍历中变化时按当前状态收敛；未构造"边遍历边改"用例。
6. **`TMap` 无效槽位**：批量在 native 侧逐索引 `IsValidIndex`（无跨边界开销），稀疏空洞多时 native 循环仍 O(MaxIndex) —— 未量化超大稀疏 map。

## 5. 复用价值

1. **稀疏容器的批量协议必须带"下一起点"**：返回"下一条的稀疏索引"而不是"第 N 条"，才能跨块跳过空洞、不重扫。
2. **尺寸比对（`GetBufferSize == Unsafe.SizeOf<T>()`）是 compound 兜底的安全闸**：不匹配就退回逐元素，绝不按错布局读字节。
3. **同一协议三容器复用**：`TArray` 的 `(start,count,buffer)` 加一个 `nextIndex` 出参就覆盖 `TMap`/`TSet`，C# 侧结构几乎一致。
4. **新增导出的成本仍是一行注册 ＋ 一个 partial**：`LibraryBridgeGenerator` 自动生成桥接，无需重生产物。

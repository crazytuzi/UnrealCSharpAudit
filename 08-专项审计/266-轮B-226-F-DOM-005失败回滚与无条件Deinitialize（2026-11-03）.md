## 2. 施工

### 2.1 A1：失败回滚（`FCoreCLRDomain.cpp/.h`）

| 位置 | 改动 |
|---|---|
| `:49` / `:75` / `:104` / `:113` 四条失败出口 | `return;` 之前加 **`ReleaseHostFxr();`**（4 × 2 行） |
| 新增 `void ReleaseHostFxr()`（private） | 把 `Deinitialize()` 原有的 teardown 段抽出：close host 上下文、`FreeDllHandle`、清 `LoadAssemblyAndGetFunctionPointerFn` |
| `Deinitialize()` | 20 行 teardown 段替换为 1 行 `ReleaseHostFxr();`（行为等价） |

- **不改变失败判据**、不新增日志/断言/公开 API；`ReleaseHostFxr()` 在四条出口上都是安全幂等（句柄为 null 时 no-op）。
- 🔴 **与设计页的偏差（如实登记）**：设计页写"抽出 `InitializeHostFxr()`、把 4 个 early return 收敛成单一失败出口"；实现改为**保留原有代码形态**、只在既有 4 个出口加回滚调用。理由：① 4 个 `return` 是**既有**代码，不是本轮新增分支，收敛会带来 75 行整体重排（review 面变大）；② 语义等价、回滚点更直观；③ §8 风格面 AddedMax 62，无需重排。若维护者要求统一形态，可在后续轮单独做纯重构。
- 🟡 **命名修订（同日，维护者定）**：初版命名为 `ResetHostFxr`，复核后改为 **`ReleaseHostFxr`** —— `Reset` 在本仓是**数据复位**动词（`FArrayHelper::Reset`、`FDoxygenConverter::ResetBuffer`），且暗示"会重建"，而函数实际是 close 宿主 ＋ 卸模块 ＋ 清缓存指针；`Release` 覆盖全部三件事，回滚与终态两种语境都成立。插件提交为 **`efdca39f`**；代码/文档同步改名，判据 = 纯改名（套件同 SHA）。

### 2.2 A2：域销毁无条件 `Deinitialize`（`FScriptDomainFactory.cpp`）

```diff
- if (InScriptDomain->IsInitialized())
- {
-     InScriptDomain->Deinitialize();
- }
+ InScriptDomain->Deinitialize();
```

- 三后端的 `Deinitialize()` 均已幂等：CoreCLR 的 teardown 本就在 `bIsInitialized` 之外；Mono/LeanCLR 有 `if (!bIsInitialized && !bIsInitializeCompleted) return;`（`FMonoDomain.cpp:185-187`、`FLeanCLRDomain.cpp:92-94`）。
- 效果：失败态（`initialized=0`）与"completed 但未 initialized"窗口现在也会释放静态句柄（§2.3 第二次读数可见）。

## 4. 未取得 / 边界

1. **真实配置恢复后的重试成功未取得**：两次启动期 `Initialize()` 间隔仅 0.8 s，文件恢复必然晚于两次调用（§1.3）⇒ 用 env 门控的一次性失败注入补读数；该探针已删除，交付代码不含注入点。
2. **`0x8`（already initialized）句柄的关闭语义未单独实测**：`ReleaseHostFxr()` 对任何非空 `HostFxrHandle` 一律 `hostfxr_close`（按 hostfxr 契约"initialize 返回的句柄需 close"）。若该分支的句柄实际属于他人，可能需要收窄——**未实测**，作为残留前提登记。
3. **Mono/LeanCLR 未实编**：A2 改共享工厂，但本轮只跑 CoreCLR（`WITH_MONO 0` / `WITH_LEANCLR` 需改 ini 重编）；静态判据 = 两者 `Deinitialize()` 在未初始化时早退（§2.2），行为不变。
4. **同进程 hostfxr 重初始化限制未突破**：真实失败（runtimeconfig 缺失）后的第二次尝试仍然失败（CoreCLR 运行时已部分加载）——本轮只保证**不再假成功**，不保证"真实永久失败能自愈"。

## 3. 施工（2 文件 `+16/−5`）

`Source/ScriptCodeGenerator/Private/FGameplayTagGenerator.cpp`（`+14/−5`）＋ `Public/FGameplayTagGenerator.h`（`+2/−1`）：

1. `GeneratorChildren` 增形参 `const FString& InClassName`（`:149-150`）；`UsedNames` 追加外层类型名（`:159-162`）；
2. 根调用传 `GAMEPLAY_TAGS_NAME`（`"GameplayTags"`，`:73`）；递归传当前子类名 `Name`（`:227`）；
3. **类名避让**：`if (!Child.Children.IsEmpty() && Name == TEXT("Value")) { Name = MakeUniqueName(Name, UsedNames); }`（`:181-186`）。

**形参命名**：取 `InClassName` —— 与 `FCSharpEnvironment::GetClassDescriptor(const FName& InClassName)` 同词；`Enclosing` 在插件手写代码里零先例，`ParentClass` 已被"UClass 继承"占用（`BeginGenerator(…, UClass* InParentClass)`）、`Outer` 已被"UObject 归属"占用（`GetOuterName`），两者都会读偏。

**为什么第 3 条必需（与第 1 条不同根因）**：`UsedNames` 里保留的 `"Value"` 只约束**子名**（`:154-156`），不约束**本类自己的名字**；而 `:213-222` 会为"自身有标签且有子节点"的类**无条件**发射字面量 `Value` 成员 ⇒ 类名一旦是 `Value` 就必然 CS0542。

**为什么改类名而不是改成员名**：改成员名要把它塞回子作用域的保留集，否则 `Value.Value.X` 会让"改名后的成员"与"同名兄弟嵌套类"再撞一次（CS0102）；改类名后递归会把 `Value_2` 一并纳入保留集，**构造上无碰撞**。

**口径**：无新增注释 / 日志 / `throw` / `try-catch` / `ensure` / 公开 API（G7）；`if` ＋ 单一出口；命名沿用 `In*` 形参与 `Name` 局部量；**无新增引擎接口**（见 §9）。

## 10. 复用价值

- **"语料要能让缺陷到达"**：`Test.Value.Child` 单独登记不复现 —— 中间节点的 `Tag` 只在**完整标签的末节点**写入；判据型语料必须先证明"分支进得去"（与 `_CONVENTIONS.md` §7.6 ③ 同一条纪律）。
- **同一函数里的两个 CS0542 根因不同**：保留集少"外层名"是一个；固定成员名不过 `MakeUniqueName` 是另一个。只照前者修会漏掉后者。
- **改名避让的次序很重要**：先加外层名 → 再对"类名 == 固定成员名"补避让，两步都在**父帧**完成；把避让放到子帧会因为"子帧不知道自己的类名"而失效。

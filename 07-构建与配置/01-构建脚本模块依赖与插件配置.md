## 1. 模块职责与架构速览

### 1.1 插件模块图（`.uplugin` 声明 vs 磁盘实际）

`.uplugin:18-54` 声明 7 个模块，`Source/` 下有 8 个目录（含 `ThirdParty`）：

| `.uplugin` 声明名 | Type | LoadingPhase | 磁盘目录 | 对应规则文件 | 构造函数类名 |
|---|---|---|---|---|---|
| `UnrealCSharp` | Runtime | Default | `Source/UnrealCSharp/` | `UnrealCSharp.Build.cs` | `UnrealCSharp` |
| `UnrealCSharpEditor` | Editor | Default | `Source/UnrealCSharpEditor/` | `UnrealCSharpEditor.Build.cs` | `UnrealCSharpEditor` |
| `ScriptCodeGenerator` | Editor | Default | `Source/ScriptCodeGenerator/` | `ScriptCodeGenerator.Build.cs` | `ScriptCodeGenerator` |
| `Compiler` | Editor | Default | `Source/Compiler/` | `Compiler.Build.cs` | `Compiler` |
| `UnrealCSharpCore` | Runtime | Default | `Source/UnrealCSharpCore/` | **`UnrealCSharpCore.build.cs`**（小写 b） | `UnrealCSharpCore` |
| `CrossVersion` | Runtime | Default | `Source/CrossVersion/` | **`CrossVersion.build.cs`**（小写 b） | `CrossVersion` |
| `SourceCodeGenerator` | **Program** | PostConfigInit | `Source/SourceCodeGenerator/` | **无 `.Build.cs`**（是 UBT 插件 `.ubtplugin.csproj`） | - |
| （未声明，正确） | - | - | `Source/ThirdParty/{Mono,CoreCLR,LeanCLR}/` | `{Mono,CoreCLR,LeanCLR}.Build.cs` | 三个 `ModuleType.External` 模块 |

三方一致性结论：**模块名字符串本身 6/6 完全一致**（`.uplugin` 名 = 目录名 = `.Build.cs` 构造函数类名，见 §3 表 A），不存在 `UnrealCSharpCore`/`UnrealCSharpcore` 之类的大小写拼写错误。真正的差异只有两处，且都不是"名字拼错"：
1. `UnrealCSharpCore.build.cs`、`CrossVersion.build.cs` 的**文件扩展名大小写**为 `.build.cs`（UBT 容忍，见 F-BLD-002 的引擎证据），但插件自己的模块列表扫描器不容忍；
2. `SourceCodeGenerator` 在 `.uplugin` 里被当成 UE 模块声明，而磁盘上它是 UBT 插件（**F-BLD-009**；原文误引 F-BLD-010，已改正）。

### 1.2 构建期数据流（`.Build.cs` 的副作用）

```
UBT 编译 RulesAssembly（.Build.cs 在"规则求值期"被执行，不是编译期）
  └─ UnrealCSharpCore.build.cs 构造函数
       ├─ AddExternalDependencies()   → 声明两个工程 ini 为外部依赖（:113-117）
       ├─ if (Target.bBuildEditor) GeneratorModules()  → 扫描工程/引擎的 Plugins 与 Source 目录，
       │                                                 写 <Project>/Intermediate/UnrealCSharp_Modules.json（:120-201）
       ├─ EnableExport()  → 读 DefaultUnrealCSharpEditorSetting.ini，PublicDefinitions += WITH_BINDING（:203-232）
       └─ WithDomain()    → 读 DefaultUnrealCSharpSetting.ini，PublicDependencyModuleNames += Mono/CoreCLR/LeanCLR
                           + PublicDefinitions += WITH_MONO/WITH_CORECLR/WITH_LEANCLR（:234-307）
```

这条链是"ini → 宏 → 模块依赖"的单向决定链，也是本插件最容易出跨平台/跨机器问题的部分（F-BLD-002/003/004/008）。

### 1.3 运行期消费方（后端选择闭环）

`UUnrealCSharpSetting`（`UnrealCSharpSetting.h:150-163`）只有 5 个平台属性：`Windows/Linux/Mac/Android/IOS ScriptDomainType`；运行期用 `FPlatformProperties::IniPlatformName()` 查询（`FScriptDomainFactory.cpp:16` → `UnrealCSharpSetting.cpp:92-120`），未命中即返回 `CoreCLR`（`:119`）。构建期用的是 `Target.Platform.ToString()`（`UnrealCSharpCore.build.cs:261`）。两者对平台名的映射并不等价，见 F-BLD-004。

本工程当前配置（`Config/DefaultUnrealCSharpSetting.ini:3-8`）为 5 个平台全部 `LeanCLR`。

### 1.4 C# 工程生成流（模板 → 工程）

```
FSolutionGenerator::Generator()（FSolutionGenerator.cpp:9-137）
  ├─ CopyTemplate(工程侧目标, 插件侧模板, {替换回调...})   ← 参数顺序 (Dest, Src)
```
